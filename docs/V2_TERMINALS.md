# V2 所有者终端合同

当前批次为 R5.terminal，仍在开发与集成中。默认入口保持 V1；平台代码、离线验证和三平台实机验收分别记录，不能根据接口存在或类型检查通过宣称已支持。

## 职责与权限

`domain/terminals.py`只定义请求、尺寸、身份与指纹规则；`application/terminals.py`拥有会话、单写者租约、有界输出、操作回执和关闭义务；持久仓储统一事务与审计；平台适配器和固定辅助进程实现原生 PTY。组装根显式注入平台后端，测试可以注入隔离后端。V1终端不被V2导入或改造成兼容转发。

首批是所有者手动终端，启动须明确确认当前用户权限，工作目录只能使用本Agent已配置并重新验证的工作目录。终端不提供操作系统沙箱；Shell本身仍能访问当前用户具有权限的资源。原始键盘输入不进入模型工具目录，模型执行命令继续使用既有逐动作审批。所有者令牌通过Bearer请求头提交，不写入URL或传入Shell环境。

工作台将xterm作为输出视图，使用独立输入框与明确发送、回车、Tab和Ctrl+C操作；不把终端解析器的自动应答转发成输入。终端输出属于不可信内容，禁用自动剪贴板与链接动作。面板离开、切空间、切会话和断线立即停止本面板读循环并撤销连接，不把断开连接显示成进程退出。

## 原生进程与回收

Windows使用原生ConPTY同步管道，V2不依赖第三方PTY包；macOS和Linux使用POSIX PTY。无桌面环境不影响核心服务，也不要求图形会话；系统API不可用时能力报告给出原因，核心仍能启动。Python关于PTY的[平台边界](https://docs.python.org/3.12/library/pty.html)与微软的[同步ConPTY接口](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session)是实现参考，实机行为仍须单独验证。

首次Windows专项发现，旧pywinpty3.1.0依赖的[winpty-rs1.0.6写入实现](https://raw.githubusercontent.com/andfoy/winpty-rs/v1.0.6/src/pty/base.rs)不能提供当前请求的独立字节回执。V2改用同步`WriteFile`，保留当前缓冲区直到获得当前字节数；不将0改写成请求长度，不追加字符“刷新”旧写，也不放宽完整输入断言。Shell还显式绑定ConPTY的`CONIN$/CONOUT$`，避免继承辅助进程的协议标准句柄。

主进程不执行fork，也不直接运行原生PTY阻塞库。固定辅助进程先归受管进程系统拥有，交互Shell或可信启动门再登记实际身份，最后复核持久授权并允许执行。Windows核验实际PTY进程的Job归属；POSIX单独拥有控制终端、Shell进程组和创建身份。辅助进程退出本身不证明交互Shell和后代已回收。

默认最多4个受管终端，实际启动、原生调用和清理均有明确所有者。取消请求不能遗失实际spawn或cleanup；失败回收继续占用资源并报告`cleanup_pending`。关闭阶段先停止接收输入，再等待或回收实际进程，最后结算持久状态；存在残留或无法登记最终状态时，不释放数据库及实例锁。

## 数据与回执

`terminal_sessions`保存Agent、启动身份、固定Shell、工作目录身份、权限代次、原生PID及创建身份、尺寸、修订和生命周期。`terminal_operations`保存每个启动、输入、尺寸变更和关闭操作的身份、意图指纹、字节数、状态与审计引用。输入原文和输出正文不写入诊断日志，也不复制为数据库操作载荷。

每次原生调用前先提交意图和审计。操作身份绑定完整意图；相同请求只返回原回执，不再次调用原生能力，不同意图复用身份返回冲突。状态含义如下：

| 状态 | 含义 |
|---|---|
| `prepared` | 意图已登记，尚无确定结果 |
| `accepted` | PTY确认接收输入、尺寸变更完成或回收得到确认 |
| `not_sent` | 在实际派发前已确定拒绝 |
| `unknown` | 无法确定派发或原生结果，禁止自动重放 |

输入`accepted`不证明Shell执行成功、命令结束或其外部写入成功。连接断开、HTTP超时和输出停止也不能作为命令结果。结果不明时工作台只按操作身份查询回执，不能重发旧输入。关闭只根据实际回收结果更新会话，不回写历史输入回执。

读取输出需要Agent、会话、连接身份、启动/流身份和游标共同匹配。单写者连接默认15秒租约，读取期间续期；过期、显式断开或权限改变后拒绝后续输入。输入上限16KiB；输出每个活动视图最多512KiB及256个块，页最多16块。保留窗口丢失、底层输出丢失和流重建必须显示缺口，不得返回空结果冒充完整历史。最多保留8个已回收会话的内存输出，重启不恢复正文。

备份、恢复与新启动保留原会话和操作记录，把未完成状态隔离为未知，不自动启动、输入、重新连接或根据数据库中的历史PID杀进程。人工独立观察已按下方D4合同接通；操作系统级历史进程身份核验仍待独立实现，不能因为创建了新实例而声称旧进程已经消失。

## 验证边界

开发阶段先完成生产路径，再集中覆盖意图回滚、重复请求、单写者、权限撤销、部分写入、输出缺口、断线、启动取消、回收失败、恢复隔离和UI迟到响应。每例使用隔离实例、工作目录和浏览器上下文。真实平台用例使用临时目录与受信测试Shell，不连接真实账号或付费模型。

Windows ConPTY、macOS PTY与Linux PTY分别形成实际运行证据；未运行的平台继续标记待验收。完整UI矩阵、全量离线测试、三平台长期常驻和系统服务验收保留为阶段门槛，不由本批窄专项替代。

## 终端未知结果的独立观察（D4，v2_0026）

所有者终端内的“未知终端操作核查”显式读取未知回执。`TerminalReviewService`编排用例，`TerminalReviewRepositories`管理短事务，`terminal_review`领域定义精确请求及有界证据；组装根注入终端原生静止门。HTTP不访问原生对象或数据库连接。

只可核查已结算的unknown操作；列表仍保留原始unknown，即使已有人工观察。applied/not_applied/still_unknown分别表示所有者独立观察，不改terminal_operations、terminal_sessions、费用、运行或投递，也不授予重放或历史PID操作。accepted仍只表示PTY/原生操作接收，任何核查都不把它解释为Shell业务成功。

来源证明包含Agent、操作/会话UUID、原boot、种类/字节/意图指纹、原始状态/时间及会话修订/权限代次/工作目录指纹/回收状态，使用版本化schema=1载荷和SHA；不保存终端输入或输出原文。提交绑定review UUID、当前核查revision、history_epoch、来源fingerprint、terminal-review-1策略、决定、1–2000字符说明与显式限制确认。父操作/会话/Agent用组合外键约束；每操作最多100条追加观察，修订唯一且递增。

新terminal_reviews单表保存不可变观察元数据与可显式清除的说明。清除只从正文到NULL并保留SHA与删除时间，不能改结论、来源或原始回执，重复提交不能复活已清除说明。说明及记录审计在原短事务共同提交；普通诊断只记录固定事件及operation/review UUID，不记录说明、输入/输出或证明正文。审计引用自动纳入现有外键保护。

只有当前实例所有实际终端工作、spawn和回收均结束才登记；检查和事务共享终端启动锁，防止检查后并发启动。取消HTTP等待不取消已接受事务；phase 0未排空继续保护数据库和实例锁。历史会话没有当前进程所有权，不代表旧进程已经停止：界面分开显示记录中的回收状态，必须确认核查限制，不做历史PID探测/杀进程或自动清理。

同一review UUID和内容只返回原记录，改变内容复用UUID冲突；不同请求并发使用旧revision只允许一个提交。来源状态/会话修订或恢复history_epoch变化使旧证明失效，历史观察与说明保留，但不作为当前匹配观察。恢复通过既有一致备份/新目录/隔离流程，不增加第二套运行真值。

API均在`/api/v1/agents/{agent_id}/terminal-reviews`：GET列表按操作UUID稳定分页，GET`/{operation_id}`检查来源，GET`/{operation_id}/history`按核查revision分页，POST`/{operation_id}`追加独立观察；DELETE`/{operation_id}/history/{review_id}/evidence`携带空对象只清除选定说明。列表/历史每页默认20、上限50，正文请求上限32KiB；不默认读取全部历史。

工作台沿用原生ES模块和公共表单/对话框，不增加自动轮询或新主题。草稿按Agent/操作隔离，最多32份；待确认请求固定UUID与完整载荷，丢回复后只按原身份手动重试，不能默默换ID。列表最多200项、历史最多100项，详情与说明离开面板清除、迟到响应丢弃。说明删除也清除匹配的本地待确认载荷。v36统一V2缓存引用；四视口/双主题完整矩阵仍待阶段验收。

v26只新增一张表及两个原表索引，当前合计96表。V25升级先由既有维护流程生成验证备份；旧回执保留，新DDL中断应回滚后重试。原生PTY、服务安装/更新、三平台和72小时验收仍未完成；本批隔离/浏览器通过不等同于平台支持或整个D4完成。
