# V2 模型流式输出合同

本批属于 D6 模型与扩展包，接通模型流式传输、临时预览、完整工具调用与统一费用结算。它不代表 D6、产品切换或完整 V2 已完成；图像附件和真实供应商验收仍待继续。当前证据见 [流式输出记录](evidence/v2-model-stream.json)。

## 职责与生产路径

`application/model_calls.py`继续统一模型与摘要调用的预检、配置/凭据授权、token 计量、费用预留和结算。普通生产回合使用显式注入的 `ModelStreamingPort`；摘要仍走原有非流式调用，测试模型或其他明确注入的非流式端口可继续使用 `ModelPort`。组装根选择实现，不在业务中查找全局 Runtime。

`adapters/models.py`读取凭据并准备一次调用；`adapters/model_stream.py`拥有实际异步传输和关闭；`domain/model_stream.py`只校验和组合有限响应，不执行网络、存储或工具。应用层的 `model_output.py`仅保存正在执行的模型调用预览，不构成另一份消息或运行状态真值。

普通生产路径是：建立共享费用预留 → 计量实际请求 → 捕获配置及凭据代次 → 准备传输 → 再核验授权 → 派发一次 → 组合片段 → 核验供应商结束及用量 → 实际关闭传输 → 结算调用 → 再核验运行 → 原子保存最终消息/终态或进入工具审批。

传输不能提供可核验的异步迭代和关闭合同，或供应商协议不能证明结束时，返回明确错误/残留。不会在流失败后隐式切回完整请求、改模型或补发。供应商兼容矩阵与正式配置选择仍须在后续 D6、真实验收中收口。

## 有界组合与工具

- 单响应最多 32768 个片段；单帧 256 KiB、累计原始帧与标准化帧分别不超过 8 MiB。
- 正文最多 1 MiB；最多 32 个工具调用，累计参数 256 KiB；名称、ID、索引、UTF-8、JSON 对象、重复键和非有限数均校验。
- 限制同时作用于供应商原始迭代器，避免 SDK 在返回有效正文前无限缓存元数据或空帧。
- 请求总期限 130 秒；每次读取片段最多等待 30 秒，供应商请求 timeout 为 120 秒。

正文与函数名/JSON 参数可以分片，只有完整结束并通过校验才形成 `ModelReply`。半个 JSON、重复 ID、多个选择、结束后追加正文、缺少结束或非法内容都不能生成可执行工具。

工具动作沿既有 `prepare_action → approval → dispatch`；写工具仍需人工批准。模型工具输出不能绕过策略、运行范围或未知副作用规则。`length`、过滤或明确拒绝不是完整成功：可确认的用量照常结算，但不保存半条最终消息、不执行残余工具。

## 供应商证明与费用

SDK 可能在 EOF 合成结束标记、估算用量、包装空 choice，或吞掉底层关闭异常。适配器在 SDK 标准化前观察原始帧，分别确认供应商结束与原始 token 用量；仅标准化 SDK 的已知空 usage envelope，不忽略实际正文。

只有供应商原始计数和本地可用价格共同成立才结算已知费用。SDK 估算、缺失用量或未知模型价格不能作为零费用，也不能自动释放预留。完整内容而费用不明时，费用账保持 `unknown`；缺少真实结束时，运行失败且不发布半条消息。

费用预留、结算、调用身份和账本继续使用现有 `model_calls/budget_accounts`。本批不新增业务表或迁移，仍为 108 表、`v2_0031`。`ModelReply.completion_reason`区分完整与截断/过滤响应；历史运行记录不重写。

配置修订与凭据 revision/authority_epoch 在准备前捕获、派发及每次预览更新前核验。准备期间换密钥时不派发、释放未发送预留；流中换密钥/撤权/删除来源时清除预览并结束，已派发调用费用保持未知，不能套用“未发送”错误白名单释放预算。摘要与非流式准备也复用同一凭据代次检查。

## 预览与重连

`GET /api/v1/agents/{agent}/runs/{run}/live-output`需要所有者认证，复核 Agent、运行、上下文和模型/凭据授权。响应带 run_id、持久运行状态、临时状态；流存在时另含 call_id、revision、text、truncated、ephemeral。无片段、终态或权限失效时正文为空，不把空结果解释为模型成功。

每个活跃回合最多一条预览，最多 4 条；每条只保留末尾 32 KiB UTF-8，截断明确提示。它是有界快照，不是持久事件游标，不保存到 SQLite、日志、诊断包或浏览器存储。断线后获取当前快照；运行完成后读取持久消息及运行状态。持久事件仍沿原有游标接口恢复，不用片段充当执行证据。

工作台用 textContent 显示片段，明确标注“临时、尚未保存”。切换 Agent/会话、离开对话、隐藏页面、取消、来源失效或运行结束时清除；迟到响应通过代次和序列检查丢弃。浏览器停止轮询或断线不拥有也不取消模型任务。

## 生命周期与诊断

传输由一次调用拥有，准备和消费都不可重放。取消时等待实际底层异步关闭；重复取消不能提前释放运行任务。关闭失败保留实际传输引用、容量和可查询的 `cleanup_pending`，由共同生命周期继续回收；数据存储和实例锁不得先于残留关闭。

最多 4 个传输归属，凭据准备前后均检查容量。总关闭预算沿既有实例生命周期，残留时明确报告不完整。关闭异常仅返回固定业务错误，不暴露供应商异常正文；SDK 请求日志与缓存按调用关闭，不设置外部日志导出。

运行健康中的 `model_streaming`报告启用、拥有数、活跃数、关闭状态和待清理数。诊断日志仅记录现有模型跨度、运行/调用关联及错误码，不写片段、请求正文、密钥、完整参数或结果。

## 验证边界

使用真实 SQLite、回合调度、审批和所有者 HTTP，注入异步传输；另以真实锁定 LiteLLM/OpenAI 兼容解析器连接本地假 HTTP/SSE 服务，验证正常、缺用量和缺结束。所有模型、凭据和网络目标均为隔离测试对象，不能替代真实供应商调用。

重点覆盖 Unicode/大载荷、畸形工具、工具完整后审批、重复使用、费用不明、截断/拒绝、取消关闭、关闭失败/恢复、凭据切换、模型撤权、删除来源、HTTP 作用域、不缓存，以及四视口双主题和安全文本渲染。只跑相关专项与直接调用方，不宣称全量、主包或三平台通过。

供应商接口参考 [LiteLLM 流式文档](https://docs.litellm.ai/docs/completion/stream)、[使用统计](https://docs.litellm.ai/docs/completion/usage)；实际行为同时核对锁定环境源码，不能假定 SDK 的合成用量就是供应商计费依据。

## 下一批：图像附件与附图预算

后续在同一 D6 包推进，不重开已完成的流式基础：

1. 统一图片上传/验证对象与原有截图，消息接收、message_parts 引用、入站去重、运行和队列在同一事务提交。
2. 明确模型的图像能力和 token 计量；不支持或计量不可用时明确拒绝，不偷偷转为纯文本请求。
3. 上下文快照记录实际使用的附件；“登记”“附到请求”“未附及原因”分开，不宣称模型已看过。
4. 累计附图预算与当前上下文引用分别管理；压缩或移除旧图不重置本运行已经使用的预算。
5. 图片原文只存在受保护对象目录，最后适配到供应商请求；不抓取任意外部 URL，不把 base64 写入日志或业务 JSON。
6. 删除、遗忘、上下文失效、对象引用、队列/在途取消和费用结算共同闭环，覆盖图像降级、压缩后重用、跨 Agent 访问与真实视觉验收步骤。

真实向量、档位路由、MCP/OAuth、技能/视频/ASR、插件与市场及 D7 产品切换继续保留原范围。完整 V2 和三平台/72 小时验收均未完成，默认入口仍为 V1。
