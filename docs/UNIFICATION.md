# 项目统一规则与交付范围

## 唯一状态来源

`tasks/unification.json` 是 U0–U8 状态与旧编号映射的真值；DEVELOPMENT_STATUS.md 是其可生成摘要。
会话记录只补充历史证据，不再维护另一份当前完成清单。架构、设计规范、数据模型仍各管其职责。

## 目录和契约

- agent/ 是 Python 产品；web/ 是单一前端源码。sdist 收入 _web，wheel 收入 omni/web_assets。
- docs/ 保存当前规则、任务与脱敏证据；scripts/ 为仓库入口；配置、数据和技能保留原位置。
- temp/archive 为已退役版本；temp/private 为私人恢复内容，Git与模型文件工具禁止读取；temp/build 为可再生构建产物。
- market/ 与 website/ 为独立本地仓库，主程序仅通过冻结接口和版本引用协作，不依赖其本机存在。
- 保留现有分层、唯一组装根、两库分工、HTTP/WS/工具及公开导入合同；旧URL通过明确映射兼容。

## 工程纪律

- 一个集成负责人串行推进；不批量暂存他人改动、不重写共享历史、不清理未知归属文件。
- 结构化结果与权限判定单源；状态、记忆、调度不互相复制业务真值。
- Python 使用项目锁定的检查工具；前端保持原生ES模块、data-action、原生dialog、统一token和版本组。
- 各批次专项验证并覆盖调用方；最后全量一次。不能以复跑通过掩盖并发失败或放宽业务断言。
- 真实账号发送、付费、服务重启、安装升级、公开部署和发布先准备可审核步骤，再确认具体目标。

## 验收

Windows 为完整交付平台；默认套件离线。真实模型、QQ/B站、手机、前台接管和72小时常驻单独记证据。
未实际验收的能力始终列为待真实验收。目的引擎、概率唤醒、群分层不在本次交付范围。
