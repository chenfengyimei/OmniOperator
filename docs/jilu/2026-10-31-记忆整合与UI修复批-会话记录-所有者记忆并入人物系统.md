## 2. 为什么这么做（关键取舍）

- **为什么 owner 并入 people 而不是给旧表换名字**：用户明确选「连数据层一起
  并」。people 已有 importance=owner 枚举与三类条目（archive/resident/event），
  与旧 profile 行/MEMORY.md 条目语义 1:1 对应——并入后全库只有一套「人物条目」
  模型，界面/工具/迁移全部收敛。
- **为什么 facts 不并入**：facts 是「按需检索的语料」（FTS+向量+墓碑+作用域），
  与「每轮注入的常驻条目」是两个记忆功能，并入会破坏 recall 管线；界面层用
  「事实记忆」页签统一，数据层保持独立。
- **为什么门面逐一同形而不是重写接口**：Runtime.resident、工具注册、web 端点
  都是既有注入点，同形门面=换实例不换契约，注入块字符串逐字节一致可被测试钉住
  （test_owner_memory.py 等价断言），模型提示词零变化。
- **为什么旧表/文件冻结不删**：迁移是复制不是搬移，原样保留供回滚取证；删除
  是不可逆动作留给用户决策（至今未删，见 §3.2）。
- **为什么皮肤修复走「canonical 类+片段作用域皮肤」而不是改 frame.css 的
  Unified 选择器**：把 workbench 加进 Unified 会波及工作台全部无类控件（与
  workbench.css 自己的皮肤打架）；规范路径=按钮用 components.css 的 `.btn`，
  片段级输入框皮肤写进面板自己的 memory.css（作用域 .memory-surface，独立页
  上与 Unified 同值叠加零视觉差）。

## 6. 给排查会话的重点清单（隐患）

- **R1 本地/远端分叉**：写作时本地 HEAD=7ae23bd、origin/master=2159c30，本地
  领先 40+ 提交；且历史上有并行会话提交信息声称「已推」实际未推的先例

- **R2 主树全绿 ≠ 提交树可复现**：多会话共写一棵工作树，主树全量含所有在途

  add --detach 临时树全量跑（原生面板化批已建立此方法论）。
- **R3 迁移幂等的边界**：owner 迁移靠 `owner_migration` 标记+按内容去重续迁。

  owner 条目数比对（§3.2 的脚本可复用）。
- **R4 双会话共写工作树的提交混入风险**：本会话 284cd57 吸收了并行会话 index.html
  去内联样式中间态（提交信息已声明）；原生面板化批用「git show HEAD:<path> 取
  原文→只打自己补丁→hash-object」分离混合文件。**核实法**：对敏感文件
  `git log --follow -p` 查每批归属声明。
- **R5 版本号三计数器纪律**：app 组（ui/app *.js+各页引用）/memory.css/面板组
  各自独立计数，跨组 import（hub-memory.js→memory.js）必须跟应用组对齐，否则

- **R6 flex 多 auto-margin 陷阱**：工具条加新元素时「贴右」只能有一个

## 8. 本会话踩的坑（通用工程教训）

1. **flex 多 auto-margin 均分陷阱**：`.mode-pick` 与 `#send` 各加
   margin-left:auto 时各自看都对，合起来档位悬在正中——「贴右」只能有一个
   auto margin。
2. **双宿主片段皮肤依赖宿主选择器必翻车**：Unified controls 的
   `:not([data-ui-page=workbench])` 让面板在设置中心里裸奔——片段要么用
   canonical 组件类，要么自带作用域皮肤。
3. **Windows write_text 把 \n 翻成 CRLF**：手工编辑过的 MEMORY.md 分隔符变成
   `\r\n§\r\n`，按 `\n§\n` 切分会整文件变一条——解析外部文件先归一化换行。
4. **dataclass 带默认值字段不能插在无默认字段前**（Runtime.owner_memory 曾致
   TypeError: non-default follows default）。
5. **f-string 测试定位器搜不到字面量**：`f'[data-tab="{name}"]'` 用 rg 搜
   `data-tab=.facts` 不命中，批量找引用会漏（test_workbench_ui 漏网一次）。
6. **测试没改完就启动全量后台跑**：全量跑在半成品树上浪费两轮——先小范围
   定向绿，再全量。
7. **并行会话编辑器保存旧缓冲会瞬时回写共享文件**：门禁子进程恰在写窗口读到
   旧内容（统计数字 213/82 vs 200/81 可判别新旧），直接复跑即绿——先查文件
   mtime 与计数差异再定性瞬态/回归。
