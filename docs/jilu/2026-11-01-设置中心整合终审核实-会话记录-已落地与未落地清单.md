## 3. 隐患清单（R1..R12）

> 分级：R1–R3 是**用户可感知的缺陷或会误导审计的欠账**；R4–R7 是改代码时的必守规则；R8–R12 是取证与环境坑。

### R1【高·已核实的真实缺陷】除「记忆系统」外的分区深链全部无效

`ui/shared.js` L180 是唯一的深链处理点，而它把分区写死成一个：

```js
const section = new URLSearchParams(location.search).get('section');
if (section === 'sec-memory-system') button.dataset.section = section;   // ← 只有这一个
button.click();
```

后果：`/?settings=1&section=sec-terminal`（或 android/jobs/mcp-services/capabilities/project）
→ **打开设置中心，但停在首页卡片网格，不会跳到目标分区**；而且 URL 里那个 `section` 参数被静默忽略，用户以为链接坏了。
`/?settings=1` 和 `/?settings=1&section=sec-memory-system` 两个是正常的。

这不是理论问题：rail 的 6 个工具入口能正常工作只因为它们是**点击**（`el.dataset.section` 来自被点的元素），一旦有人复制地址栏/写文档给深链，就是哑的。

修法：L180 泛化为任意 `sec-*`（校验前缀，别把任意字符串塞进 `dataset.section`），同时把 L117 的 `!path.includes('section=sec-memory-system')` 白名单一起泛化，L30 的导航项才有必要收敛。**改完必须补一条守卫**（现有 `test_ui_hub_sections.py` 没覆盖深链）。

### R2【高·审计误导】台账缺登记

`docs/DEVELOPMENT_STATUS.md` 里搜不到这四笔提交的任何状态。多会话协作时，其他会话与审计会话都以台账为准——**台账没有 = 事实上不存在**。补一条 D 序列条目：状态写 **待真实验收**（不能写"完成"，理由见 R3）。

### R3【中·别当已完成】"已交付"只到契约层，真实观感没验收

自动化能证明：分区结构对、协议消息通、token 单源、契约门禁过、项目索引导得上。
自动化**证明不了**：面板信息密度是否合理、长输出时滚动是否跟手、390px 下触控目标是否够大、浅色主题下终端是否真的好看。
上一份记录 §3.2 有 Playwright 截图核对，但**逐张人工核验没做**。任何人接手请按"待真实验收"对待，不要因为 56 项绿了就写完成。

### R4【中·高价值】CSS 不闭合括号会静默吞掉其后整段规则

批量改选择器（尤其往多行 `:is(...)` 里插东西）之后必须跑：

```bash
python scripts/check_ui_contract.py     # 含"CSS 括号配平"项
```

判据：`frame.css` 正常约 108 条规则，掉到 31 条就是被截断了。症状是"整块布局失效"，肉眼极难定位到"括号没闭合"。

### R5【中】面板是"双宿主片段"，控件皮肤不能靠宿主级选择器

同一个 `panel.html` 既跑在独立页（`body[data-ui-page="xxx"]`）又跑在设置中心（`body[data-ui-page="workbench"]`）。规范写法：`frame.css` 里用「`body` 作用域 + `.subpage-panel` 作用域」**并列选择器、规则体只有一份**。新面板若只写 body 作用域，在设置中心里会整体落空（这正是上一批"样式全乱"的根因之一）。

### R6【中】新增面板必须同时接三件事，漏一件就出症状

1. `hub-*.js` 里 `ensureStylesheet(页面css)` + **动态 `import()`**（静态 import 会让一个子站 404 打挂整个工作台模块图，页签全哑）；
2. `index.html` 的 `.hub-card` 与侧栏 `data-go` 成对；
3. 卡片里留「整页打开 ↗」，否则触发「每个子站必须有界面入口」守卫（防事实孤儿页）。

### R7【中】工作台脚手架禁止裸标签选择器

`workbench.css` 里遗留的 `aside,section{display:flex;flex-direction:column;align-items:center}` 与 `ul{overflow-y:auto}` 会**漏进注入的面板**（工具条被压成纵向居中列、列表被强加滚动条）。已有正解是 `main > aside, main > section` 与 `main ul`。新增规则沿用这个写法。

### R8【中·取证坑】配对文件在 ≠ 服务在跑

本次实测：`data/run/pair_url.json` 存在、mtime 22:57、`expires_at` 未过期、`port: 8000`，但 **`127.0.0.1:8000` 连接被拒**（`WinError 10061`）。该文件只是一个 TTL 86400 秒的凭据记录，**服务退出后它不会被删**。
验收前顺序必须是：先确认端口在听 → 再读 `pair_url.json` → 再校验 `expires_at`。直接拿文件里的 URL 递给用户会得到"打不开"。
另外：探测本机端口必须**绕过系统代理**（环境里有 `HTTP_PROXY`），Python 侧用 `urllib.request.build_opener(urllib.request.ProxyHandler({}))`，curl 侧用 `--noproxy '*'`。

### R9【中·本轮新增】两个会话同时在 bump 版本串

HEAD 里 `ui/app/*.js` 是 `?v=20261101u2`，工作区被另一会话推到 `20261101u5`，涉及 48 个前端文件。
危险动作：用 `git show HEAD:<path>` 取基线 → 打补丁 → `git hash-object -w` 写索引提交。这样做会把**对方的 u5 回退成 u2**，浏览器缓存随即拿旧模块，表现为"改了没生效"。
规矩：**不要碰 `ui/app/*.js` 与 `index.html` 的版本串**，除非确认对方已提交；需要改页面 css 时只 bump 自己那一组，别整组重写。

### R10【中】版本串有两个维度，都要一致

1. app 组（`ui/app/*.js`）必须**全组一致**（守卫 `test_app_module_import_versions_are_atomic`，本次实跑通过 = 当前 u5 是一致的）；
2. 同一页面 css 有"独立页 `<link>`"与"hub 懒加载"两个入口，版本必须一致（守卫 `test_hub_panel_stylesheet_versions_match_pages`）。

### R11【低】已知 flaky，别当成回归

`agent/tests/test_mcp.py` 的超时判定用例、`agent/tests/test_command_jobs.py` 的取消用例在**基线树上也会失败**，且失败参数每次不同。看到只有这两处红，先在基线树复跑确认归因，不要怀疑自己的改动。
同一仓库**永远只跑一个 pytest**：后台 + 前台两个全量同时在跑会互相踩 `data/`，输出里 F/E 遍布，看着像大面积回归。

### R12【低】全量数字的口径必须写明

`3ac0a2f` 的提交信息记的是**干净提交树 1887 passed**。本次我**只跑了 UI 相关 5 个文件（56 项）与项目索引（11 项）**，没跑全量——主树有 84 项他人在途改动，就地跑全量得出的数字不能归因。
要全量：`git worktree add --detach <tmp> HEAD` + `PYTHONPATH=<worktree>/agent/src`（`.venv` 是 editable 安装，不压 `PYTHONPATH` 会加载主工作区代码，数字是混的），跑完 `git worktree remove --force`。
