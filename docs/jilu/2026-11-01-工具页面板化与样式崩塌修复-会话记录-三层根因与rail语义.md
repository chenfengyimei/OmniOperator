## 2. 为什么这么做（问题链）

1. **用户报障「样式错误位置不对」**，不是某个颜色写错，而是整块布局失效。逐层排查的顺序值得复用：先量 DOM 几何（卡片宽 820 vs 宿主 1244、工具条被压成 17px）→ 再查 CSSOM（`document.styleSheets` 规则数、选择器命中数）→ 最后看页面 css 是否根本没有 `<link>`。
2. **为什么 frame.css 的损坏会表现为「全乱」**：CSS 解析器遇到不闭合的 `:is(` 不会只丢一条规则，而是吞掉后续整段直到括号配平/EOF。所以症状具有欺骗性——看起来像「某个模块样式没写」，实际是「文件后半段全部消失」。**这类错误必须在门禁里静态拦截，靠截图定位代价极高。**
3. **为什么面板要在工作台懒加载 CSS 而不是静态 `<link>` 全带上**：4 个页面 css 共计几十 KB，20 个分区里只有 4 个用得上；更重要的是**加载顺序**——页面 css 必须在 workbench.css 之后生效，动态插 `<head>` 末尾天然满足，静态 link 容易被人排错顺序。
4. **为什么必须动态 `import()` 页面模块**：静态 import 会把「子站脚本」拉进工作台的模块图。任何一个子站脚本 404（离线、路径改名、版本串不一致），`main.js` 整棵图失败——页签、设置中心按钮全哑，用户看到的是「界面坏了」，而真正原因只是一个 404。本会话实测踩到：`test_workbench_ui` 的静态路由只放行 `/ui/`，静态 import 立刻 57 个错误。
5. **为什么 rail 要改成 hub 内打开**：工具页已经全部搬进设置中心（原生面板/内嵌页），rail 却仍按「子站是另一个网站」整页跳走——同一功能两个入口两种行为，用户会以为「工具页是外部站点」。独立页没有删，而是降级为「整页打开 ↗」，既保留深链与排障能力，又保证每个子站仍有界面入口（防事实孤儿页）。

**H3【中】面板是「双宿主片段」：控件皮肤不能依赖宿主级选择器。** 同一个 `panel.html` 既在独立页（`body[data-ui-page="xxx"]`）又在设置中心（`body[data-ui-page="workbench"]`）。规范路径：frame.css 的 Unified controls / Shared surfaces 用「body 作用域 + `.subpage-panel` 作用域」**并列选择器、规则体一份**；新增面板别写只有 body 作用域的新规则。

**H4【中】新增面板必须同时接三件事。** ①`hub-*.js` 里 `ensureStylesheet(页面css)` + 动态 `import()`；②`index.html` 的 `.hub-card` 与侧栏 `data-go` 成对；③卡片里给独立页留「整页打开 ↗」（否则触发「每个子站必须有界面入口」守卫）。漏①的表现是「面板没样式/位置全乱」，漏③的表现是守卫红。

**H5【中·高价值】CSS 不闭合括号会静默丢弃整段规则。** 批量改选择器（尤其往多行 `:is(...)` 里插东西）之后，**必须**跑 `python scripts/check_ui_contract.py`（新增的「CSS 括号配平」项）并看一眼浏览器 `document.styleSheets` 的规则数。判据：frame.css 正常 108 条，掉到 31 条就是被截断了。

**H6【中】分区挂载模块必须动态 import 子站脚本。** 静态 `import ... from '/capabilities/capabilities.js'` 会让一个子站 404 打挂整个工作台模块图（页签全哑）。守卫 `test_hub_panel_modules_load_pages_lazily` 已钉住。

**H7【中】工作台脚手架禁止裸标签选择器。** `workbench.css` 里 `aside,section`/`ul` 这类规则会漏进注入面板（工具条被压成纵向居中列、列表被强加滚动条）。已有作用域写法是 `main > aside, main > section` 与 `main ul`；新增规则请沿用。

**H9【中】rail 语义已定，别回退。** 工具入口 = `data-action="hub:open" data-section="sec-*"`；独立页只从卡片「整页打开 ↗」（`_blank`）。`rail.js` 里不允许再出现 `window.open` 或子站路径（守卫已钉）。新增工具页时同时加 rail 入口 + 分区 + 整页链接。

## 8. 本会话踩的坑（实测）

1. **CSS 解析器对不闭合括号的处理**：不是「这条规则不生效」，而是「其后整段消失」。定位靠 `document.styleSheets[...].cssRules.length` 与 `规则数`，肉眼看不出来。
2. **`git show | Select-String` 查中文会假阴性**：PowerShell 管道编码不一致，`IN HEAD` 判定错。要么用 Python 显式 `decode('utf-8')`，要么 `Select-String -SimpleMatch` 且确认控制台编码。
3. **PowerShell 里 `python -c "..."` 写含中文/引号的脚本极易被打花**：一律 `write_file` 落 `.py` 再执行；临时脚本用完即删（本会话在 `agent/scripts/` 留过 4 个 `_tmp_*`，已清理）。
4. **`window.open` 与 `<a target=_blank>` 是两条独立路径**：只改其中一条，用户仍会「整页跳走」。改入口时要同时 grep `window.open`、`href="/xxx/"`、`target="_blank"`。
5. **CSS 里同特异性规则靠文件顺序压制**：`base.css` 的 `body[data-ui-page="workbench"] .hub-nav` 会盖掉 `workbench.css` 的 `.hub-nav`；覆盖时必须写同名特异性。
6. **flex 列容器 overflow 时子项会被压扁**：该滚动的列表要给子项 `flex-shrink:0`，否则搜索框能压到 17px 并与标题叠字。
7. **测试正则对 DOM 结构脆弱**：`<div class="hub-card..." id="x">(.*?)</div>` 在卡片里插了新 div 后会截错位置，误报「缺 hint」。用「截到下一张卡片」的 lookahead 更稳。
8. **提交前版本串要动全组**：只 bump 一个文件会被 `test_app_module_import_versions_are_atomic` 抓住；跨组（页面 js 引用 app 模块）也要跟组。
