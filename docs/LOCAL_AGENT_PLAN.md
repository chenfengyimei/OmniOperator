### 1.2 稳定个人使用版的目标

小鱼应能在一台 Windows 电脑上长期运行，用户通过 QQ、Web、CLI 提交任务，调度器执行明确授权的周期任务。任务必须有身份、状态、预算、证据和终止方式；失败后能说明哪里失败、是否产生副作用、如何恢复。记忆和技能可持续维护，但不能通过学习改变权限。

首版服务单一所有者及其白名单场景。多人组织协作、云端多租户、所有聊天平台、训练数据流水线和通用插件市场不属于首版要求。核心可移植，但 macOS/Linux 不计入 Windows 首版的已验收范围。

“像人”应体现为理解上下文、适度主动、能记住约定、知道何时停止和请人处理。随机延迟、模拟鼠标轨迹或大量工具不能替代这些能力。

## 2 初始评估时与 Hermes 的差距（当前进度见 §0.1）

Hermes 的本地源码包含较完整的中断、预算、供应商恢复、异步委派、技能治理、调度锁和工具生命周期实现；官方文档也提供本地及远程 MCP、桌面控制等能力入口。下面比较的是实现范围，不对两个项目的所有功能可靠性作无证据保证。[Hermes 文档](https://hermes-agent.nousresearch.com/docs)

| 维度 | OmniOperator 当前情况 | Hermes 参考与本项目所需补齐 |
| --- | --- | --- |
| 多入口 | QQ/Web/CLI/心跳共用 Agent；不同入口仍有身份、锁和生命周期差异 | 参考 gateway 的统一路由；先做统一 RunContext、明确会话身份和所有权 |
| 工具循环 | 多工具回填、grace call、基本错误回传已具备 | 缺完整运行状态、取消、持久轨迹、全链预算和有限故障恢复 |
| 委派 | 独立 UUID 会话、同一 Agent 同步执行、防嵌套、父审批链复用 | 不等于独立并行 worker；需要独立运行实例、受限工具集、预算继承和取消传播 |
| 模型层 | LiteLLM 接口、chat/vision/local/review 名称路由 | 需要能力检测、明确超时、usage、费用预算、错误分类、流式输出和有限重试 |
| 上下文 | 字符阈值压缩、工具批次完整、单回合系统提示稳定 | 历史先按条数截断，摘要不持久化；未形成跨轮可恢复的长任务上下文 |
| 记忆 | SQLite FTS、事实、档案、常驻笔记、回合后 review | 需来源与作用域、修改一致性、遗忘/纠错、review 背压、索引迁移；向量检索是后续增益项 |
| 技能 | 创建、按节 patch、重写、references 按需读 | 版本号递增不等于历史版本可恢复；缺并发 CAS、完整历史、安装隔离、来源和用户编辑闭环 |
| 定时任务 | 简单间隔/每日、技能、context_from、执行账本 | 缺跨进程领取、积压治理、持久状态、投递去重、链依赖一致性和任务编辑 |
| 本机工具 | 任意 shell、前缀白名单观察、终端 | 缺独立受限文件工具与命令参数语法；前缀判断存在已复现漏洞 |
| 浏览器 | Playwright 持久 profile、读/点击/输入、预算、页面文本回读 | 跨线程所有权、跨进程 profile 占用、目标稳定性、未知副作用状态尚未解决 |
| 安卓 | ADB、UI 树、中文输入、看屏、基础动作 | 动作后复检未强制；陈旧索引会重新解释；缺设备租约、观测版本和真正多模态回路 |
| 桌面 | 无原生 Windows 桌面能力域 | 可先评估适配 `cua-driver`，再按需求补 UIAutomation；必须逐应用验证后台交互能力 |
| MCP | stdio 懒连接、持久会话、只读名单、人工确认、超时封闭 | 缺状态面板、权限与 schema 漂移检测、远程 HTTP、安全认证及资源/prompt 治理 |
| 交互体验 | 基本工作台、终端、审批、设置、设备看屏 | 缺任务进度、停止/恢复、失败原因、产物、技能回滚和任务编辑的统一视图 |
| 运维 | 服务启停、pid、日志、已有测试 | 缺完整 doctor、备份恢复、身份校验、升级迁移、持续集成和长时间可靠性报告 |

Hermes 的 MCP 文档覆盖本地 stdio、远程 HTTP、工具过滤以及资源/prompt 封装，本项目当前仅完成 stdio 工具调用子集。[Hermes MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)

Hermes 通过 MCP 接入 `cua-driver` 提供桌面能力；这是可学习的适配路线。不能据此推断本项目只要调用 `SendInput` 就能对所有应用“不抢焦点”。UIAutomation、PostMessage、真实键盘输入的限制需要逐项验收。[Hermes Computer Use](https://hermes-agent.nousresearch.com/docs/user-guide/features/computer-use)

本项目的明确定位是 Windows、QQ、B 站和安卓的个人工作流。这个定位值得保留，但不构成“这些能力优于 Hermes”或“Hermes 不支持 Windows/QQ”的结论。

### 4.1 三个可交付阶段

| 阶段 | 应包含的能力 | 不可跳过的门槛 |
| --- | --- | --- |

“完整桌面 agent”还要求 R5 的桌面读写验收通过。若 1.0 尚未包含桌面控制，应称“本地工具 agent”，不能在名称或宣传里暗示已能操作所有 Windows 软件。

### 4.2 全局完成定义

以下都是**拟定验收目标，不是当前已达到的指标**。

1. 无已知未修复的权限绕过、跨会话泄露、真实运行目录污染和数据丢写阻断项。
2. 所有外部副作用有清晰状态：未执行、执行中、确认成功、确认失败、结果未知。结果未知不能自动再发一次。
3. 任一运行可查询 run_id、来源、会话、状态、已用预算、工具轨迹、产物和错误。用户停止后不再发起新工具调用；已在途不可中断操作如实显示。
4. 每条发布能力至少有成功、输入错误、权限拒绝、超时、并发、崩溃恢复/断连中的适用测试。测试数只记录结果，不作为追数量目标。
5. 数据备份可恢复到临时实例，恢复后关键记录数和内容摘要一致；迁移失败不能破坏旧状态。
6. 自动化测试默认不访问真实账号、不调用付费模型、不使用真实 data、不启动真实常驻服务。真实验收由明确标记的手动套件执行。
7. 提交前全量 `uv run pytest` 通过；引入的 lint/type/集成检查同时通过。已有 warning 需登记，不得批量静默掩盖。
8. 稳定版进行一次 72 小时常驻验收：无未授权动作、跨会话污染、重复副作用或未处理崩溃；人为断网、服务重启、模型失败后状态可解释。资源增长门槛在 D26 基于预热基线确定，避免凭空承诺内存数值。

## 5 架构落点与关键设计决策

### 5.1 保留现有分层

- `channels` 负责身份与协议适配，调用 Runtime；不能各自复制一套 Agent 运行逻辑。
- `bootstrap` 构造核心对象、注入目录与依赖，负责装配，不演变成业务处理大文件。
- `core` 管运行状态、上下文、预算协调、任务调度；不实现 ADB、Playwright、MCP 协议。
- `tools/<域>` 管具体能力。工具需要取消检查、运行标识或审批元数据时，通过低层协议/回调注入，禁止 import core。
- `memory` 负责持久化、迁移、事务、检索；embedding 生成与模型裁决经注入，不 import llm/safety/tools。
- `safety` 保持叶子层。策略依赖传入的描述和上下文，不能向上访问 Runtime 或 Gateway。
- `config` 只描述和加载配置；新增值应有类型、范围和迁移默认值。

当前架构文档对 `system/` 等辅助包的允许依赖说明不完整，架构守卫也未穷尽能力域互相 import 等规则。D00/D26 必须把这些盲区登记并补测试；新增组装根对象要同步更新 ARCHITECTURE 和 AST 守卫。

### 5.2 请求、运行与结果

建议由 `core/run.py` / `core/events.py` 管理运行；持久记录由 `memory/runs.py` 管理。名称是建议落点，可在保持职责前提下调整。

```text
RunIdentity = run_id + parent_run_id + session_id + channel + principal + conversation_scope
RunState = queued | running | waiting_approval | cancelling | succeeded | failed | cancelled | interrupted | unknown
ToolResult = status + text + error_code + retryable + side_effect_state + artifacts + verification
```

RunContext 中的预算、取消信号、权限快照不可由模型参数覆盖。`waiting_approval` 单独计时：人工等待与执行活跃时间、模型读取超时和总寿命不是同一概念。采用带 sequence 的结构化事件；UI 断连可从上次 sequence 补读，不能靠重新执行任务恢复画面。

Registry 保留对旧字符串工具的兼容适配，逐域迁移 ToolResult。阶段切换期间不能同时维护两套相互矛盾的成功判断。尤其不能用中文字符串前缀判断 cron 是否成功。

### 5.3 数据与并发

已有 `memory.db` 已使用 WAL 和 busy_timeout，不要重复提交“新增 WAL”当作改进。新的运行、调度、投递和写预算建议统一放入可注入的 `data/state.db`，由 memory 仓储负责，避免每个模块再造 JSON 锁。

关键状态包括 `runs`、`tool_calls`、`run_events`、`jobs`、`job_runs`、`deliveries`、`write_budgets`、`approval_records`。需要唯一约束、短事务和条件更新；调度领取与额度预留必须原子化。外部调用不能放在长 SQLite 写事务内。SQLite 同一时刻仍有写入竞争，应处理 BUSY 和事务边界；WAL 不会自动把多步业务变成原子操作。[SQLite WAL](https://sqlite.org/wal.html)

JSON 迁移必须区分文件不存在、合法空集合和损坏文件。保留迁移前备份与校验摘要，迁移可重复执行；损坏状态隔离并告警，预算和权限相关状态不能按“空”放行。

SKILL.md 仍可供用户编辑。技能更新需要跨进程锁、expected_hash、历史快照、原子替换和失败恢复；修改旧版本后产生新修订，不能覆盖历史。用户在编辑器中改了文件时，应识别新 hash 并提示冲突。

### 5.4 权限与安全

风险分级、调用者身份、允许目标和数据作用域共同决定权限。模型的工具名、外部页面、技能正文、MCP 的只读标注都不能新增权限。

保留 SAFE/CONFIRM/DANGEROUS、requires_human 和无人值守拒绝。例外如写记忆、向已授权所有者发送单条提醒必须被明确建模，不能把“写操作均安全”或“有白名单就能无限群发”作为隐含规则。

需要三类能力边界：工作区文件路径、网络/收件人目标、设备/窗口身份。通用 shell/桌面点击可能产生任何副作用，所以人工确认必须绑定本次参数及观察版本，不能用旧确认执行已经变化的目标。

Web 需要本地身份、SameSite/CSRF 设计、Origin/Host 校验和终端 WS 握手验证；默认拒绝没有完整配置的非回环监听。配置接口返回密钥是否已设置的状态，不回显明文。CORS 不能代替身份认证或 CSRF 防护。

### 5.5 外部工具与设备生命周期

Playwright 采用专属所有者线程/进程：创建、所有动作和关闭均在该所有者执行。每个 profile 有跨进程占用协议，另一个入口遇占用应排队或明确拒绝，不能并开同一 profile。先实现可解释的互斥，再考虑统一浏览器服务。

安卓/桌面动作携带 observation_id，绑定设备、窗口、页面或树的版本。若过期，应返回新观察要求模型重新选择，不能把旧 idx 套进新树。动作与验证形成一个串行执行单元；验证失败返回 unknown。

桌面后台模式只使用经验证的可访问性/窗口级操作。需前台焦点的场景明确请求用户接管或授予本次前台操作；默认不移动用户光标，不绕过锁屏/UAC/MFA。

### 5.6 费用、隐私与自主性

模型、review、压缩、embedding、委派共享父运行及日额度；预算是确定性代码约束。启用付费推理前由用户设置授权范围和上限，在此范围内不重复逐次询问；购买、升级套餐、额外付费服务仍需人工确认。未知价格不得按零费用记账。

`read_only_tools` 是用户授予的权限，不是服务器的自我声明。MCP 的连接身份/命令/schema 变化应触发权限重新检查；远程认证和 token 存储先于 HTTP 自动重连功能。返回内容和 prompt 只能作为不可信数据，不作为系统规则。[MCP 工具协议](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

主动行为默认关闭或仅针对明确授权的个人提醒；需要安静时段、每日频次、去重、停用开关。每条主动消息必须能追溯触发原因，不以“像人”为理由自行扩大交友、群发和发布范围。

## 6 分阶段交付路线

阶段编号 R0–R7 用于本轮计划，与旧架构文档的 P0–P5 历史阶段不同。

| 阶段 | 任务 | 交付内容 | 放行条件 |

按一个主要执行者串行负责规划。各 D 任务可分成 1–4 个完整提交，复杂任务先完成契约再实现。此时不给日历完成日期；在 D00 和首两个任务完成后，用实际交付速度重新估计工期。不要让模型为“按期完成”删掉故障测试或硬凑完成比例。

## 7 重点功能要求

### 7.1 运行控制与故障恢复

先实现“可取消且状态准确”，再实现“可恢复”。模型读取、工具执行、人工审批和设备操作分别支持合理的超时。不能把 asyncio.wait_for/to_thread 超时误当成底层线程或进程已经停止。

恢复默认重新读取环境与账本。纯读任务可按策略续跑；已经提交的写操作必须查证实际结果；无法证明未执行的写入保持 unknown 并交人工。进程恢复不自动批准旧的待审批记录。

委派子任务只能缩小父权限和预算，不可选择更高权限审批器。并行只开放给相互独立的读/计算任务；同浏览器 profile、同手机和同工作区文件写入保持互斥。先解决单任务正确性，不以并行数量作为进度。

### 7.2 上下文、记忆与学习

历史压缩要保留用户目标、约束、决定、已完成步骤、未完成事项和证据索引。持久摘要包含覆盖消息区间与生成版本，新对话不能无声丢失区间外信息；FTS 查询原文依旧可用。

系统提示词稳定范围应明确为一次运行的冻结快照。跨轮若要提高缓存命中，先测量时间、人设、档案变化导致的缓存成本，不能伪称当前整段会话始终字节一致。

review 采用有界队列、按 session/消息区间去重、累计预算和可停止生命周期。低风险事实可按用户设置自动归档；覆盖既有事实、修改技能的关键操作或疑似外部指令应形成可查看差异的候选变更。用户明确“不要记”的内容不能通过 review 再写入。

所有事实、档案、常驻笔记、技能应保留来源和适用场景。全局个人记忆不能不加筛选注入群聊。额度、注入风险与敏感数据规则要覆盖新增、编辑、替换、回滚、导入、review 等入口。

向量层采用 FTS 与向量混合检索，保留中文短词、编号、日期和精确字符串能力；不要直接删除 FTS。sqlite-vec 提供向量存储/检索能力，并不生成 embedding，后者必须独立配置、计量并允许本地实现。[sqlite-vec Python](https://alexgarcia.xyz/sqlite-vec/python.html)

### 7.3 调度器和投递

任务编辑支持 prompt、schedule、enabled、skills、context_from 和投递目标；使用 revision 避免前端旧表单覆盖后台更新。手动执行也创建独立 run，不绕过无人值守策略。

一个调度时刻由数据库唯一键及原子 claim 保护。已经运行的同一任务按显式策略跳过或合并，不无限堆积 asyncio task。任务依赖拒绝环和不存在来源；context_from 绑定明确成功的 run_id、产物、有效时间，不只读取一个任务的“最后一句话”。

执行与投递分开记账。投递建立 outbox、目标白名单和去重键。外部通道不支持幂等且发送后确认丢失时，只能显示未知，不能承诺端到端 exactly-once，也不能自动再次群发。

预采集脚本属于后续受限能力：只允许受信目录内的已审核文件和哈希版本，不接受任意命令字符串；继承预算和最小环境，不把 script 当绕过 run_command 的通道。

### 7.4 工具和设备

增加独立文件工具，提供有界搜索、读取、差异预览、expected_hash 写入和回读。真实密钥目录、浏览器凭据、`.env` 等默认不可作为模型输入；用户授权也需要明确范围与脱敏设计。

通用网页读取支持公开页面与正文提取，但要控制 URL 协议、重定向、网络目标、大小、超时和不可信指令。当前 B 站专用 API 不等于通用网页研究能力。

视觉链路需要 ArtifactStore：工具返回受控 artifact_id，核心按权限与模型能力生成图像消息；不将任意本地路径作为可公开读取的 URL。截图是否送往云端由用户设置决定。

设备动作必须返回新的观察和验证状态。GUI 点击结果不等于业务提交成功，特别是发帖、私信和购买页面。一次动作完成不应隐式执行多个“确认/发送/购买”步骤。

### 7.5 工作台和日常操作

在既有前端工作的基础上增加任务队列、当前步骤、工具结果、审批参数、停止按钮、产物、错误及恢复入口；保留按会话查看的历史。未显示的后台任务也要有可查询的 run_id。

技能工作台需要编辑、校验、冲突检测、版本差异和回滚；cron 工作台需要编辑、下一次运行预览、执行记录和投递状态；MCP 面板需要配置状态/连接状态区分、只读授权名单、禁用和脱敏日志。

前端展示不能把“有 pid”写成“已登录”，不能把“配置了 vision 模型”写成“已具备视觉”，不能把“工具调用返回”写成“副作用已验证成功”。

## 8 验收场景与证据

| 套件 | 代表场景 | 达标证据 |
| --- | --- | --- |
| 权限负例 | shell 复合命令/写参数、空白名单、未认证 WS、过期审批、伪造 MCP 只读标注 | 实际执行器或发送器调用次数为零；拒绝原因可定位 |
| 路径隔离 | 临时 Runtime 执行截图、Cookie/配置修改、ASR 缓存、review、预算 | 所有写入位于注入根；真实目录和服务不变；symlink/junction/ADS 负例通过 |
| 并发 | 两个 Web 会话、同一会话连发、多个 cron 进程、同时消耗最后额度、技能与 review 同写 | 无串话/丢写/超额；冲突返回明确状态；唯一执行约束有效 |
| 故障注入 | 模型超时/429、客户端断线、服务器挂起、进程退出、文件损坏、磁盘不可写 | 状态非假成功；不重放未知写；可停止、查询和恢复 |
| 北极星 A | 所有者 QQ 发 B 站链接，小鱼读取可用信息并给有依据的回答 | 实际端到端记录；无 Cookie/无字幕时如实降级；无未经批准发送 |
| 北极星 B | Web 多步调查，列 todo、引用文件/网页、交付产物，用户中途停止 | 步骤可见；停止后不启动新工具；结果与未完成部分准确 |
| 北极星 C | 夜间整理 → 早报，跨重启继续调度 | 引用指定成功产物；一次时刻只领取一次；投递状态与去重可证 |
| 北极星 D | 安卓观察 → 选择控件 → 人工批准 → 动作 → 新观察 | 设备/观察版本一致；换屏/换设备/旋转时拒绝旧定位；输入法恢复 |
| 北极星 E | 受信 MCP 服务查资料，再申请一项写操作 | 中文、权限、超时和关停通过；生产服务的真实 schema 与认证完成验证 |
| 扩展桌面 | 读取一个受支持应用窗口，在明确授权下完成一次写操作 | 可访问性定位有效；后台能力如实标注；前台接管尊重用户 |
| 运维恢复 | 从备份建立临时实例，升级失败后回滚 | 核心数据可校验；不使用测试实例启动真实外部服务 |

单元和契约测试覆盖明确不变量；真正的子进程、SQLite 多进程、Playwright 和 ADB/账号验收分别建套件。默认 CI 运行离线套件，手动套件因设备/凭据缺失而跳过必须记录为“待验收”。

D26 建立版本化任务集：建议首批 20 个本地核心场景和对应权限/故障负例。相同配置下至少重复 3 次；安全负例必须全部通过，任务完成率单独报告。接真实模型后同时记录模型、配置、耗时、token、成本与人工介入，不能拿两个不同模型的结果直接归因于框架。

## 9 执行管理与禁止事项

每次只推进一个 D 任务或一个可独立验收的子项。完成一个提交就记录：改了什么、哪个证据关闭、跑了什么、哪些真实环境仍没测、当前 commit、下一任务。建议执行者创建 `docs/DEVELOPMENT_STATUS.md`，状态使用待开始/开发中/待真实验收/完成/阻塞，不用含糊的“基本完成”。

提交信息遵循现有中文格式，N 使用实际通过数。继续用户已有的测试通过后推送要求，禁止 force push、删除其他人的变更或提交 `data/`、密钥、浏览器 profile、`xuexi/`。发生远端并行更新先复核再整合。

不得用以下方式宣称完成：删除失败测试、把写工具改 SAFE、把超时改无限、捕获所有异常后返回成功、自动重试未知写、仅建空接口/空页面、只加版本号不保存历史、仅返回截图路径却宣称视觉闭环、仅加 RLock 却宣称跨进程/Playwright 线程安全。

用户需要参与的外部前提：QQ 登录、B 站测试 Cookie、安卓设备与输入法、受信 MCP 服务和允许的目录/工具、桌面目标应用、模型预算。缺少它们不妨碍开发离线契约，但对应端到端能力必须保持待验收。不要打印密钥值，也不要为了验收自行发布、付款、群发或加好友。
