# V2 持久事件通知

`GET /api/v1/agents/{agent_id}/events/stream` 提供有界 SSE 通知，可选 `run_id` 筛选。使用普通 Bearer 所有者鉴权和同源边界，令牌只放请求头，不接受 URL 令牌。连接期间每轮继续鉴权；令牌轮换、关闭或客户端断开后停止读取和发布。

通知复用 `Application.history` 和既有历史仓储，不建立第二套事件序列、正文缓存或重放队列。Agent/run 归属、实例 epoch、清理代次及高水位沿原历史游标校验。查询 `cursor` 和 `Last-Event-ID` 只能指定同一枚游标，不能使用整数 `after`。初次作用域或游标错误在 HTTP 200 前返回；运行期间历史过期发送 `reset`，客户端清空游标并重新读取通知。

每个 `history` 帧的 `id` 是该页的完整续接游标。JSON 只包含 `count`、最多50个 `run_ids`、`has_more` 和 `history_trimmed`，不推送消息、工具参数、事件正文或凭据。通知驱动工作台重新查询当前业务事实，删除屏障和权限仍在业务服务中执行。

每个应用最多8条连接、每页50项、单帧8KiB；空闲每0.5秒读取一次，5秒发送无正文心跳，30秒主动结束并由客户端续接。发送及响应的外层总期限35秒，慢客户端不能无限占槽；连接退出、取消、发送失败乃至正文尚未开始时均释放同一租约。数据库端口继续拥有实际在途读取，没有脱离 HTTP 任务的轮询工作。

工作台使用带请求头的 `fetch` 读取流，支持分块UTF-8和CRLF，不把令牌写入持久存储或URL。断线最多30秒退避，只有通知消费者成功后才推进游标；切换Agent、连接或隐藏页面时中止旧连接，旧响应不能更新新空间。可见后重新连接。原有轮询保留，临时推送失败不会使工作台无法刷新。其他客户端提交的新消息会触发当前会话和列表更新；模型临时预览仍沿原独立接口读取。

协议依据：[WHATWG Server-sent events](https://html.spec.whatwg.org/multipage/server-sent-events.html)。当前开发验证记录见后续交接；所选局部通过不等于新源码已全量验收，平台与长跑另计。
