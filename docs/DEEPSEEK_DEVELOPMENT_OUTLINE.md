## 1 如何执行

原始基线第一轮只做 D00–D04；当前续接先完成 D15，再按依赖推进 R3/R4 剩余任务。D25 的备份准备和 D26 的回归基础提前做，最终运维验收在 R7 完成。桌面控制、B 站写、远程 MCP 和向量记忆不能挤占未关闭的安全和稳定性问题。

每个 D 任务可拆成多个完整提交，不能一次提交整个路线图。每批必须同时交付实现、必要测试、文档和剩余限制。无法完成真实设备/账号验收时，记录“待真实验收”；接口存在、测试跳过、仅 mock 通过都不等于真实能力交付。

项目继续服务现有个人用户，不做推倒重写。先保持现有命令和接口兼容，新增异步运行接口时为旧调用保留薄适配层。新架构契约须与 ARCHITECTURE 同步修订，不能借此绕过分层和组装根。

### 1.1 每批固定工作流

1. 查看 HEAD、工作区和远端；核实当前任务尚未被其他开发完成。
2. 在 `docs/DEVELOPMENT_STATUS.md` 登记任务、证据编号、范围与验收方案。该文件已由 D00 创建，继续维护而非覆盖重建。
3. 先用隔离测试固定失败条件，再改业务代码；安全测试用假执行器，禁止拿真实密钥、账号或危险命令试验。
4. 运行针对性测试，再运行完整 `uv run pytest`；检查 `git diff --check` 和暂存差异。
5. 更新 HANDOFF、状态记录及实际涉及的架构说明；只暂存本任务文件。
6. 按中文格式提交并推送：`领域：要点——细节（N 单测全绿）`，N 为本次实际数字。
7. 报告提交号、修复证据、验证结果、未验收项目和下一任务，不把待验证内容写成完成。

发现别人的未提交修改先保护；不能 `git reset --hard`、强推、用 `git add .` 混入其他工作。基线时 `web_static/index.html` 与 `prototype-html/` 有另一项前端工作，后续任务涉及前端时先重新检查差异再合并。

## 2 必须先统一的契约

以下名称是建议，最终落点遵守 ARCHITECTURE；不要因为名称不同另造同类对象。

| 契约 | 必要字段/行为 | 负责位置 |
| --- | --- | --- |
| RuntimePaths | data、配置写入位置、Cookie、skills、profile、截图、artifact、cache、run、log；可注入 | config 定义值，bootstrap 装配 |
| RunIdentity | run_id、parent_run_id、session_id、channel、principal、conversation_scope | core；低层所需数据经协议/回调传入 |
| RunContext | 冻结权限、取消信号、预算、deadline、追踪信息；不接受模型自行覆盖 | core 协调，safety 做纯策略 |
| ToolResult | status、text、error_code、retryable、side_effect_state、artifacts、verification | tools 低层契约；旧字符串兼容适配 |
| Observation | observation_id、target_id、捕获时间、树/图版本、窗口/页面身份、坐标系 | 各设备驱动产生，工具传递 |
| Artifact | artifact_id、所属 run/scope、类型、大小、hash、受控路径、隐私与保留期 | memory 管元数据，存储依赖注入 |
| Usage/Budget | 模型/工具类别、token、估算/实收成本、预留/结算、父子额度 | llm 产 usage，core 协调，memory 持久化 |
| Approval | 请求与参数摘要、目标/观察版本、有效期、操作者、结果、一次性消费 | safety 协调；持久化回调注入 |

不要把 core.RunContext import 到 tools、memory 或 safety。低层可使用自有不可变参数类型或注入 callable；工具只获取完成任务所需的最小上下文。新管理器、仓储和驱动的构造统一放 bootstrap，并补架构守卫。

建议新增 `POST /api/runs`、`GET /api/runs/{id}`、事件续读和取消接口；旧 `/api/chat` 通过同一执行服务保持兼容。同步 CLI 也消费同一事件源。不能因为 UI 断开就复制执行一次任务。

### D01 结构化 SAFE 命令与进程边界（A01、A02、A19）

- **位置**：`tools/shell_tools.py`；可逐步抽到新 `tools/shell/` 包；`bootstrap.py`、`tests/test_shell_tools.py`。旧注册入口保留兼容薄层。
- **实现**：SAFE 调用解析为已知命令及有限参数，再以 argv、`shell=False` 执行；`dir/type` 等 shell 内建用受控 Python 实现或移出 SAFE。拒绝复合语法、重定向、写参数、路径逃逸、敏感文件和未经确认的工作目录切换。
- **细节**：不能只换另一个前缀正则。Git 子命令参数也要受控，禁外部 diff/textconv、pager、自定义命令配置和危险环境注入；尽量固定可信可执行文件。任意命令仍须人工确认与硬拒绝检查，环境最小化，不自动继承全部密钥。
- **进程**：输出读取有上限、超时后管理所属进程树；Windows 可评估 Job Object。结果区分已确认回收与仍未知，不能统一建议重试；最终 ToolResult 在 D09 接入。

- **参考**：Hermes `tools/terminal_tool_guards.py`、`terminal_tool_lifecycle.py`、`file_tools_paths.py`。学习边界设计，不照搬 Unix shell 假设。

### D02 QQ/cron 权限与会话边界（A03、A04、A05）

- **位置**：`channels/qq.py`、`core/cron.py`、`tools/qq/tools.py`、`tools/cron_tools.py`、Web cron 校验、相应测试。
- **实现**：空私聊白名单拒绝入站与主动投递；新建、编辑、执行和投递时分别验证目标，配置撤销立即生效。群白名单、发送者策略、@触发分别建模，拒绝伪造/非法身份及未知事件类型。
- **会话**：私聊、群聊至少按不同 scope 绑定，两个群不得因同一 sender 共用历史。旧绑定迁移只保留到明确私聊，不复制私密历史到群。
- **提前保护**：在 D12 的完整记忆作用域完成前，群聊不得读取全局个人档案、常驻笔记或跨私聊历史；若现有接口无法隔离，暂时禁用该能力并明确状态。
- **验收**：空名单/名单外/撤销目标时 fake agent 与 fake sender 调用符合预期；群、私聊绑定互不混用；群触发无法获得私人上下文；正常已授权私聊仍回复。同步覆盖工具路径和 cron 直接投递路径。
- **边界**：不增加群发、陌生人主动私信或自动加好友；批准某个群可回复不等于批准群成员使用所有本机能力。

### D03 工作台与终端身份保护（A07）

- **位置**：`channels/web.py`、`channels/terminal.py`、config、bootstrap；前端沿用现有工作成果，避免整页覆盖。
- **实现**：设计本地登录/配对和会话失效流程；默认回环监听；有效 Host/Origin 检查、HTTP 会话鉴权、修改请求的 CSRF 防护、终端 WS 握手鉴权。身份建立接口自身不能允许跨站配对；CORS 不能充当认证。
- **密钥**：设置读取返回“已配置/未配置”，修改接口支持保留旧值及显式替换/清除，日志/异常/事件不输出 token、Cookie 或完整命令环境。已有明文回显字段移除并迁移前端。
- **验收**：未登录读取敏感 API、修改设置、审批、启停服务和打开终端均拒绝；恶意 Origin/Host、过期会话、CSRF 失败时无副作用；合法本地 UI/WS 正常；默认非回环监听失败关闭。
- **边界**：首版是单所有者本地保护，不声称实现公网多租户认证；不自动开放防火墙或监听所有地址。

### D04 全路径与外部依赖隔离（A08）

- **位置**：config、bootstrap、Web 设置/Cookie 路由、AndroidDriver、BiliAPI/ASR、browser、services、MCP、review；测试临时根统一注入。
- **实现**：建立 RuntimePaths 或等价明确路径值，补安卓截图、B 站 Cookie/下载/ASR 缓存、配置更新等遗漏。配置源文件与运行数据可以不同，但二者都须明确注入，不能写回全局真机路径。
- **依赖**：runner、设备、HTTP、模型、时钟、服务探测和终止器均可替换。`data_dir=tmp_path` 不代表外部服务隔离；服务探测不能回退发现真机 pid/端口后将其停止。
- **验收**：临时实例执行所有持久化路径，写入审计仅命中允许根；真实目录 canary 不变；截图、Cookie、配置接口确实覆盖；测试无真实模型费、网络账号访问、服务启停。skills_root 独立注入保持有效。
- **边界**：生产默认路径保持兼容；新增目录结构先迁移再切换，不能以测试方便为由删真实数据。

## 4 R1：持久化与并发

### D05 事务状态和可恢复迁移（A09、A10、A17）

- **位置**：新 `memory/state.py`/仓储模块、现有 `memory/cron.py`、`tools/browser/budget.py`、bootstrap；名称可调整。
- **实现**：先完成 D25 的最小备份，再将共享 jobs/执行账本/额度迁入注入的 state.db。引入 schema_version、唯一键和短事务，提供原子领取、额度预留/结算及 revision 更新接口。
- **迁移**：合法空、文件缺失、损坏文件分别处理；保留旧文件和校验摘要，成功后标记迁移，重入不重复导入。遇未知版本/磁盘失败停止相关能力，不能重置预算放行。
- **验收**：两个真正独立进程竞争最后一个额度仅一个成功；并发编辑不丢数据；中途崩溃、损坏 JSON、数据库忙、只读目录有可解释状态；迁移前后记录校验一致。
- **边界**：已有 memory.db 已使用 WAL，不重复包装为新功能；不要把网络请求/人工等待放在数据库写事务中。此阶段先提供调度 claim，D17 完成调度语义。

### D06 显式会话与有界队列（A05、A06）

- **位置**：Runtime、`core/agent.py`、Web/QQ/CLI/heartbeat、store binding、review 调用。
- **实现**：chat、review、todo、响应都携带请求固定的 session_id/scope；“当前选中会话”只是客户端状态。相同会话按顺序执行，不同会话在容量内独立；跨进程会话租约有所有者与失效规则。
- **一致性**：绑定创建使用唯一约束与事务；不能先查后创建造成重复会话。队列满返回 busy，取消排队无需等待前一个长任务。
- **验收**：屏障控制两个 Web 请求交错，历史、回答、todo、review 均留在正确会话；同会话不交错；跨进程绑定唯一；worker 异常后租约可恢复且不误释放他人租约。
- **边界**：保留既有 SessionRef.bind 和委派 UUID 测试；不靠全局单锁把所有入口永远串行。

### D07 浏览器单一所有者与 profile 租约（A11）

- **位置**：`tools/browser/driver.py`、tools、bootstrap、Runtime 关闭流程及 browser 测试。
- **实现**：Playwright 创建、调用和关闭全部在同一所有者线程/进程；调用者通过有界请求队列交互。profile 跨进程互斥并标识所有者；忙时明确返回，不同时启动两个浏览器使用同一 profile。
- **超时**：等待超时不等于动作已取消，停止后不得继续排入新操作。无法安全中断的动作记为未知，验证或由用户决定后续；不要直接取消正在执行 Playwright API 的任务。
- **验收**：假驱动记录所有操作 thread_id 一致；实际临时浏览器进行跨调用线程读操作；profile 争用、异常关闭、请求积压和退出收尾可复现；不使用真实登录 profile。
- **边界**：暂不强制改成网络浏览器服务；不承诺“加 RLock 就线程安全”。

### D08 技能历史、CAS 与常驻文件一致性（A09、A14）

- **位置**：`memory/skills.py`、`memory/resident.py`、技能工具、bootstrap；历史根路径注入。
- **实现**：完整读改写期间跨进程互斥；expected_hash 检测外部编辑；保存历史内容、作者/来源、时间和摘要；同目录临时写后原子替换，失败恢复。常驻笔记更新也要防丢写。
- **版本**：rollback 产生新修订并再走校验，不把整数版本改小；references 一并纳入版本范围或明确记录不属于该修订，避免主文与附件静默不一致。
- **验收**：两个 writer 同时修改只有一个成功或明确合并；用户编辑后旧 patch 冲突；中途写失败原文件完整；回滚能找回真实内容；junction/symlink/ADS 保护继续通过。
- **边界**：先交付仓储 API 与测试，编辑 UI 在 D18；不自动覆盖外部编辑器写入。

## 5 R2：运行内核

### D09 Run、ToolResult、取消和委派（A19、A20）

- **位置**：新 core run/events 与 memory runs 仓储、Agent、Registry、delegate_tools、ApprovalBroker、Runtime、通道运行接口。
- **实现**：持久运行状态与单调序号事件；结构化工具结果，旧字符串适配；创建、查询、取消和查询产物接口。每次开始模型/工具调用前检查取消与预算，审批中取消必须撤销待批准操作。
- **恢复**：重启将遗留 running 归入 interrupted/unknown；不自动批准旧请求，不重放结果未知写。tool_call_id 是本次记录身份，不等于外部系统已支持幂等。
- **委派**：子 run 具有独立上下文和 trace、父权限/预算上限及取消传播；限定深度、并发和时间。用工厂注入构造能力，tools 不得自行构造 Agent 或 import core。先完成同步子运行契约，再开放独立读任务的有界并行。
- **验收**：排队/模型中/工具中/审批中停止；父取消子任务；异常工具完整回填；断连事件续读不重新执行；重启保留未知副作用；没有把底层仍运行的线程显示为“已停止”。
- **参考**：Hermes conversation_loop、iteration_budget、interrupt_control、interrupt_scope、delegate_tool_child_run、async_delegation_worker。

### D10 网关能力、流式、重试和费用预算（A20）

- **位置**：`llm/gateway.py`、config、core 预算协调、usage 仓储、通道事件消费；新增能力均在 bootstrap 接线。
- **实现**：明确模型能力与角色路由；结构化 request timeout、错误分类、流式事件、usage 与取消。对可重试的暂时模型故障有次数/总时限和退避，不循环切换付费提供商。
- **预算**：模型、压缩、review、embedding、委派共同计费；调用前预留、调用后结算，未知计费保守保留。已授权推理范围内不逐次打扰，增加支出范围必须重新人工授权。
- **验收**：fake 429/超时/认证失败/不支持 tools 或 vision/流式半途断连；超额前禁止新调用；父子累计限制有效；没有 usage 的供应商状态可解释；SDK 错误不泄露密钥。
- **边界**：不更换用户正在使用的模型配置以“提升效果”；不宣称任意 OpenAI 兼容接口都支持相同多模态和工具功能。

### D11 持久上下文与 FTS 生命周期（A16）

- **位置**：`core/compress.py`、Agent、`memory/store.py`、摘要/消息迁移与测试。
- **实现**：持久摘要记录覆盖消息区间、来源和版本；上下文组装先选择摘要及未覆盖消息，再按预算截断，保留目标/约束/未完成任务/证据引用。完整工具批次不可拆分。
- **索引**：FTS 通过 schema/migration 状态在需要时构建，普通连接初始化不 rebuild 全库；原文可检索、旧数据库可迁移。
- **验收**：长对话关键约束仍可恢复；摘要失败保守降级不篡改事实；重启、重复压缩、多个 review 连接不重复重建；3 字 trigram 与 2 字查询现有能力不退化。
- **参考**：Hermes turn_context_compaction 与 context_compressor 系列；不照搬全部 mixin 结构。

### D12 有界 review、记忆来源与隐私（A15、A16）

- **位置**：`core/review.py`、memory store/resident/skills、builtin 工具、bootstrap、工作台记忆操作。
- **实现**：有界 worker 队列、消息区间去重、背压、合并与关停；所有模型消耗纳入 D10。记忆带来源、scope、时间、修订/纠错关系，检索和注入先按 scope 过滤。
- **写入**：新增/编辑/重写/导入/review/回滚共享额度和输入检查。明确事实与不可信外部指令的区别；敏感覆盖或技能变化进入可查看差异的候选队列。正则不是完整提示词注入防御，权限仍由确定性代码约束。
- **遗忘**：支持删除和“不要记”；原文按既定保留策略处理，派生摘要/向量/缓存建立失效机制，不能在下次 review 自动恢复被遗忘事实。
- **验收**：profile_edit 不能绕过总额；并发 review 数有界；重复消息不重复学；外部“改变权限”文本不能生效；群上下文不返回个人秘密；用户删除后不被自动重建。
- **边界**：自主学习不等于自主改安全配置或批准外部写；不把所有普通记忆都强制人工逐条批准。

- **边界**：不自动点击支付、发布或授权确认来凑成功；DANGEROUS 和 requires_human 不放宽。真实设备未插入时保持待真实验收。

## 7 R4：调度、技能与 MCP 管理

### D17 cron 编辑、依赖与可靠投递（A04、A17）

- **位置**：memory cron/state、`core/cron.py`、cron_tools、Web 任务 API/页面、投递 outbox。
- **实现**：revision 编辑 prompt/schedule/enabled/skills/context_from/target；调度唯一键、原子 claim、租约及失效恢复；显式 timezone、错过执行与运行中到期策略；禁无限排队。
- **依赖/投递**：校验无环，context_from 引用具体成功 run/产物和新鲜度；执行与发送分别记账；单条所有者通知的授权、频次、去重与目标撤销有独立判断。未知发送结果不自动再发。
- **验收**：两个调度进程同刻领取、任务长于间隔、编辑与到期交错、时区边界、重启、依赖失败、成功发送后确认丢失；不会因重复 tick 再执行已领取副作用。
- **扩展**：预采集脚本仅作为可选后续子项，需固定受信文件/hash、最小环境、独立权限；不得把任意命令字符串藏进 cron。

### D18 技能编辑、回滚与安装隔离

- **位置**：D08 仓储 API、skill_tools、Web 技能 API/面板；新安装器归属与依赖先按 ARCHITECTURE 明确。
- **实现**：读取原文、保存预览、expected_hash 冲突、历史差异、回滚；references 有界文本编辑也遵守路径和修订规则。外来包先到隔离区，检查清单、文件类型/大小、危险脚本和来源，再由用户激活。
- **验收**：外部编辑冲突不丢内容；回滚主文/附件一致；恶意路径压缩包不逃逸；安装不执行 postinstall；技能正文不能变更风险等级、allowed_tools 或自动放宽 MCP 权限。
- **边界**：扫描只能提供风险证据，不能宣称扫描通过即绝对安全；远程技能执行脚本是独立授权能力，不随导入自动启用。
- **参考**：Hermes skills_guard、skill_manager_guards；优先复用小鱼现有 references 读取与路径测试。

### D19 MCP 连接管理和权限漂移

- **位置**：`tools/mcp/client.py`、tools、config、bootstrap、Web MCP 面板、MCP.md。
- **核心交付**：列出配置/连接/健康/错误状态；启停、超时、协议分页和工具数量/输出上限；命令/参数/服务身份/schema 指纹变化后重新检查只读授权。只读标注始终不是授权来源。
- **认证与扩展**：先定义凭据安全存储和目标范围，再做 Streamable HTTP、重连和必要 OAuth。resources/prompts 若接入，要有 scope、大小、来源标记；sampling/roots/elicitation 不默认开启。
- **验收**：现有真实离线 stdio 子进程测试不退化；schema 改动不能沿用旧 SAFE；挂起/异常帧/大输出/重连不重放未知写；日志脱敏；一项受信生产服务只读与确认写实际联调。
- **边界**：stdio 管理属于 1.0；HTTP/OAuth 可独立后置并标为未实现；环境白名单不是操作系统沙箱，MCP 服务必须来自明确受信配置。
- **参考**：Hermes mcp_tool_config 与官方 MCP 文档。不要照搬无法测试的第三方服务器配置。
