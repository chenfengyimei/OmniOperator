# V2 图片附件与实际附图预算

本批接通 D6 的低清图片附件，默认入口仍为 V1。开发与离线验证分别登记在 [任务台账](tasks/v2.json) 和 [本批证据](evidence/v2-images.json)。真实供应商、Mac/Linux 运行及完整 V2 验收仍待完成。

## 生产路径

`ImageService`通过对象端口和有界图片编码端口校验原始图片，复用对象存储。接收回合时，消息、不可变图片分块、运行、入站去重和工作项共同提交；图片上传不等于模型接收。会话截图先显式校验，再复用同一个对象，不再保存第二份图片真值。

`ContextService`选择完整历史回合后，再按模型修订的图片协议选择最多四个引用；较早图片改为包含原因的未附加标记。图片引用包含消息分块、对象、指纹、实际尺寸和策略身份。上下文快照固定消息范围，图片分块在原消息入队后不可增改。

`ModelCalls`继续拥有统一的预检、授权和费用路径。它先在短事务内登记图片预留，再读取对象并生成请求载荷。编码前后、凭据准备后和派发前复核运行、来源、模型与凭据代次。供应商只收到经过校验的内存 data URL；主数据库、对象路径、内部引用和策略编号不进入模型图片载荷。流式和非流式都走这条路径，摘要保持纯文本。

## 范围与计量

- 输入为实际可解码的单帧 PNG、JPEG 或 WebP；最多 16 MiB、8192 像素单边及 1600 万像素。拒绝动画、SVG、损坏图片和解压炸弹。
- 请求图片在内存中校正 EXIF 方向、转成 RGB、缩至最大 512 像素边长，重新生成无元数据 PNG。原图只存于受保护对象目录。
- 模型配置中的 `image_policy` 独立于普通模型参数，绑定不可变配置修订。协议默认 `disabled`，显式启用 `openai_low` 才允许新消息附图。单次上限 1–4，本轮累计次数从单次上限至 64，默认 4/12。
- 本批只支持已声明低清固定计量的 gpt-4o、gpt-4o-mini 及源码明确列出的日期版本；可带 `openai/` 前缀。对应低清图片成本分别为 85、2833 输入 token。型号列表在 `domain/images.py`，依据 [OpenAI 图片计量说明](https://developers.openai.com/api/docs/guides/images-vision)。自定义地址仍须显式采用此协议并自行验收供应商合同，不自动推断能力。
- 保守计量器计算文本/工具/引用的 UTF-8 包络，再加实际选择图片的固定 token 成本；不会把 base64 字符数当作文本 token。专用计量器尚无图片合同的配置明确报错，不隐式退化为纯文本。
- 每次模型调用中每张图片计一次，包括工具循环中再次引用同一张图片。确定未发送的预留释放；`prepared`、已附加和 `unknown` 都占用本轮累计上限。压缩、上下文快照变化和删除消息均不重置上限，耗尽后明确停止，不自动去图重发。
- 上下文摘要记录源消息的图片引用数量及“未包含图片内容”，不能声称摘要模型看到了图片。被摘要覆盖的旧图片不会通过摘要恢复到请求。

## 数据、删除与恢复

数据库基线增至 `v2_0032`、111 张表：`image_objects`保存已验证的非拥有元数据；`model_image_policies`固定修订策略；`model_call_images`保存实际调用引用及状态。费用、消息和运行继续使用原有账本。

未引用上传仍可在到期后回收，图片元数据随对象级联删除。消息图片及模型调用引用才构成对象保护。删除源消息复用现有摘要、记忆与上下文失效传播，清除调用记录的对象指针；保留指纹、原分块身份与次数，既允许对象回收，又防止重新获得已消耗额度。共享同一对象的其他有效引用继续保护该对象。

SQLite 约束和触发器拒绝跨空间引用、事后添图、策略改写、预算超限及调用记录删除。崩溃恢复沿现有模型调用恢复路径把未结清调用及其图片置为 `unknown`，没有证据时不猜测已发送或释放预留。

## HTTP 与工作台

所有端点使用既有所有者认证、Agent 作用域、同源和 `no-store` 规则：

| 入口 | 合同 |
| --- | --- |
| `POST /api/v1/agents/{agent}/images` | 有界原始二进制上传；依实际格式判定，返回 `registered_not_attached` |
| `POST /api/v1/agents/{agent}/images/{object}/prepare` | 显式校验已有对象/截图，不进行模型调用 |
| `POST /api/v1/agents/{agent}/turns` | 新增最多四个 `image_ids`，允许纯图片；相同去重键更换文字或图片会冲突 |
| `GET /api/v1/agents/{agent}/runs/{run}/images` | 返回本轮策略、已登记图片、每次调用状态、未附加原因及累计用量 |

工作台图片草稿只在有界内存中保存对象引用，按 Agent/会话隔离；页面切换保留草稿，迟到上传不会写入另一会话。发送时绑定文字和图片的去重身份，期间新编辑内容保留。消息展示图片元数据，运行报告区分登记、预留、附加、未发送及未知，始终不声称模型已经理解图片。模型图片策略沿现有配置编辑器保存、历史查询和导入导出。

诊断日志不保存图片载荷、聊天原文或模型请求正文。编码工作最多两个并行、八个已接收任务；取消等待方不撤销底层线程归属，关闭未完成时继续保留实例资源。

编码适配器显式拥有输入/输出内存缓冲区及验证、解码、方向校正、RGB和重建像素图像，正常返回与Python异常路径均关闭资源。独立RGB图像登记清理后，先关闭原解码与方向校正图像，再缩略和重建PNG；清理异常仍尝试关闭其他已登记资源并保留原错误上下文。转换算法和输入/输出预算保持，取消等待方后仍由原编码线程完成清理；这不证明原生进程异常终止时可执行清理，也不替代历史内存峰值问题的验收。

## 验证边界与接续

专项覆盖真实 Pillow 编解码、SQLite 事务/约束、来源删除和对象级联、图像上限、重复请求、跨 Agent、工具循环、真实上下文压缩与快照变化、未发送/未知、凭据变更、迟到准备、流式取消与实际回收。真实锁定 SDK 只访问本地假 HTTP/SSE；浏览器按四视口、双主题使用独立上下文及数据库。

本批未调用真实付费模型，未执行设备动作，不替代三平台运行、供应商视觉效果、全量、主包重建或 72 小时验收。本地ONNX现已接文档检索，见[向量合同](V2_LOCAL_VECTORS.md)。后续继续档位路由、记忆语义、技能媒体、MCP/OAuth、插件和市场；D7才在功能对齐后切换默认入口。
