# Android 观察与受控动作

所有写工具都需要人工批准和 observation：点击元素、坐标、滑动、按键、文字输入。
`android_screen_tree` 返回的随机令牌绑定会话、设备序列号、完整 UI XML、尺寸与方向；
默认 120 秒有效，最多缓存 32 条，一次写入尝试后失效。进程重启只恢复树的展示，
旧令牌不能使用。共享 data_dir 的各入口按设备文件锁互斥；读写锁覆盖完整观察/动作流程。

坐标点击必须引用 `android_screenshot` 的令牌，比较截图像素和截图前后的 UI 树。
工作台“实时看屏”保持半分辨率 JPEG q40；要操作，先点“锁定当前帧以操作”。
锁定帧使用完整 PNG，点击坐标排除 object-fit 黑边，再换算一次；画面改变就拒绝。
刷新树可以给返回/主屏键提供新令牌，服务端不会自动替换成“最新观察”绕过绑定。

输入只允许唯一的、启用的非密码 EditText 焦点。Unicode 使用 ADBKeyboard；
切换输入法后再次检查焦点，失败或取消不广播文字，并尝试恢复原输入法。
设备返回的原输入法名称先校验，不能被拼成任意 shell 命令；原本启用的 ADBKeyboard
不会被错误禁用。ASCII 的引号与 `%s` 特殊序列也改走 Unicode 通道，避免悄悄改写内容。

写后强制重新观察。**ADB 返回成功和树发生变化都不证明业务目标达成**，目前动作结果
保守记为 unknown，附新观察供下一步核查。设备断开、动作超时、输入法恢复失败也不会自动
重复旧动作。工具返回结构化状态，内核不再从“已点击”文字推断任务成功。

ADB 的观察和输入是两次设备调用，无法保证期间外部应用或用户完全不改变界面；
文件锁只能协调共享数据根的 Omni 入口。敏感场景仍须用户在前台核验。
当前不支持无法提供 UI 树的游戏/画布盲操，动画画面可能导致坐标操作保守拒绝。
真机多设备、旋转、掉线、中文输入法恢复和 MJPEG 延迟仍需插入设备验证；
离线测试不能替代真机适配结论。

C01：全局 devices 命令不加 -s，显式设备命令只组装一次 -s；多设备按指定 serial 查找，避免重复目标参数。

## C05 多设备与应用控制

工作台手机入口打开 `/android/`；用户点击检测后列出 device/unauthorized/offline。
单个已授权设备可自动选定，多设备必须明确选择；每次 API/工具调用固定 serial，
不修改共享的“当前设备”。切换设备立即撤销界面令牌，迟到响应不会覆盖新设备状态。

观察、缓存视图和线程/文件锁按设备隔离；默认最多 8 个设备上下文、每设备 32 个单次观察。
屏幕读取和动作在设备互斥内完成，预览让位于交互操作。新按设备 API 的人工观察绑定配对
cookie 身份；agent 绑定 SessionRef，观察不能跨设备或对话使用。

工具增加 android_list_apps、android_launch_app、android_long_press；已有工具支持 serial，
滑动增加 left/right。长按元素 200–2000ms（默认 600）；启动应用需人工确认且在用户
android.allowed_apps 白名单内（默认空），只解析 MAIN/LAUNCHER 组件，不接任意 Intent/URL。
工作台提供元素点击、长按、滑动、中文输入、返回/主屏、白名单应用启动及锁帧坐标点击。

配置 android：allowed_apps、observation_ttl_s（默认 120）、operation_timeout_s（默认 30）、
max_devices。ADB 客户端输出有界（stdout 16MiB/stderr 64KiB），操作内多条命令共享 deadline；
清理与恢复输入法另给短预算。错误带稳定 code，不回显失败命令里的输入文字或 stderr。
UI dump 在失败时也清理固定临时文件；由同设备文件锁协调。ADBKeyboard 广播限定目标包。
只注入 shots_dir 时缓存/锁也派生到其父目录，避免测试污染真实 data。

新接口在 `/api/android/devices` 下按 serial 提供 observe/snapshot/apps/actions。
旧单设备 HTTP 路径/请求模型仍保留；多设备旧客户端会收到明确选择提示。
动作回读仍是 unknown，不把 UI 变化当作业务成功；仍不支持游戏/画布盲操作。

独立源码 1004 项全绿，目标类型检查 0 错误，Chromium 多设备选择/长按/切换撤权/手机布局已验证；没有真实手机的新增验收证据。共享实时预览见下节。

## C06 共享实时预览

同一工作台 Runtime 内每设备一个按需生产者，多个客户端共享最新半分辨率 JPEG q40。
默认最多 2fps/每设备 2 观看连接，慢客户端跳过旧帧，不建立历史帧队列。
最后观看连接释放后立即停止采集，5 秒内回收等待线程。交互观察/动作优先，
同进程或文件锁忙只跳帧，不重放动作；跨工作台实例仅共享设备锁，不做图像中转。

页面展示序号、画面年龄和采集耗时，超过 2 秒标旧；设备掉线/坏帧停止，用户手动重开。
预览不创建 observation，锁帧仍单独捕获完整 PNG 和单次令牌。切换设备清空树、帧及令牌，
迟到响应不覆盖新设备。新增 stream/stream-state 接口位于按设备路径下；旧 stream 路径
转用同一采集器，媒体类型与 JPEG 尺寸兼容。

配置增加 preview_fps（默认 2）、preview_clients（默认 2）、preview_idle_s（默认 5）。
Runtime.close 报告未退出的采集线程，残留时保持数据库；不声称关闭完成。
真机仍需验证旋转、掉线、输入法恢复、UI 树与预览延迟；假件不能替代硬件结论。
