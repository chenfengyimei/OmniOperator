# Android 观察与受控动作

所有写工具都需要人工批准和 observation：点击元素、坐标、滑动、按键、文字输入。
`android_screen_tree` 返回的随机令牌绑定会话、设备序列号、完整 UI XML、尺寸与方向；
默认 120 秒有效，最多缓存 32 条，一次写入尝试后失效。进程重启只恢复树的展示，
旧令牌不能使用。共享 data_dir 的各入口按设备文件锁互斥；读写锁覆盖完整观察/动作流程。

坐标点击必须引用 `android_screenshot` 的令牌，比较截图像素和截图前后的 UI 树。
工作台“实时看屏”保持半分辨率 JPEG q40；要操作，先点“锁定当前帧以操作”。
锁定帧使用完整 PNG，点击坐标排除 object-fit 黑边，再换算一次；画面改变就拒绝。
刷新树可以给返回/主屏键提供新令牌，服务端不会自动替换成“最新观察”绕过绑定。

输入只允许唯一的、启用的非密码 EditText 焦点。Unicode 使用 ADBKeyboard；
切换输入法后再次检查焦点，失败或取消不广播文字，并尝试恢复原输入法。
设备返回的原输入法名称先校验，不能被拼成任意 shell 命令；原本启用的 ADBKeyboard
不会被错误禁用。ASCII 的引号与 `%s` 特殊序列也改走 Unicode 通道，避免悄悄改写内容。

写后强制重新观察。**ADB 返回成功和树发生变化都不证明业务目标达成**，目前动作结果
保守记为 unknown，附新观察供下一步核查。设备断开、动作超时、输入法恢复失败也不会自动
重复旧动作。工具返回结构化状态，内核不再从“已点击”文字推断任务成功。

ADB 的观察和输入是两次设备调用，无法保证期间外部应用或用户完全不改变界面；
文件锁只能协调共享数据根的 Omni 入口。敏感场景仍须用户在前台核验。
当前不支持无法提供 UI 树的游戏/画布盲操，动画画面可能导致坐标操作保守拒绝。
真机多设备、旋转、掉线、中文输入法恢复和 MJPEG 延迟仍需插入设备验证；
离线测试不能替代真机适配结论。
