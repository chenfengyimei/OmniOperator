# 人格（PERSONA.md）

## 0. 一句话定位

人格 = `config.yaml` 里 `persona` 段的两个键（`name` / `system_prompt`），
`system_prompt` 每轮都进系统提示词。**它是"她是谁"的唯一来源**——
所以它既不能被悄悄清空，也不能被写成放凭据的地方。

本文件讲三件事：**保存契约**（什么样的正文允许保存）、**热生效**（改了什么时候起作用）、
**凭据拒绝**（为什么人设里不许放密钥）。

## 1. 配置形态

```yaml
persona:
  name: "小鱼"                 # 显示名：CLI 标题、会话元数据
  system_prompt: |             # 正文：每轮进系统提示词
    你是小鱼，一个运行在用户电脑上的个人智能体。
    说话简洁，先给结论再给理由。
```

- `name`：只用于**显示**（会话列表、CLI 标题），不进提示词。
- `system_prompt`：进提示词。`{now}` 会被替换成"见本轮运行上下文的 observed_at"
  （见 `core/context.py:42` 的 `system_prompt()`）。

## 2. 保存契约

判定实现在 `agent/src/omni/system/persona_rules.py`，入口在
`agent/src/omni/system/config_io.py:apply_updates`——**改文件之前**校验，
拒绝了磁盘上一个字节都不会动。

| 规则 | 阈值 | 违反时的文案 |
|---|---|---|
| 名字非空 | ≤ 30 字 | 「它叫什么」不能空着 / 名字太长了（N 字，上限 30 字） |
| 正文非空 | > 0 字 | 人格正文不能是空的：想换回默认人设，请把默认内容贴回去再保存 |
| 正文里没有凭据 | 命中即拒 | 人格正文里出现了疑似〈类别〉：人设会跟着每次对话进入提示词，凭据不能写在这里。请删掉这一段再保存 |
| 正文够长 | ≥ 20 字 | 人格正文太短了（N 字，至少 20 字）：这么短的内容说明身份、说话方式或规则都没写全 |
| 正文不太长 | ≤ 20000 字 | 人格正文太长了（N 字，上限 20000 字） |

**判定顺序是 空 → 凭据 → 长度**，这是刻意的：一段 16 字的正文里藏着密码时，
报"太短"会误导用户——他会去补字，而不是删掉凭据。凭据才是更危险的那件事。

### 2.1 为什么空正文一律拒绝（不区分"清空"与"不存在"）

`config_io` 对 multiline 键只校验"是不是字符串列表"，空列表 `[]` 照样通过，
于是 `_replace_multiline_block` 会把整块正文替换成空——**用户保存后人格凭空消失，
而前端还在提示「已保存」**。

这个坑来自参考项目 `xuexi/surfcore` 的一则真实事故（`docs/cases/2026-10-31-persona-tone-overwrites-core.md`）：
他们做多层人格，"保存全部"时服务端少返回一层，客户端把空值也发过去，
于是语气层的内容写进了核心文件、或者核心被清空。抄的是**判定逻辑**：
空值语义必须显式、每层一个显式分支、核心内容有最小长度闸门。

我们只有一层，但同一个洞照样存在。想换回默认人设，请把默认内容贴回去再保存——
**不提供"清空"这个动作**，因为清空和误操作在协议里长得一模一样。

### 2.2 凭据检测在 `system/text_guard.py`（单一真源）

人格与长期记忆**共用同一份检测表**（`agent/src/omni/system/text_guard.py`）。
第一版两边各写一份正则表，结果人格侧漏掉了「密码是」与 Cookie 两类——
**两份真源必然漂移，漂移只会往"某一处更宽松"的方向走**。
现在两边只共用"检测"，各自决定"命中之后怎么办"（人格拒绝保存，记忆拒绝写入）。

## 3. 热生效

`system_prompt` **在进程启动时被读进 `runtime.config`**，运行中的 Agent 用的是那份快照。
所以改了人格要**重启才生效**——工作台会显示「待重启」。

> 以前 persona 不在"改了要重启"的比较范围里：改完前端显示"已生效"，
> 但运行中的 Agent 用的还是启动时的快照——**用户以为改了，其实没改**。
> 现在人格单独参与比较（只比 `system_prompt`；`name` 只用于显示，
> 而且 bootstrap 会用目录 profile 覆盖它，整段比较会让非默认 profile 永远误报）。

## 4. 边界与已知限制

- **正文里的凭据按形态判定，不按语义**：私钥、API key、Cookie、密码赋值等确定形态才拦；
  身份证/银行卡这类**必须旁边出现上下文词**（"身份证""卡号"）才拦——
  否则订单号、BV 号、时间戳这类普通长数字会被误伤（误伤比漏判更常见，代价更大）。
- **不支持人格分层**：参考项目有 core/tone/scene/daily 四层与分场景注入，
  我们只有一层 `system_prompt`。这属于"拟人化行为层"，见
  `xuexi/NOTES.md` 第 7、11 节，尚未落地。
- **改过的正文不会自动备份**：配置写入本身有 FileLock + 原子写，
  运行数据另有 `omni.system.backup` 统一入口；没有单独的"人格备份目录"。
