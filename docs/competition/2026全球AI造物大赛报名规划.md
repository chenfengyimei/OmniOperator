## 2. 赛道匹配与参赛策略

### 2.1 为什么选「智能办公与任务执行」

该赛道官方主题是 **“让AI从回答问题走向完成任务”**，场景为会议协作、数据分析、业务自动化。
OmniOperator 的产品定位（README 原文：“一个跑在你电脑里的数字具身智能体……不是聊天框里的助手”）与赛道主题**逐字契合**，且项目已具备：

- 三套真实效应器：Windows 桌面自动化（UIAutomation）、安卓手机（ADB）、浏览器（Playwright）——直接覆盖“业务自动化”；
- 心跳驱动的定时任务与依赖链、六层记忆、技能/插件生态——覆盖“会议协作、数据分析”的常驻执行需求；
- 确定性安全内核 + 本地优先——回答评委必问的“AI 乱来怎么办 / 数据隐私怎么办”。

### 2.2 差异化叙事（评审记忆点，一句话）

> 别人做“更聪明的聊天框”，我们做“住在你电脑里、有手有眼有记忆、且被代码管住的数字员工”。

三个对比锚点（BP 与路演反复使用）：

| 对比对象 | 它们的短板 | 小鱼的回答 |
|---|---|---|
| 云端聊天助手 | 只会说不会做；关掉页面就消失 | 常驻本地 + 三套效应器，观察-决策-执行-复核闭环真正做完任务 |
| 云端 Agent / RPA | 数据出域、行为失控、脚本脆弱 | 本地优先隐私不出机；确定性安全内核 fail-closed；观察令牌防“点错按钮” |
| 传统 RPA | 无记忆、无主动性、靠人写脚本 | 六层记忆 + 心跳节律主动执行；技能包自然语言可扩展 |

### 2.3 赛区选择（⚠️ 提交后不可改，需你确认）

- **默认建议：全球赛区**。团队在广州（按环境信息推断，请确认），无 NTU 关联时走全球通道（20 个决赛名额）。
- 新加坡赛区有 10 支直通决赛名额、竞争通道独立，但由 NTU 校友联盟主办，**若团队成员有南洋理工校友/在读关联，值得评估改走该通道**。
- 决策点：是否有 NTU 关联？有 → 考虑新加坡赛区；无 → 全球赛区。

## 4. 项目介绍草稿（≤1000 字，可直接粘贴）

【背景】当前 AI 助手大多停留在“对话”：能回答问题，却难以在真实办公环境里把任务做完；云端 Agent 又面临隐私外泄与行为失控两大顾虑。办公自动化需要的不是更大的聊天框，而是一个可信、常驻、能动手的数字员工。

【方案】OmniOperator（小鱼）是运行在用户本地电脑上的“数字具身智能体”，以 Apache-2.0 开源。它拥有三套真实效应器——Windows 桌面自动化、安卓手机 ADB 控制、浏览器操控，配合截图/UI 树等感官，形成“观察—决策—执行—复核”闭环：每个动作绑定观察令牌，执行前复核界面、执行后强制复检，从工程上杜绝“点错按钮、发错消息”。它通过 QQ、Web 工作台、CLI、心跳四个入口共用同一内核与记忆，7×24 常驻，按心跳节律主动执行定时任务与依赖链。

【核心技术】①确定性安全内核：SAFE/CONFIRM/DANGEROUS 三档风险、灾难命令硬黑名单、无人值守 fail-closed、结果未知不自动重发——安全由代码强制而非模型自觉；②六层记忆与本地向量检索：对话逐字留存、分层压缩、人物卡与事实检索，数据全部留在本机；③技能与插件生态：SKILL.md 技能包隔离安装、人工确认激活，支持 MCP 扩展；④四层架构与全链路审计：费用账本、运行事件流、AST 强制分层守卫。

【进展】项目已完成 Windows 平台核心能力与安装器链；据 2026-11-12 交接记录，最新一次全量离线自动化测试 4658 项中 4654 项通过（4 项失败为并行会话样式守卫与争用抖动，非功能缺陷）。V2 架构重构推进中，macOS/Linux 服务管理已接线、待实机验收。

【价值】面向会议协作、数据分析、业务自动化三类办公场景，让 AI 从“回答问题”走向“完成任务”，同时以本地优先与确定性安全解决企业隐私与合规顾虑；赛后可依托开源社区与园区孵化，走向个人订阅与企业私有化部署。

> 字数约 800，符合 ≤1000 字限制。测试数据引用口径来自 docs/HANDOFF.md（2026-11-12），提交前如仓库有新全量结果请同步更新；对外材料建议简写为“4600+ 项离线自动化测试”。
