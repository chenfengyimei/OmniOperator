# V2 QQ 文本通道接入

本合同对应 D5 的 QQ 文本首批。默认入口仍为 V1；B站、安卓、附件及真实 QQ 账号验收继续待完成。本批不导入 V1 白名单、人物、会话或数据库，不启动 V1 Runtime。

## 使用入口

启动独立 V2 实例，进入开发工作台的「配置」建立 `channel/qq` 配置。`endpoint` 是 OneBot v11 正向 WebSocket，远程必须为 `wss`，回环地址可用 `ws`；地址不能包含凭据、查询串或片段。`account` 填实际机器人 QQ 号，`credential_ref` 引用独立凭据服务中的访问令牌。

在「人物与档案」建立人物，并绑定 `channel=qq`、`external_id=发送者QQ号`。昵称和上报的身份不能自动创建所有者或人物绑定。

在「QQ通道」建立会话授权，分别指定私聊/群聊、对方QQ号/群号、人设和入站冷却。默认停用；启用且通道配置有效后会主动连接并接收消息，可能产生模型费用。停止接收时停用会话授权或通道配置。一个实例最多四个接收连接，一个Agent最多64份会话授权；同一机器人配置到多个通道时停止自动接收并报告账号歧义，避免重复回复。

每份会话授权有独立会话和人设。群聊只接受正常群消息且要求消息段明确 @ 当前机器人；私聊只接受好友消息。发送者必须已有人工人物绑定。只支持文本段及对机器人本人的 @；CQ字符串作为普通文字，不解析成指令；图片、语音、引用回复、临时会话和匿名消息暂不接入。工作台本地聊天、桌面命令不能写入QQ专用会话。

QQ回合不加载所有者档案、常驻记忆、全局事实召回或全局人设，不注册工具和插件。人物关联用于来源归属和撤权，不能使远程发送者获得所有者权限。群聊当前只提供共享会话正文，不自动注入参与者个人档案。

## 事务与授权

`qq_bindings` 保存明确授权、修订、专用会话、人设和最近接收时间。`qq_runs` 关联统一运行及人物，固定会话授权修订、通道配置修订、人工账号绑定、事件键、内容指纹和有效人设；事件归属不可改写。消息正文只存在于 `messages`，不保存重复上游事件正文。

事件键绑定机器人账号、场景、目标和带符号 int32 消息编号，0和负数均合法。人物/会话授权检查、去重、消息、运行、排队工作项及审计在同一数据库事务提交。重复事件返回已有运行；相同事件键但内容或发送者变化拒绝，拒绝和事务失败不留下半份运行。

模型调用、输出提交和投递前共同使用 `qq_authority.py`。停用/修改会话授权、变更通道配置、撤销人物账号或凭据会阻止后续调用及发送。配置修订变化要求新运行；凭据变更代次还绑定实际连接，接收事务再次核验，发送连接建立前后两次核验。监督器关闭失效连接并有界退避重连，异常不携带提供方原文。

最终助手消息、运行成功和待审批outbox原子提交。每条回复仍需「持久投递」逐项批准，不自动批准，不因QQ消息内容触发审批。发送前核验最新尝试、令牌、boot、租约、审批期限、配置、凭据和精确目标。

入站冷却按会话持久化，1至3600秒。原生QQ发送另外按机器人账号统一间隔3秒；依据已有投递尝试的持久时间计算，重启不清零，冷却期间推迟领取、不消耗新尝试。工作台显示最近接收时间、间隔和发送恢复时间。

## 传输与结果

真实网络只在V2适配器中发生。连接先调用 `get_login_info` 核验账号，再接收或发送；收发帧最多64KiB，内部接收队列16帧，最多8个实际连接归属（四接收、四发送）。单次发送总期限15秒，连接/登录分别受限，回收由调用任务持有，关闭未结清时不能报告完整关闭。

发送仅构造一个 `send_private_msg` 或 `send_group_msg`，正文使用一个文本消息段，不切片。提供方明确成功且返回合法消息编号时才记为sent；这只证明提供方接受，不证明对方已读。调用发出后断线、超时或回执无效均为unknown，不自动重发；派发前确定未调用时记为not_sent。

正向WebSocket没有本项目可控制的持久上游重放游标。因此已提交事件可以去重，但不能承诺断线期间的消息自动补收；队列满、未授权、未绑定、冷却及不支持的内容可以拒绝。连接诊断提供明确状态；需要历史补收时须另行建立有来源和游标的合同。

协议依据：[OneBot v11 通信](https://github.com/botuniverse/onebot-11/blob/master/communication/ws.md)、[消息事件](https://github.com/botuniverse/onebot-11/blob/master/event/message.md)、[公开API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)。

## HTTP与验证范围

以下均在所有者认证的 `/api/v1/agents/{agent_id}` 下：

- `GET /qq/bindings`：UUID游标，单页上限100。
- `POST /qq/bindings`：创建完整授权，revision为0。
- `PUT /qq/bindings/{binding_id}`：完整编辑与revision比较；目标和通道不可更换，须另建授权。
- `GET /qq/status`：连接、授权拒绝原因和发送冷却；不暴露另一个Agent的连接详情、令牌或提供方原文。

离线专项覆盖真实SQLite、假模型、假OneBot、锁定WebSocket客户端的本地假服务、私聊/群聊审批投递、撤权、并发重放、冷却、回收和四视口双主题。每例使用独立数据目录或浏览器上下文。

真实账号尚未验收。后续使用指定测试账号完成登录身份、好友/群绑定、重连、凭据撤销、审批后的单条发送、实际提供方回执与unknown人工核查；实测单独记录，假服务不替代真实结果。附件、群回复引用、重放补收和更完整的业务能力属于后续范围。
