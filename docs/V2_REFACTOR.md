# V2 架构重构：实施记录与继续入口

本记录对应已批准的 R0–R7 计划。**当前是可运行的基础批次，整个重构尚未完成，默认四个入口仍使用V1。**
V2 使用独立目录，不导入V1代码、不读取旧配置/数据库、不双写。尚未完成业务迁移前，不删除或归档仍有生产调用的V1模块。
任务真值见 [任务台账](tasks/v2.json)，验证结果见 [离线证据](evidence/v2-offline.json)。

## 已落地的基础

- `domain → application` 定义纯状态与端口；`adapters` 实现外部能力，`composition` 构造并拥有资源。
- 单一`omni.db`，35张声明业务表、Alembic新基线及FTS5派生索引；SQL快照不引用当前metadata。
- 单写入执行器、四个读取线程、队列上限、只读连接、显式事务和跨Agent组合外键；读取不能暗中写入。
- 消息、运行、入站去重、工作项共同提交；输出、终态、投递记录共同提交。消息原文只保存一次。
- 四个并发回合、同会话FIFO、不同会话并行、协作取消和可重入关闭。当前仅运行回合分发，尚未接入新的定时与投递工作器。
- 动作意图、一次性审批、策略版本复核、结构化结果和崩溃后的unknown；未知外部写入不重发。
- 模型费用预留/结算与未知费用保留；真实模型不在默认测试中运行。
- 记忆来源逐字锚定、FTS与中文子串回退、作用域隔离、遗忘时清除修订正文与索引内容。
- 标准logging、上下文、OpenTelemetry追踪身份、有界单写入日志、脱敏、轮转、丢失计数和磁盘故障降级。
- 独立`/api/v1`接口、所有者令牌、配置revision、记忆、审计、日志查询及最小开发工作台。
- 12项内建能力：系统信息、文件列表/读取/指纹写入、审批后的argv执行、独立Agent浏览器导航/读取/点击/填写、记忆搜索/写入/遗忘。
- 能力工作器使用有界JSON协议、最小环境和独立进程；Windows使用Job Object，POSIX使用受控进程组。
- 独占离线备份/恢复，SQLite一致快照、文件指纹、恢复前整体验证、恢复后撤销登录令牌。

## 运行与验证

开发入口：`uv run --no-sync python -m omni.composition.cli --home <全新绝对目录> serve`，默认端口8766。
另一个终端执行同入口的`auth`子命令获取本机令牌，在工作台输入。**该令牌属于私人凭据，不能加入任务记录。**
`init`仅建立新库；`doctor`、`backup`要求实例已停止并取得独占锁；`request`通过HTTP查询正在运行的实例。
部署与恢复示例见 [开发部署说明](../deploy/v2/README.md)。

专项门禁：`uv run --no-sync python scripts/ci_v2.py`。全仓收尾仍执行`uv run --no-sync pytest -q`。
Pyright当前为新增四层的默认模式检查，不等同于计划要求的全生产代码严格检查。
GitHub三平台工作流仅是待运行的验证入口；本机执行结果只代表Windows。

## 数据和安全边界

实例身份与所有者唯一，业务实体使用完整UUID，时间统一UTC。SQL外键与唯一约束承担数据关系保护。
`runs.input_message_id`固定本回合输入，模型上下文组合已完成的历史回合和本回合消息，排除后续排队输入。
大文件对象、技能修订、扩展授权、调度等表目前已声明，但相应完整仓储和应用流程尚未全部接入，不能据表存在宣称能力完成。

配置只接受完整V2字段集，拒绝直接存入密钥。系统凭据后端与外部主密钥加密文件库均不降级为明文。
所有者令牌保存在当前用户私有控制目录，数据库仅保留其摘要与有效期。恢复后的旧令牌撤销。
当前令牌有效期30天；续期/撤销操作界面尚未实现。默认不向公网开放实例。

诊断日志不保存聊天原文或工具正文。业务执行详情只在业务库保存，日志写失败不得伪装业务成功。
当前日志14天/256MiB上限已实现；完整业务保留策略、临时详细调试、全局异常接入、诊断包仍待实现。
插件尚未迁至新工作器。现有内建能力子进程属于故障隔离，不提供安全沙箱。
