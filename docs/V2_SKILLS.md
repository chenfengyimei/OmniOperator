# V2 文本技能与回合授权

技能保存可复用的流程说明，支持导入、编辑、节段修补、历史、回滚、归档、恢复、参考文件和导出。它不注册代码、不执行包内文件，也不授予工具或免除审批。默认正式入口仍为 V1。

## 存储、修订与审阅

正文和参考文件写入现有内容寻址对象存储，数据库仅保存归属、修订、路径、大小及指纹。没有可同时修改的 `skills/` 文件夹真值；修改原导入文件不会改变已保存版本，重新导入才产生新修订。对象损坏会导致读取或启用失败，不能作为新内容继续执行。

当前结构为 **125 张业务表，`v2_0035`**。复用 `skill_revisions` 保存主文档修订，并新增五表：

| 表 | 职责 |
| --- | --- |
| `skills` | Agent 内名称、当前内容修订、编辑 CAS、授权代次、disabled/enabled/archived 和审阅审计引用 |
| `skill_manifests` | 内容修订所属技能、描述、Windows/macOS/Linux 声明和完整文件清单指纹 |
| `skill_files` | 固定相对路径与对象、大小、指纹；包括 SKILL.md 及只读文本参考文件 |
| `run_skill_catalog` | 本回合捕获的可用目录、确切修订、授权代次及审阅审计 |
| `run_skill_activations` | 本回合实际使用、位置、平台，以及人工选择或模型读取动作的来源 |

Agent、技能、修订、目录、运行及动作通过组合外键限制归属。内容修订、清单、文件、捕获目录和激活记录不可重写或删除。`runs.skill_capture_epoch` 在入队事务中封存一次，空目录也封存，后续不能重新开放或补入新授权。过去 V2 运行保持未登记状态，不补造历史技能使用；V1 数据不导入。

创建、完整导入、改写、节段修补和回滚都生成 **停用的新内容修订**。名称固定，回滚复制历史完整文件集合并增加版本号，不改写历史。新内容需要所有者重新审阅并明确启用；归档保留内容，恢复归档只回到停用状态。

启用必须提交当前编辑修订、内容修订 UUID 和完整清单 SHA，并重新验证所有实际文件对象。启用审计与状态共同提交，当前授权和已捕获目录通过外键保留对应审计依据。普通并发修改采用 CAS，冲突保留客户端草稿。

每 Agent 最多 256 个技能、同时启用 32 个；每技能最多 128 个内容修订。历史和列表均分页读取。

## 输入格式与跨平台边界

支持 UTF-8 `SKILL.md` 或扁平 ZIP：根目录的 `SKILL.md`，以及 `references/` 下的声明文本文件。最大输入 1 MiB，最多 17 个文件，展开总量 512 KiB；主文档最大 128 KiB，参考文件各 64 KiB。不会解包到磁盘目录。

ZIP 拒绝目录记录、链接、设备条目、加密和不支持的压缩类型，拒绝大小不符、CRC 损坏、重复或大小写别名。路径同时排除绝对路径、盘符、反斜线、ADS、越界、Windows 保留名及不规范 Unicode。只允许 Markdown、普通文本、RST、JSON、YAML、TOML、CSV 参考文件；不存在安装脚本和可执行文件入口。

ZIP成员中的损坏DEFLATE数据同样归为`invalid_skill`（422），不向所有者返回原始解压器异常。主文档或参考成员解码失败时关闭当前成员流与归档，不发布技能文件或提交新修订；已显式上传的输入对象保留原存储/GC语义。合法压缩/未压缩成员的原字节、既有CRC检查和文件预算保持，后续显式合法导入可继续完成。

ZIP解析与导出的内存缓冲区由适配器显式关闭，覆盖正常完成、构造/成员读取/编码/归档收尾失败；解析后的元数据或领域校验失败也不保留输入缓冲区。导出在校验通过后才分配输出，归档收尾后取得字节再关闭输出；成员顺序、原文件字节、压缩参数和固定时间/权限元数据保持。取消等待方时底层线程继续持有既有任务归属，实际操作结束并关闭资源后才排空；不把等待取消当作线程停止，也不据此声明进程内存峰值已验证。

主文档 frontmatter 包含 `name`、`description`，可选 `version` 和 `platforms`。名称为 3–40 位小写字母/数字/连字符，描述不超过 120 字符；正文为 50–24000 字符，必须各有一节 `When to Use / Procedure / Pitfalls / Verification`。平台未写时包含三个目标平台，声明不等于原生功能已经验收。节段修补只替换指定标准节，仍重新验证整份文档。

frontmatter 在构建元数据字典前检查合并后的字符串键；重复字段统一以`invalid_skill`拒绝，包括相同值、转义/别名同名键及YAML合并覆盖，不能静默选择后一个值。无冲突的合并、标量别名、流式映射及折叠描述保持支持，原主文档和参考文件字节不改写。创建、编辑和ZIP导入在文件发布/修订提交前完成此检查，失败保留已有技能与修订；标准SafeLoader的全局行为不受影响。

frontmatter 还限制为最多128个逻辑YAML节点：映射键/值、映射和序列容器均计数，别名每次引用都按被引用结构再次计数。检查发生在合并展开和对象构建前，超限或循环引用以`invalid_skill`（422）拒绝，解析器状态仍关闭；精确128节点可接受。4 KiB原文限制、包/文件预算及原始字节保持，普通合并/别名仍须满足此复杂度预算。

解析后的描述、可选版本与正文必须可编码为UTF-8。即使原文是合法UTF-8，YAML转义产生的代理码位仍以`invalid_skill`（422）在文件发布和数据库写入前拒绝，不替换或丢弃字符。中文、实际emoji及合法Unicode标量转义保持，描述/版本/正文仍按原字符数上限计量，原始文件字节不正规化；拒绝输入不生成内容修订，后续显式合法保存仍停用待审阅。

ZIP 导出从已验证的内容修订重新构建，包含原主文档与参考文本；生成临时对象供所有者下载，不执行内容。导入 ZIP 会替换完整文件集合，编辑器保存则保留现有参考文件。历史对象继续受原引用保护与一致备份管理。

## 回合捕获与逐步披露

接收正常所有者聊天时，在消息、模型配置、任务入队的同一事务中捕获最多 32 项已启用技能的确切修订及授权代次。QQ 和独立所有者设备命令不获得该目录。显式选择只接受最多 4 个不重复技能 UUID，并参与请求去重指纹。

聊天可提前选择技能；模型也可以通过 `skills_list` 查看本回合已捕获且适合当前平台的元数据，再以 `skill_activate` 或 `skill_view` 加载确切修订。`skill_view` 读取正文或参考文件时同样登记使用来源，避免已读内容绕过后续撤权。模型历史工具仅返回修订元数据，不直接披露未捕获的历史正文。

模型实际收到的工具文本会区分编辑用 `revision` 与历史内容号 `content_revision`，并返回声明文件清单。查看内容、读取参考文件及写入后的 ID/状态回执均通过模型可见 JSON 文本返回，不能只放在后台动作 data 中；错误也提供明确代码。模型据此申请带正确 CAS 的修改，仍须逐次审批，不能把历史内容号误作编辑修订。

每回合最多使用 4 个技能。已经激活的主文档按实际激活顺序，以独立的流程说明注入模型系统上下文，参与原容量与费用预检；参考文本按需披露。压缩历史不会重置技能使用关系或授权。完整正文超容量时明确失败，不静默截断流程。

聊天档保留轻量工具规则，检索档增加技能只读披露，写操作仍属于完整档及现有人工审批链。模型创建、改写、修补、回滚、归档和恢复使用结构化工具结果，并在最终数据库提交事务内再次核查确切动作、审批、策略和运行。模型没有自行启用技能的接口。

## 撤权、取消与恢复

停用、归档、改写或重新授权都会提升授权代次。已经使用旧授权的回合不能继续模型调用或派发动作，即使后来重新启用也不能恢复旧回合。未使用的目录项失效只移出后续披露，不影响其他无关回合。

尚未派发的相关审批及动作在技能变更事务中取消；已执行或已派发但未知的结果、费用不会被伪造成失败或自动重试。技能停用发生在模型调用中时，保留实际调用账目并阻止旧输出发布。模型修改自己正在使用的技能后，该动作可记录实际写入，新修订停用，后续回合步骤因旧授权失效而停止。

技能服务最多接纳 8 个操作，同时执行 2 个；包解析采用相同有界拥有机制。调用方取消不会中断已经拥有的对象发布与事务流程，关闭先排空服务，再回收解析及对象存储。无活动技能的回合不占解析队列，QQ 不进入技能披露流程。

公开目录、可用列表、修订历史与运行技能报告也占用同一任务队列，关闭或队列已满时于首次数据库读取前以`skills_busy`（503）拒绝。取消查询等待或关闭等待不丢失实际读取，完成交付后才排空；原分页参数/游标、平台与报告内容保持。模型历史查询直接复用已准入的内部历史读取，不重复申请槽位，已准入的模型操作可在关闭期间完成原读取。

技能上下文说明从首次活动目录查询前就登记完整读取任务，共用8项准入和2项执行上限；关闭或队列已满时以`skills_busy`（503）在查询前拒绝。调用方或关闭等待方取消不撤销已准入的目录、修订、对象/解析与最终授权检查，实际读取结束前仍保留数据库、解析器和对象服务。排空期间的后续步骤不再次准入；空目录只查询一次并返回空说明，不调用包解析器。活动顺序、确切修订与返回前撤权检查保持，任务不重放，也不派发额外模型请求。

模型的`skills_list / skill_history / skill_activate / skill_view`也从目录核验到历史/正文读取及实际使用登记持有一个完整任务。关闭或满队列在首次I/O前拒绝，取消请求或关闭等待方只结束等待，实际已准入读取仍排空；使用登记不因等待取消而重放。正文读取复用已验证的内部读取路径，不再次申请服务槽位，两个并发读取可继续完成。捕获修订、文件清单、模型可见正文与最终`skill_activate_run`授权检查保持，写技能的独立审批和提交路径不变。

六种模型写技能工具从准备、旧内容读取到最终提交和回执也持有一个任务，共用原8项准入/2项执行。创建、改写、节段修补、回滚、归档和恢复在关闭/满队列时于首次I/O前拒绝；取消请求或关闭等待不丢失实际已准入工作，不重放写入。公开保存/状态/回滚入口仍独立准入，内部组合不重复排队。最终事务内的`approved_dispatch`、版本冲突和撤权检查保持；已发布对象仍沿原引用与GC规则管理，不能把任务持有视为绕过审批或承诺提交一定成功。新内容/恢复仍停用待审阅，原参考文件和回执保持。

共享关闭协调器也补齐了短预算接续：旧协调器已经结束、但其组件关闭任务尚在结束时，新关闭请求会在剩余预算内接续一次已完成的失败等待，不重复实际仍在进行的关闭，不循环重试当前预算下的新失败，存储继续等待前置组件释放。

一致快照包含所有被引用对象。恢复进入新目录后，原来启用的技能统一停用、提升代次并登记恢复审计，历史修订保留，需要新所有者审阅。旧回合的历史代次和原授权不会被重新认可。

## HTTP 与工作台

所有接口使用 `/api/v1/agents/{agent_id}`、所有者认证和 no-store：

| 路径 | 行为 |
| --- | --- |
| `GET /skills`、`GET /skills/available` | 分页管理列表及当前平台已启用项 |
| `POST /skills` | 创建或保存正文，`content / skill_id / revision`，保存为停用修订 |
| `POST /skills/import` | 从同 Agent 对象导入 `object_id / format / skill_id / revision` |
| `GET /skills/{id}` | 指定 `revision_id` 和声明文件 `path`，重新验证后读取 |
| `GET /skills/{id}/history` | 内容修订元数据，稳定分页 |
| `PUT /skills/{id}/state` | `revision / state / revision_id / manifest_sha256` 精确审阅状态变更 |
| `POST /skills/{id}/rollback` | 将历史修订复制为新的停用修订 |
| `POST /skills/{id}/export` | 验证并导出所选修订 ZIP 对象 |
| `GET /runs/{id}/skills` | 实际捕获、使用、平台与当前授权状态，撤权后仍可查看元数据 |

原回合入口增加可选 `skill_ids`，平台由服务端选择，客户端不能伪造。工作台提供技能管理分区，正文草稿按 Agent 有界保留；导入与启用分别操作，历史回滚保留原版本。聊天可选择本轮技能并查看使用及授权状态。所有正文、描述和参考内容使用文本节点或文本框呈现，不执行 HTML。
