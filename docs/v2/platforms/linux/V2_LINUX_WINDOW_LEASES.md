# Linux 持续窗口身份

X11 发现仍以 XRes 客户端 PID、进程创建身份、logind 会话、服务器连接和当前窗口结构核验所有权。新生产路径在向应用层返回目标前，再由独立的只读守护进程订阅该窗口的 StructureNotify，返回随机 `x11-live:<UUID>`。应用保存这个别名；跨调用的 XID 和相同元数据本身不能证明窗口没有重建。

`domain/linux_window_leases.py` 定义严格的有界私有 IPC，绑定协议、随机请求 ID、操作和完整目标字段。`linux_lease_client.py` 只拥有进程和通信；`workers/linux_window_lease.py` 才打开原生连接。主进程不加载原生 D-Bus 或 X11 API。固定辅助命令继承既有最小环境，不接收实例目录、凭据、数据库或输入许可。

同一条已核验连接持续保留窗口结构通知。销毁、隐藏、映射、重挂载、配置、重力和循环通知递增该 XID 的代次；旧别名永久绑定原代次。用户重新发现可以获得新别名，不能把旧别名重新绑定到复用的编号。读取屏障排空排队通知，目标元数据读取前后再次检查代次。合成、无关、损坏或未支持通知、总线/会话/服务器变化使证明失败，不通过重连恢复旧别名。无效会话由父进程回收。

DesktopBackend 在目标发现的单次辅助进程回收后才绑定窗口。对带别名的核验、观察或截图，先核对持续证明，将原身份交给原单次进程，待它实际回收后再次核对证明和所有者视图。核验回执保留别名；截图仅在后验通过后才交给应用对象发布路径，失败不得发布像素或引用。AT-SPI 目标保留独立身份，不按应用 PID 自动映射到 X11 窗口。

守护进程与原桌面辅助进程共用最多 2 个常驻进程额度；完整逻辑请求仍受最多 4 个待执行任务及原总期限约束。每个守护进程最多 2 组各 50 个窗口、32 条命令、双向合计 1 MiB IPC、1 MiB X11 接收和 120 秒寿命；父进程在新绑定时按命令/60 秒年龄预留回收余量。旧组按顺序失效，只取消没有剩余组引用的订阅。身份过期或守护进程关闭后要求重新发现，不以新进程重建旧证明。

健康空闲的只读订阅不阻止已完成业务动作释放资源租约；启动、活动 RPC 和不确定回收继续占用资源。整体关闭只有实际进程及读管道全部回收后才能成功。取消调用等待保留实际操作；迟到创建和失败回收持有原常驻额度，后续关闭继续回收。原始 stderr 只作有界丢弃，不写入审计。

19 项新增局部回归覆盖窗口复用、真实二进制订阅/屏障、代次读中变化、组淘汰、精确 IPC、实际受管管道、迟到创建、排队超时和超量/坏帧时的回收归属。原桌面/截图/Linux/前台传输/动作/架构调用方另行验证；原截图集成节点已加入实际守护管道和隔离 SQLite 对象发布。以上原生目标均为注入，实际管道在 Windows 执行；没有真实 Linux 桌面、设备或输入结论。见[专项证据](../../../evidence/v2-linux-window-leases.json)。

本批只补持续读取身份。X11 前台输入仍需独立的节点与窗口关联、焦点/物理输入证明、逐次授权及派发后确定性；Wayland RemoteDesktop 需独立系统控制授权。窗口共享和身份别名均不授予控制权。整个 V2 尚未开发完成，未运行本轮全量。

协议依据：[X11 Protocol](https://xorg.freedesktop.org/archive/X11R7.7/doc/xproto/x11protocol.html) 的 ChangeWindowAttributes、StructureNotify 和 GetInputFocus；实际平台通知与窗口管理器差异留 Linux 正式验收。
