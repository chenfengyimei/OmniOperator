## 已确认的问题

受管 I/O 已能记录未知凭据变更，但审计计数不是完整的权限业务模型。当前引用状态还没有明确阻断未知结果之后的模型/投递使用及再次修改，所有者也没有绑定版本的核查入口。需要独立业务真值，不能靠重写历史审计结论解除阻断。

## 业务真值与实体

在同一个 omni.db 新增三个全局所有者领域实体（不归任意 Agent）：

- credential_references：完整 UUID、所有者、引用名（可空历史占位）、唯一 SHA-256 引用指纹、ready/changing/unknown/revoked、revision、authority_epoch、current_operation_id。
- credential_operations：完整 UUID、引用及所有者组合外键、set/delete/legacy、prepared/running/applied/not_applied/unknown、启动身份、执行令牌、原状态、结果时间及错误码。当前操作通过组合外键绑定所属引用。
- credential_reviews：完整 UUID、引用/操作（可空）、所有者、被核查的 revision/epoch/指纹、allow_current/revoke、证据及策略版本。核查不修改历史操作的 unknown。

实例审计仍用于解释发生了什么，与业务状态在同一短事务提交；补注册、核查及恢复事件。审计扩展载荷继续 schema=1，引用信息不包含密钥值。列表按完整 UUID/稳定序号分页，限制上限。

## 引用语义

引用名按域内规则区分大小写。统一的 reference_fingerprint 同时供数据库、FileVault 与原生系统后端使用；原生后端使用小写十六进制指纹作为用户名，避免 Windows 凭据目标的大小写行为造成跨平台别名碰撞。没有旧系统凭据的自动导入或回退，旧内容不删除。

所有者显式选择新的配置引用时可登记 ready，表示允许尝试使用当前引用，不表示系统存储、实际密钥或供应商账号已经验证。缺失实际密钥仍在发送前失败。已存在 unknown/revoked/changing 引用不能通过重新保存配置重置授权；历史占位只能绑定相同指纹的引用名。

## 修改与副作用

1. 取得有界的受管修改任务及串行锁；失效同引用的在途读取。
2. 同一事务登记操作 prepared、引用 changing、审计意图，并调用现有共同撤权方法，撤销模型旧权限及待投递授权。事务返回需要中止的实际投递 ID，组装注入的窄回调负责取消。
3. 在调用后端前短事务改为 running，核验启动身份、执行令牌、引用版本与当前操作。
4. 外部 I/O 不在数据库事务内等待。只有明确未派发才 not_applied，其他异常按 unknown；成功 set 为 ready，成功 delete 为 revoked。
5. 结果、引用状态及审计共同提交。结算失败不得宣称成功。取消 HTTP 等待不取消已接受的实际修改，真实工作、引用 changing 与实例锁持续归属，不能以 TTL 接管。

unknown 必须先核查，不能自动重做或通过新引用的同一指纹绕过。模型发送前及投递审批、领取、动作前共用引用权限判定；changing/unknown/revoked 都阻止使用。预发送拒绝不能保留未知费用，已经派发的费用仍保持原结算规则。

## 核查与恢复

只接受所有者显式核查，绑定引用 UUID、revision、authority_epoch、当前操作与策略指纹。活跃操作禁止核查；过期页面、晚到结果或恢复后的旧核查必须冲突。allow_current 仅允许未来使用，revoke 仅撤销未来使用，不重写历史 unknown，也不改费用账本。

正常重启中，prepared 为确定未调用；running 变 unknown；均不重放。只处理上一启动的未完成操作，不能把新进程当前工作回收。引用与操作在事务内恢复，旧模型/投递权限继续撤销。

备份恢复到新目录后，凭据并未随业务快照恢复。所有引用增加 authority_epoch 和 revision 并置 unknown，已有核查保留为历史，未来操作需要重新核查；不能沿用备份中的 ready/核查作为当前系统存储的证明。恢复与标记发布沿用现有完整性和中断规则。

v10 只演进 V2 开发库，不迁入 V1。旧 v9 的哈希审计或配置引用可作为隔离来源登记 unknown；不能证明的名称可留空，需要所有者绑定后核查。保留原审计，不读取真实系统凭据来猜测来源。Alembic SQL 固定，升级前一致快照。

## 接线与验证

事务仓储放入 credential_repository；配置仓储与操作仓储复用同一权限判定，保留中央连接生命周期。应用服务负责受管任务、串行修改及核查，适配器只执行真实凭据 I/O。HTTP/工作台提供有界引用列表、状态、操作记录和核查表单，不返回密钥。

必须覆盖：未知后模型/投递/再次修改阻断；配置保存不能解除；活跃核查拒绝；晚到与并发核查、重复结算；正常重启及恢复代次；真实 Future 取消/关闭；未发送费用；全局所有者与 Agent 隔离；无秘密日志；原生引用大小写一致。全部使用隔离假后端，不触碰真实账号。

## 系统凭据的受管进程边界（R5.native_credentials）

默认系统存储由`NativeCredentials → 固定omni.adapters.workers.credentials → SystemSecrets`实现；Windows使用WinVault、macOS使用Keychain、Linux使用Secret Service。核心构造、doctor和普通启动不探测或解锁原生存储；外部主密钥的FileVault及显式注入假后端继续用原有有界线程I/O，不转为原生钥匙串，也不自动回退到明文后端。

每个实例最多16项实际在途凭据任务、1个实际helper，串行顺序包含取消等待的任务。凭据IPC1只接受固定命名空间、引用和get/set/delete，不接受后端类、模块、命令、脚本或凭据文件路径。最多262144个有效Unicode字符，4MiB帧预算覆盖最坏JSON转义；重复字段、非有限数、跨请求/操作回复或多帧结果拒绝。ready/permit初始帧与放行合计仍受限，原生后端只在permit之后构造和调用。

宿主在真正派发前检查排空与读取失效，permit前失败明确not_applied；permit可能送达后的写入超时、原生异常、丢回复和无法回收均unknown，不重试。单项30秒预算包含启动和原生调用，队列等待在有界容量内另行计数；spawn、读管道和清理任务持续归属，不能以取消调用者释放容量。回收失败阻止新helper，关闭继续持有数据库与实例锁并可重试。凭据核查不仅检查持久状态，也要求实际I/O和原生进程均已结束。

固定worker使用当前Python隔离模式与模块路径，敏感值只走私有stdin/stdout管道，不进argv、环境或文件。系统后端始终显式选择，不读取配置的第三方keyring类；不继承KEYRING_PROPERTY/PYTHON_KEYRING_BACKEND等覆盖。Linux只设置当前UID的`/run/user/<uid>/bus`，不采纳任意继承总线地址。旧式自定义总线布局暂不可用；无桌面部署应显式配置外置主密钥的FileVault，不以无法访问Secret Service推断密钥不存在。

原生库stdout在专用helper中丢弃，独立私有描述符只写版本化协议；主进程和CLI不重定向stdout。原生stderr始终排空丢弃，最多64KiB后终止本次调用，不把异常文本或局部变量放进日志。宿主只输出固定`credential.native.unconfirmed`和错误码，沿用请求/操作上下文；set值在派发前、get值在返回前登记脱敏。业务凭据引用、操作、审计和核查仍在既有omni.db中，95表/v2_0025不变。

当前离线验证只使用注入存储和受控管道；真实Windows进程用错误permit退出，未访问OS存储。三平台真实解锁、拒绝、锁定、登录切换、系统服务及权限行为仍待实测，不能据此宣称三平台凭据已支持。
