# V2 Owner 令牌管理（D7 节点）

> 令牌只用于本机所有者 API 鉴权；**不表示 V2 已验收或已切换正式入口**。

## 1. 能力

- `GET /api/v1/owner-token/sessions`：最多 50 条会话，字段仅 `created_at`、`expires_at`、`revoked_at`、`current`；不返回 token 或哈希。
- `POST /api/v1/owner-token/rotate`：轮换并**只返回一次**新 token 与过期时间；旧 token 立即失效。
- CLI：`auth` 打印当前令牌；`auth --rotate [--url]` 通过运行中的实例轮换并打印新令牌。

## 2. 轮换顺序（崩溃安全）

1. 数据库登记新会话（旧会话仍有效）；
2. 原子发布 `run/owner.token`：同目录暂存、0600、fsync、`os.replace`、拒绝符号链接；
3. 撤销其余未撤销会话；
4. 注册新令牌到日志脱敏器。

崩溃窗口最多留下“多一个有效会话”，但**不会**发布数据库不认的令牌；重启后文件中的新令牌仍有效，旧令牌不复活。并发轮换由进程内锁串行化。

## 3. 边界

- 会话清单不暴露哈希、创建者或来源地址；令牌不写日志、不进诊断包、不进交接记录。
- 轮换必须有当前有效令牌；没有“重置为空”的接口，避免服务被锁死。
- 令牌有效期 30 天，与启动引导一致；数据库恢复回旧快照时，需重新轮换并同步 `owner.token`。
- 工作台“令牌”页：列出当前/历史会话与创建/过期/撤销时间；轮换需二次确认，新令牌只显示一次并可手动隐藏，成功后立即把内存 token 与连接输入更新为新值、后续请求不中断；页面不持久化令牌，刷新后需用新令牌重新连接。资源版本 v53。

## 4. 验证

- 会话清单：未授权 401、仅 4 个字段、哈希与 token 不出现在响应。
- 轮换：旧 401 / 新 200、文件内容等于新 token、旧会话 `revoked_at` 非空、二次轮换再失效、重启后新令牌有效且旧令牌不复活。
- CLI：`auth --rotate --url` 打印新令牌并更新控制文件。
- 证据：`docs/evidence/v2-owner-token.json`。
