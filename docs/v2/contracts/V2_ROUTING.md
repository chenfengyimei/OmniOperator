# V2 档位、模型选择与调用证据

> 文档范围：本页维护该能力合同与所属批次记录。当前默认入口为 V2；[当前交接](../../HANDOFF.md)区分已实现、专项通过和原生验收，历史测试数字不覆盖当前源码。

## 回合入口与配置

工作台聊天入口支持“跟随设置、自动、聊天、检索、完整”五种选择。省略 `mode` 表示跟随该 Agent 的档位策略；初始虚拟策略为修订 0、默认自动、允许一次升档。自动判定仅检查本次输入的确定规则，不调用分类模型：图片进入完整档，明确寒暄进入聊天档，明确查询前缀且不含已知写入表达进入检索档，其余保守使用完整档。这不是语义分类准确率承诺。

每档可选择模型配置及单次费用预留；留空则继承 Agent 默认模型与预留。保存采用 revision CAS，并检查同 Agent、模型类型、启用状态。普通修改只影响新运行；实际模型停用、凭据变化和工具权限撤销仍由原有执行前检查阻止。没有自动切换备用模型、自动付费路由或失败后换模型重试。

入站去重、消息、运行、所选模型修订、模型权限代次、策略引用、预留金额及排队工作项在一个事务中捕获。相同请求 key 改变明确档位会冲突；原请求重放不会重新路由。图片准入检查实际所选模型修订及图像策略，不以 Agent 默认模型代替。

QQ 继续使用受限通道上下文：固定聊天档、禁止升档，不获得所有者工具和私人记忆。显式所有者桌面/设备命令绕过模型路由，仍使用原审批链。

## 工具与升档

聊天档仅允许注册表中已知的只读 `memory_search`；检索档再允许文档、文件、浏览器、B站和系统只读工具；完整档使用本场景原本可用且未禁用的工具。未知扩展工具不凭名称被加入轻档，`writes` 工具也不能混入。具体集合以 `domain/routing.py` 为唯一实现。

当轻档确实省略工具且策略允许时，模型会获得 `request_mode` 控制工具。一次运行最多升档一次，只允许向上，必须有实际模型调用工具快照证明此前提供过该控制工具。控制参数只包含目标档位，不保存模型自由填写的原因。

升档仅改变下一次调用的工具集合。本轮捕获的模型、费用预留、步骤及图片预算保持不变；摘要、流式输出和后续工具调用继续使用该模型。与升档请求出现在同一次模型响应中的越档工具会被拒绝。下一次调用可以请求写工具，但仍须正常建立动作意图、人工审批并在派发前核验权限，升档不能批准动作。

## 数据与查询

本批新增 5 张表，该批基线为 **116 张业务表，`v2_0033`**；当前结构见[记忆语义合同](V2_MEMORY_SEMANTICS.md)：

| 表 | 职责 |
| --- | --- |
| `model_route_policies` | Agent 策略修订、各档模型配置引用和可继承预留 |
| `run_routes` | 初始档位、选择来源、规则代码、捕获策略与预留 |
| `route_changes` | 唯一升档、前后档位及实际提供控制工具的来源快照 |
| `model_call_routes` | 主调用唯一快照、运行内顺序、工具数量、规格字节数及指纹 |
| `model_call_route_tools` | 实际准备的工具名称、位置及单项规格指纹 |

组合外键和触发器约束 Agent、运行、模型、策略和调用范围；修订、初始选择、升档及工具快照均不可改写或删除。升档要求运行中、未使用升档及有效来源调用。旧 V2 运行升级只登记原捕获模型的完整档基线，不伪造历史工具快照、节省或升档授权；旧 V1 数据不导入。升级按既有实例锁和验证备份流程执行。

费用真值仍为 `model_calls` 和预算账本，路由没有另建费用表。主调用快照在实际 token 预检阶段与计量元数据共同提交；预算不足、预检故障或历史调用可能没有快照，报告明确给出缺失数量。快照表示准备的工具清单，不能单独证明请求已发送。`not_sent / settled / unknown` 由原调用记录解释，未知费用不会计为零或释放预留。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/agents/{agent_id}/routing` | 当前策略，未保存时为虚拟修订 0 |
| `PUT /api/v1/agents/{agent_id}/routing` | `{revision, value}` 完整策略 CAS 保存 |
| `POST /api/v1/agents/{agent_id}/turns` | 原请求增加可选 `mode: auto/chat/retrieval/agent` |
| `GET /api/v1/agents/{agent_id}/runs/{run_id}/routing` | 捕获模型、当前档位、最多 64 个顺序快照及原费用记录摘要 |

接口采用所有者认证、Agent 作用域和 `no-store`。策略修订已持久化，本批没有新增历史修订编辑入口。查询不返回聊天正文、模型理由、完整工具参数或结果。

## 工作台及观察口径

设置分区提供独立档位表单，草稿按 Agent 保存在有界内存中，切换分区仍保留，保存冲突不覆盖草稿。聊天结果显示实际模型/配置修订、档位、选择来源、预留及逐次工具清单、调用状态、输入估算和已知/未知费用；所有内容以文本节点渲染。

工具规格字节差是与同场景完整工具清单的 UTF-8 规格比较，不是 token、费用或质量收益。增加控制工具可能导致负值。路由模型调用数为零；摘要调用费用计入原账本，但不伪装成主回合工具快照。真实成本收益需要固定模型、输入、质量标准及供应商用量单独验收。

审计和运行事件仅记录选择/升档元数据，不新增聊天正文日志、秘密或第二份运行状态。取消、授权变化、压缩、图片累计预算、未知动作及费用继续走公共应用服务。
