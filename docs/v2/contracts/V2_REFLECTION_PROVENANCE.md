## 信笺与证据

1. 信笺保存 encounter、facts、author_view、inference、previous_judgment、revision、missing、next_response 八个文本栏。revision 在正文中指观点的修正，账本另存单调递增的记录版本。encounter、missing 必填，每栏最多 12000 个 Unicode 码点。模型判断和作者观点保留各自栏目。
2. 可进入反思队列的信笺有 1–20 个锚点。每个锚点归属于当前 agent 和已授权读取的证据，记录读动作、来源身份、固定修订或产物、片段定位、内容指纹及支撑的陈述。文档定位使用已捕获的半开字符区间；媒体定位使用绑定 source 的实际转录段或帧及其时间位置。时间须在可验证的时长内。定位、指纹或读取归属无法复核时拒绝入队；单有链接、模型自报时间或另一 agent 的同内容哈希不能建立来源。
3. 来源内容、字幕、弹幕、OCR 和模型推断始终作为不可信数据呈现。保留可验证的证据种类、时间覆盖及缺失信息；未知覆盖标成未知，不把单帧当作全片观测。来源日取服务端首次保存信笺的上海日期，跨日评审、修订和重试沿用原值。
4. 同一事务验证活源，按 agent、八栏正文及规范化锚点集合精确去重，检查来源日最多两封新信笺，写信笺、反向来源索引及唯一待审项。相同请求重试返回原结果；竞争写入不能多扣配额或留下孤儿。草稿只供本地审阅。

## 候选和所有者决定

| 转移 | 前提及原子结果 |
|---|---|
| 待审 → 已读 | 当前授权上下文只接收内部信笺 ID，一次显式读取限定在同 agent 的活跃版本。记录读取者、版本及指纹，正文走不可信数据通道。无当前上下文则保留待审，不唤醒空闲会话。 |
| 已读 → 待所有者决定 / 跳过 | 只从同版 revision 或 next_response 选一段连续原文，保存栏目、半开起止位置、原句及信笺版本。按 Unicode 码点逐字比对，长度 1–240；空白句、改写、越界、未读或版本漂移均拒绝。跳过只记录原因，不消耗正式配额。 |
| 待决定 → 已批准 / 已拒绝 | 所有者显式决定绑定候选 ID、预期版本及原句指纹。批准事务重读所有锚点、信笺和摘录，校验未撤回、同 agent 正式句去重、每实际批准日一条且每来源日一条；写正式版本、决策及两项占用，任一失败整体回滚。拒绝不产生条目。同决定重放返回既有结果，冲突决定拒绝。 |
| 已批准 → 撤回 | 所有者按预期版本撤回，记录阻断重选的来源日标记；保留当日已用配额。修订正式句须新候选重新核源、重新审核，显式替换同一正式条目的版本；替换沿用原双日占用，不增加第二条。 |

## 失效、擦除与重建

按 agent 从每个源反查全部依赖信笺、候选和正式版本。任一锚点失效即阻断整条信笺的读取、选择、批准及导出；不能用另一条同名、同哈希或更新的源自动替换。信笺编辑令旧候选失效，旧正式版本停止可见，替换须明确引用旧条目。批准与修改、擦除竞争时以同库事务排序，读和导出还要复核屏障；擦除先赢则批准失败，批准先赢则后续屏障立即遮蔽派生产物。

擦源完成前清除含引文的信笺、候选、历史版本、快照及受管导出副本。崩溃后维持屏障并续做清理，遗留文件清除前不得报告擦除完成。最小审计残留限内部标识、决定、日期、版本和失效原因，不保留正文或可重建引文的内容。重建只从仍有效且已批准的账本生成；撤回后重启或再评审不得复活原句。

首批只持久化来源关系和草稿。人格文件、inbox/月卷如另批启用，仅作派生视图，需单独约定读取入口、受管目录、防链接替换、大小上限、哈希核验及原子重建。此处不向系统前缀注入内容。跨会话 shadow、观影后提问与外联各自独立；缓存键和父会话前缀不证明来源或授权，普通反思不依赖 K01 D3 或 cache-parity fork。

## 实现顺序与离线验收

| 独立批次 | 放行用例 |
|---|---|
| 1. 锚点、信笺和队列同库持久化 | 隔离临时库从旧版本升级；同 agent 已读范围往返、跨 agent/伪造/已删/越界拒绝、20/21 锚点、同日第 2/3 封、重复提交、并发及事务回滚；已有文档/媒体删除入口同步接入屏障。 |
| 2. 摘录与所有者决定 | 脚本模型只见 ID 通知；未读、239/240/241 码点、重复句、跳过、拒绝、跨日双配额竞争、旧版本批准、修订替换和重复决定。模型自身无法批准。 |
| 3. 端到端失效与恢复 | 通过生产组装入口与隔离注入验证多源共享、删一源失效全部依赖、批准与擦除两种顺序、撤回禁止重选、重启续清及零正文泄露。若引入导出，同时验证损坏/链接目标拒绝及撤回后重建。 |

domain 负责校验和转移；application 负责授权、端口与用例；adapters/persistence 在同一 omni.db 事务内核源、限额和写账；composition 仅接 V2 四层，需要脱敏时注入 adapters.diagnostics.Redactor 实例。每批覆盖调用方及架构守卫，新增用例摘实现验红再还原核对指纹，执行 strict 和 ruff。真实视频、模型选择和人格质量留给独立隔离验收。

批次 1–3 的离线用例已由 v0051/v0052 与本批证据覆盖：升级/回滚、已读范围与拒绝矩阵、双配额与竞争、精确摘录边界、修订替换、撤回重选阻断、生产入口提交/批准/撤回、多源删一、中断擦除重启续清与重启不复活。导出未启用，故导出损坏/链接目标拒绝与撤回后重建未验；人格成长文件仍未启用。
