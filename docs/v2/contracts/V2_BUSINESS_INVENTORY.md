# V2 业务清单（D7）

> 本清单描述 **Windows V2 离线候选**的业务面；**默认入口为 V2**，真实平台和整个V2仍未验收。状态只表示离线源码与专项验证，不把“已实现”写成“已验收”。

## 1. 口径

- **可用（离线）**：源码与专项测试已验证；真实供应商/账号/设备/平台仍需验收。
- **需配置**：功能存在，但依赖真实凭据、账号、服务或设备才能实际运行。
- 所有页面均属 V2 工作台；可通过 `omni-web`、`omni-v2 --home <目录> serve` 或 `python -m omni` 使用；显式 `omni-v1` / `omni-web-v1` 保留旧入口。
- 每个页面都必须出现在本清单与工作台导航中；`agent/tests/test_v2_business_inventory.py` 做双向一致性守卫。

## 2. 导航分组

工作台 23 个入口按业务域收敛为 7 组（仅分组，不改变页面 id、能力或既有测试选择器）：

- **对话与记忆**：对话、记忆。
- **知识与技能**：技能、来源文档。
- **工具与扩展**：可信插件、MCP、动作核查。
- **设备与平台**：QQ 通道、B站、安卓设备、桌面能力、所有者终端。
- **资料与媒体**：人物与档案、文件、媒体。
- **自动化**：持久调度、持久投递。
- **系统与运维**：模型接入、设置、能力、令牌、诊断日志、审计记录。

## 3. 实例级接口（非页面）

Agent空间侧栏现提供“新建空间”“重命名空间”：创建独立默认配置、按修订号重命名并保留冲突草稿，不复制当前空间私人数据；相关所有者API见[空间合同](V2_AGENTS.md)。实例只读长跑工具独立使用[V2监测器](../operations/V2_SOAK.md)，短跑和注入材料不能替代实际72小时。

| 接口/命令 | 用途 | 状态 |
| --- | --- | --- |
| `GET /api/v1/health/live`、`/health/ready`、`/health/identity` | 存活/就绪/身份证明 | 可用（离线） |
| `GET /api/v1/version` | 版本、构建、schema | 可用（离线） |
| `GET /api/v1/capabilities` | 只读能力报告 | 可用（离线） |
| `GET /api/v1/owner-token/sessions`、`POST /api/v1/owner-token/rotate` | 令牌会话与轮换 | 可用（离线） |
| `omni.composition.cli auth [--rotate]` | 打印/轮换 owner 令牌 | 可用（离线） |
| `omni.composition.cli backup|recover|objects` 等离线维护命令 | 快照、恢复、对象维护 | 可用（离线，需一致快照含 WAL） |
| `/oauth/callback` | MCP OAuth 回环回调 | 可用（离线） | 真实供应商未验收 |

## 4. 明确未实现/未验收

- Windows离线候选默认入口为V2，V1仍以显式命令兼容保留；真实平台验收和旧业务数据迁移不随入口切换自动完成。
- 真实模型供应商、真实 QQ/B站账号、真实 MCP 服务与 OAuth 供应商、真实第三方插件、真实安卓设备、三平台原生桌面/终端。
- Windows候选独立安装、同schema更新/回滚及快照恢复已有离线证据；其他平台、容器与真实系统服务仍待验收。
- 全仓严格类型（pyright 尚未全仓 strict）。
- 负载与各平台 72 小时稳定性。

## 5. 维护规则

- 新增/删除工作台页面时，同时更新本表与 `web/ui/v2/index.html` 导航；守卫测试会失败直到双向一致。
- 状态变化只写实际验证到的范围；真实环境未做的不要写“已验收”。
- 证据与合同见 `docs/history/v2/V2_AI_HANDOFF.md` §8/§12 及各能力合同（`V2_EXTENSIONS.md`、`V2_MCP.md`、`V2_MEDIA.md`、`V2_SKILLS.md`、`V2_DESKTOP.md`、`V2_TERMINALS.md`、`V2_CAPABILITIES.md`、`V2_OWNER_TOKENS.md`）。
