# V2 记忆向量、混合召回与相关事实核查

本批接入事实、人物档案与常驻记忆的本地向量索引和模型召回，并提供所有者可确认、拒绝、撤销的相关事实候选。默认正式入口仍为 V1；真实预训练质量与三平台运行需要单独验收。

## 数据与来源合同

记忆正文仍只在原来的 `memory_entries / memory_revisions` 中维护，来源仍由 `source_anchors` 管理。向量、候选和工作台都不另存正文真值。人物档案与常驻记忆复用同一修订、证据及删除路径。

`v2_0034` 新增四表，当前共 **120 张业务表**：

| 表 | 职责 |
| --- | --- |
| `memory_embeddings` | 绑定记忆及修订、原文和完整来源指纹、模型版本/维度、启动所有者；记录 building/ready/failed/invalidated 及可清空的派生向量 |
| `memory_semantic_batches` | 不可变请求 key/指纹、策略、恢复代次、模型身份、来源和候选数量 |
| `memory_semantic_sources` | 规范化来源 ID/修订、人物/会话作用域、原文和证据指纹，不复制正文 |
| `memory_semantic_links` | 同批两条来源的相似度、不可变指纹、pending/accepted/rejected/revoked/invalidated、CAS revision 和首次决定/撤销审计引用 |

组合外键防止串入其他 Agent、记忆修订或批次，整数、状态、向量维度/归一化和关系作用域有数据库约束。清单不可改写；向量身份固定，仅允许完成、失败或失效，决定只允许明确的单向状态转换。首次核查与撤销的审计分别保留。

记忆正文、修订、种类、归属、删除、人物删除或来源锚点变化时，数据库立即使相关索引失效并清空向量，相关 pending/accepted 关系也失效。发布前再次核验实际修订和证据指纹，避免在途计算重建旧内容。恢复变更历史代次时统一失效派生向量和相关候选；新 home 需要重建索引并重新核查，原文及费用账不因此改变。

## 本地索引与生命周期

模型安装沿用 [本地 ONNX 合同](V2_LOCAL_VECTORS.md)。文档和记忆共用 `application/local_vectors.py` 的状态、身份、超时与有限向量校验，实际推理仍在原受管 CPU 子进程。没有远程嵌入调用、自动下载或新增计费路径。

索引由所有者显式逐页建立：每页最多 32 条，正文合计最多 256 KiB，按 UUID 游标继续；每批最多 8 条进入实际向量计算。只索引有效事实、档案、常驻记忆，已批准的精确重复抑制仍生效。相同修订/模型的就绪结果复用，并发请求不会同时拥有同一计算。building 不冒充 ready，失败可重新申请新尝试。

主进程最多接纳 8 个记忆语义操作，最多同时执行 2 个。HTTP 调用方取消后，实际操作仍由服务拥有，不能提前释放队列或关闭共享向量进程。关闭先停止接收并等待现有工作，再由既有向量生命周期拥有者回收进程。重启将旧 boot 未完成索引结算为失败，不重放外部动作；这是可重建派生工作，不会释放或重算模型费用。

## 混合召回与模型接线

全文和向量结果使用同一记忆 ID 合并、稳定排序，每次最多返回 20 条。全文包含事实、人物档案与常驻记忆；向量只比较当前模型版本和维度、当前有效修订。向量候选最多扫描 512 条，超过时显式报告截断，不宣称完成了全库近邻搜索。

未安装、模型未配置、运行失败或索引缺失/过期时，返回全文结果和明确降级原因。返回体说明 `mode`、`degraded_reason`、`vector_candidates_limited`，每项给出 `matched_by`、修订和来源状态。有来源锚点不等于事实正确性证明，历史无锚点内容标记 `unverified`。

模型的 `memory_search` 已通过此应用服务，命中在同一最终验证事务内登记为该运行的上下文依赖。来源在查询期间变化时，拒绝发布旧内容；后续遗忘或源删除继续使已捕获上下文失效。QQ 仍没有这些工具与所有者上下文。业务结果不进入诊断日志。

## 相关事实候选

沿用现有事实勾选，所有者固定 2–32 条事实修订，必须先有相同模型版本的有效向量。只比较人物和会话作用域完全相同、原文不同的事实；原文完全相同的情况仍交给现有精确重复整理。局部余弦相似度达到 0.85 后，最多生成分数最高的 31 项候选，不调用分类或生成模型。

候选表示“可能相关”，不证明两句话同义，也不证明事实正确。确认后只保存 related 关系，两个原文、所有来源和各自召回保持独立；不合并、不删除、不抑制、不改写人物档案。所有者可以拒绝，或在确认后撤销。确认和撤销均绑定候选 revision、指纹、历史代次，并重新核查模型版本和全部来源。

模型变化、恢复或来源失效后，旧详情不返回正文，也不能继续批准。已失效候选不因内容后来相同而恢复。请求 key 重放只返回原批次；同 key 更换来源修订会冲突，模型更新不会偷偷生成另一批。

本批没有实现生成模型自动综合事实、跨作用域聚类、自动压缩档案或自动遗忘。这些不由相似度替代，完整 D6 仍未完成。

## HTTP 与工作台

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/agents/{agent_id}/memory/index?after=&limit=32` | 建立一页索引，返回明确状态及后续游标 |
| `GET /api/v1/agents/{agent_id}/memory?q=...` | 混合召回，保留 items 并补充降级及来源信息 |
| `GET /api/v1/agents/{agent_id}/memory/semantics?after=&limit=20` | 分页查看语义批次及本地向量状态 |
| `POST /api/v1/agents/{agent_id}/memory/semantics` | `{key, sources:[{memory_id,revision}]}` 固定输入并生成候选 |
| `GET /api/v1/agents/{agent_id}/memory/semantics/{batch_id}` | 重新核验的来源及候选状态 |
| `POST /api/v1/agents/{agent_id}/memory/semantic-links/{link_id}/decision` | `{revision,fingerprint,epoch,decision:apply/reject/undo}` |

接口采用所有者认证、Agent 作用域及 no-store。工作台记忆分区提供索引分页、全文/向量命中及降级状态、相关候选确认/拒绝/撤销。查询草稿按 Agent 有界保留，正文通过文本节点渲染。没有自动轮询；显式刷新重新核验。`doctor` 增加未完成索引和待核查语义关系计数。
