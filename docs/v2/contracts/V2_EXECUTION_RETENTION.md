# V2 执行正文保留与恢复

> 文档范围：本页维护该能力合同与所属批次记录。当前默认入口为 V2；[当前交接](../../HANDOFF.md)区分已实现、专项通过和原生验收，历史测试数字不覆盖当前源码。

本合同管理两项独立维护：至少 30 天前结束的运行的正文裁剪，以及已裁剪动作的产物引用释放。聊天、记忆、持久摘要、文档、审批、费用、调度、投递和原审计保持各自的业务职责。引用释放不删除对象元数据或文件；物理回收继续使用独立对象 GC。诊断文件轮转和用户遗忘均不执行此流程。

## 离线操作

以下命令均取得实例独占锁，活动实例会返回 `instance_busy`；命令不会停止服务、调用模型或执行设备动作。必须先完成正常排空与关闭。维护只接受当前安装包对应的数据库结构，不隐式升级。

```text
python -m omni.composition.cli --home <V2实例绝对路径> retention-preview --limit 20
python -m omni.composition.cli --home <V2实例绝对路径> retention-plan <实例外的新计划文件> --limit 20
python -m omni.composition.cli --home <V2实例绝对路径> retention-apply <已审核计划文件> --backup <实例外的新备份目录>
python -m omni.composition.cli --home <V2实例绝对路径> retention-cancel <原计划文件> --reason "保留剩余证据，重新审核"
python -m omni.composition.cli --home <V2实例绝对路径> doctor
python -m omni.composition.cli restore <原备份目录> <新的V2实例目录>
```

预览 `can_apply=false`，不是执行计划。计划只含实例/结构/策略版本、完整 UUID、固定版本、截止时间和正文指纹，每页最多 50 个运行；不会导出聊天或工具正文。预览的 `next_after` 用于继续分页；计划仅选择当前页中符合条件的运行。输出文件不可覆盖，执行时不接受修改后的已登记计划。

执行之前逐项重新核对计划，在实例外生成 SQLite 一致快照及全部登记文件对象，验证完整性、外键、逐文件大小/指纹和精确对象清单。数据库中的批次绑定原计划指纹、备份绝对位置和备份清单指纹。恢复不包含凭据，继续服从现有费用、动作、投递及授权隔离规则。

## 保护与一致性

裁剪事务重新核查：终态及 30 天期限、人工固定、未决审批、未完成或未知动作、副作用、费用、工作项、投递、运行资源、记忆来源、文档上下文、固定产物，以及其他未完成批次占用。来源、费用和对象固定可以在正文指纹不变时发生，因此不能只比较指纹放行。

`retention_batches` 保存不可变计划/备份身份与 `prepared → complete/cancelled` 状态；`retention_targets` 以组合外键隔离 Agent，部分唯一索引保证一个运行只有一个待裁剪目标。每个运行以单独短事务修改动作/事件正文、原始指纹、运行标记、目标进度及审计。等待备份和文件 I/O 不进入业务事务。

动作保留身份、工具、参数原指纹、状态、副作用、策略版本、原结果指纹及结构化错误码；结果以 `body_pruned` 标记替换正文。事件保留原序号、类型、时间、关联身份与状态/错误码，并保存原载荷指纹。运行保留终态、错误与截止时间，记录 `body_pruned_at/body_pruned_plan_id/body_sha256`。接口与工作台明确显示已裁剪，不能通过固定按钮假装恢复正文。

正文裁剪保留全部对象引用；其后是否释放引用必须单独审核，不能由正文标记自动决定。正文裁剪不承诺 SQLite 文件立即缩小或物理擦除。备份包含裁剪前原文，须按独立备份保留策略管理。

## 已裁剪动作的产物引用释放（R3.retention_references）

当前基线为 71 张声明表、Alembic `v2_0013`。引用维护仍要求停机、实例独占锁和当前安装包对应的结构；与正文维护共用 `plan/apply/cancel` 生命周期，但使用独立计划、批次、备份和审计。

```text
python -m omni.composition.cli --home <V2实例绝对路径> retention-refs-preview --limit 20
python -m omni.composition.cli --home <V2实例绝对路径> retention-refs-plan <实例外的新引用计划文件> --limit 20
python -m omni.composition.cli --home <V2实例绝对路径> retention-refs-apply <已审核引用计划文件> --backup <实例外的新引用备份目录>
python -m omni.composition.cli --home <V2实例绝对路径> retention-refs-cancel <原引用计划文件> --reason "保留剩余产物引用，重新审核"
```

预览按完整引用 UUID 分页，`next_after` 可传给 `--after`；每页最多 50 条引用，同一对象可以出现多条不同动作引用。计划固定实例、结构、策略、Agent、运行、动作、引用和对象身份，以及对象 revision、`object_sha256/object_bytes`、原裁剪计划与复合指纹。预览不含执行正文，维持 `can_apply=false`；审核对象指纹和大小不代表已经授权 GC。

只有运行与动作的裁剪标记一致、原正文目标已提交且其裁剪批次已完成，引用才进入候选。执行前、备份后及每条尚未释放的引用提交前，都重新核对精确身份、指纹、对象版本与固定状态，并沿用正文维护的业务保护：新增来源、文档上下文、未决审批、未知副作用、未结费用、未完成工作/投递和持有资源均可使原计划失效。未知投递即使已有人工核查，也不会按普通保留期释放。不能只因正文未变化而忽略新增保护。

当前只接受 `complete` 的原正文批次。原批次若部分裁剪后取消，已裁剪部分的引用仍保守保留，显示 `pruning_batch_incomplete`；取消不把它们移入新正文批次，也不自动授权引用释放。这一范围尚需后续独立设计与验收。

每个目标在一个短事务中删除精确的 `action_objects` 行、记录 `released` 进度并写审计；任一步失败共同回滚。其他动作、消息、文档、记忆和技能等真实对象外键保持原状，共享对象的其他引用不会被解除。已裁剪动作禁止通过仓储或 SQL 重新添加或更换产物引用。`reference_release_targets` 保留对象身份、版本、大小与指纹供核查，但不建立到 `objects` 或 `action_objects` 的外键，不把历史证据变成永久保活引用。

引用释放完成后，必须重新生成并审核对象 GC 计划；不能沿用释放前的候选集合或把“引用已释放”显示成“文件已删除”。现有 GC 仍保护固定、未到期及具有任何真实外键引用的对象，核对版本与物理指纹，先事务提交元数据删除和审计，再清理文件并记录残留。引用释放不修改对象到期时间，也不绕过 GC 的中断续跑规则。

```text
python -m omni.composition.cli --home <V2实例绝对路径> objects gc-plan <实例外的新GC计划文件>
python -m omni.composition.cli --home <V2实例绝对路径> objects gc-apply <刚审核的GC计划文件>
```

引用备份是在释放前创建的数据库一致快照与全部登记对象，正文此时已经裁剪。将该备份恢复至新目录，只恢复释放前引用和对象，不恢复更早的执行正文；需要原文时使用正文裁剪前的独立备份。两种备份均须完整核验，不包含凭据，也不能证明备份后外部动作的实际结果。

## 中断、取消与恢复

- **备份创建中断，或备份完成但批次尚未提交**：正文尚未改动；半成品和未绑定的孤儿备份都不覆盖、不自动复用。保留供核查，并用新的备份目录重试。不能仅用某个运行指纹复用旧备份，因为其间可能已有其他业务写入。
- **批次已提交，某运行尚未提交**：该运行正文、进度和裁剪审计共同回滚。使用原计划和原备份位置继续；每次继续都重新验证完整备份及待裁剪目标。
- **运行已提交、命令响应或批次完成标记前中断**：数据库标记识别已完成目标，不重复裁剪或写审计；继续处理剩余目标并结算批次。
- **计划失效、来源新增或需要保留剩余证据**：显式取消原计划。取消同事务释放待裁剪占用、保留理由和审计，不复原已提交正文、不删除备份；再次执行已取消计划会拒绝。需要裁剪剩余目标时重新生成计划。
- **需要恢复原文**：验证原备份，恢复至全新实例目录。恢复全程持有目标实例锁；活动目标、损坏报告、未核验 WAL/journal 均拒绝，不覆盖当前实例。

`doctor` 对 `prepared` 批次返回需要关注；已完成/已取消不计入待处理。诊断与工作台只展示批次数量，不包含备份路径、取消理由或执行正文。详细关联通过受保护的业务审计查询。

引用批次遵守相同中断原则：未提交目标完整回滚；已提交目标依据不可变历史跳过，即使对象随后已由 GC 删除，也可使用原计划和原绑定备份完成续跑。显式取消只取消尚未释放的目标，保留已释放进度和审计，不重建引用、不恢复文件或正文、不删除备份。取消不要求剩余目标仍符合释放条件，因此新增来源、固定或费用保护不会阻止所有者结束该批次；重新处理剩余引用须另生成计划。`doctor` 的 `reference_release_attention` 单独统计未完成引用批次。

180 天摘要/审计清理仍待实施，必须另行保护人工来源、文档作者引用与持久游标水位；本合同不授权按时间直接删除审计。

下一批的已核实依赖、禁止删除集合、游标合同和分批门槛见[180 天保留实施设计](V2_AUDIT_RETENTION_DESIGN.md)，其中所有新清理能力均为待实施。
