# Agent 空间、目录与文件管理

2026-10-30：全项目存储根、默认工作目录、长期记忆/档案和运维入口已扩展，最新总说明见 [STORAGE.md](STORAGE.md)。本文保留 Agent 文件中心初始设计；全局优先级与分类布局以新说明为准。

设计基线 `1865c22`。人设预设改变交互风格，Agent 空间负责持久数据与工作目录；二者分开管理。
现有默认空间继续使用旧路径，新增空间采用统一结构。全局模型/审批配置仍共用，不把目录隔离描述成操作系统沙箱。

```text
data/agents/<agent-id>/
  workspace/             命令默认工作目录与项目工作区
  files/                 生成和整理的文件
  documents/             用户提供的资料，模型只读
  memory/                memory.db、MEMORY.md、修订历史
  skills/                技能库
  artifacts/             截图、导出与受管理产物
  cache/                 可再生缓存
  private/               Cookie、浏览器登录态
  runtime/               state.db、插件与文件回滚
  logs/                  system、commands、mcp
  backups/               校验后的备份
```

空间目录表单允许自定义根及各业务目录；空字段按上面结构派生，相对业务目录固定相对于该空间根。
空间根的相对路径固定按应用 data 根解析，不随进程工作目录改变。
配置由单独 `agents.json` 管理，带版本、修订号、跨进程锁与原子替换；更新需匹配当前修订号。
默认目录注册表放在主配置同级；注入 data_dir 时使用该隔离目录内的控制文件，不读写真机注册表。

实现顺序：

1. 空间目录模型、冲突校验、注册表、有效目录预览。
2. bootstrap 选择空间，贯通记忆/状态/技能/文件/命令/终端/日志/备份；保留旧路径与显式注入。
3. 设置中的 Agent 与目录页面：创建、编辑、默认选择、配置/运行差异、目录树及资料与文件管理。
4. 假数据与 Chromium 回归、旧合同、备份、路径注入和架构验证，更新索引和交接。

目录变更只影响下次启动，不搬移、删除或合并旧数据。保存前明确确认新路径可能使用空记忆库；
需要旧数据时先备份并按恢复手册准备副本。运行页面同时显示实际空间、配置默认空间与待重启差异。
文件页只访问当前运行空间公开目录；不提供记忆库、凭据、缓存或其它 Agent 的原始文件入口。
普通浏览限制条目数，预览限制文本大小；上传单文件有大小与路径限制，拒绝覆盖已有文件。
不自动执行上传内容，不做后台递归扫描或自动向模型加载资料。

全局 PID 和服务启动日志保持共享控制位置，避免切换 Agent 后失去对原常驻服务的身份核验。
子服务启动绑定父运行态的配置源和 Agent，不跟随后来修改的默认选择串入其它空间。
切换默认空间后先重启 Web，再从新版运行态重启 QQ/心跳；各入口分别持有启动时确定的目录。
模型、审批等主配置仍共用，费用/写额度随各空间的 state.db 分别记账，不能把它当成跨空间总额度。
目录只能声明为本机路径，拒绝设备路径、UNC、ADS、保留名、链接、越界和相互覆盖；
新空间之间不共享持久目录，模型资料目录只读。人工批准的任意命令仍以 Windows 用户权限运行。

真实数据迁移、旧服务重启和真实模型验收单独登记；测试只用注入目录与临时文件。
