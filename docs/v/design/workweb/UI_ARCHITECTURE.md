# WorkWeb 技术架构

Phase V3-2 · A 方案已确认 · Windows

## 入口与目录

- WorkWeb/ui/ 是选定方案的独立原生 ES 模块应用。index.html 组织会话、主区和产物。tokens.css 提供统一的主题、排版和间距。workspace.css 实现布局和组件。
- 同一 UI 可以本地体验，也可以与一个明确指定的 V2 开发实例同源运行。当前 8773 静态服务默认进入 /ui/，本地演示的会话、产物和工作记录统一由 demo.js 提供。/comparison/ 保留三套早期选型原型，标明开放日资料整理是历史演示会话。连接真实实例需要从联调入口进入并在设置里完成所有者验证。
- 联调命令从任务工作树运行。指定开发实例路径，页面入口为 http://127.0.0.1:8774/workweb/。

~~~powershell
uv run --no-sync python WorkWeb/dev.py --home <独立开发实例目录>
~~~

- dev.py 在已有 composition.http.http_app 实例上额外挂载开发静态入口。现有 V2 API、所有者鉴权、模型执行和业务存储由原装配处理。
- 当前 V2 已提交资源作为回滚标签保存在 Git，另外从该标签导出了本机 temp/ui-v3/web-v2-legacy-d56edbd1.zip。现行 web/ 仍供 V1、V2、业务子站及发行包装配使用。旧版物理目录切换与发行候选会同步更新源码路径、资源路径和回滚校验。

## 会话与产物

api.js 统一访问 /api/v1。消息、会话、产物和运行都在请求边界转换为界面可用字段。连接凭据只保存在当前页面内存。

读取实例的主会话绑定和可见会话。已绑定时在该会话发指令，其余会话可回看。当实例处于普通会话模式时，从最近会话继续，或在首次发送时使用服务端返回的会话。消息请求沿用现有幂等键。发送结果不明时保留草稿，用户用同一内容确认时复用该键。

右栏读取当前会话消息中的已交付产物，通过同一会话的授权内容路由获取正文。默认预览最近交付，列表可切换。对话切换会清空上一会话的产物并关闭其请求，迟到响应只可写入原选择。输出使用文本节点。产物未生成时给出明确空状态。

主会话从现有运行接口返回的数据中呈现最近三条工作记录，详情在工作进展页。没有运行标题时，界面使用对应用户消息的首行作为摘要。切换会话后，上一会话的响应不会覆盖当前记录。会话和消息采用服务端提供的时间字段，演示时间来自本地样例。

主会话标题与执行记录读取现有 Ticket 投影、Worker 分工、会话待办和待审批数据。审批入口总数对应当前实例，主会话中的审批提示匹配当前会话已公开的运行。决定沿用审批工作页的现有入口，收到确认后回读审批。右侧产物沿用会话隔离。

Worker 详情使用两种现有投影。普通委派从父运行的委派清单定位子运行，校验归属后读取公开的子会话、执行事件和模型调用中的工具快照。OmniWeave 详情显示公开 Ticket 投影提供的任务状态、角色和版本。源内容已脱敏的委派只显示公开状态。

会话记录保存当前工作区各会话的阅读位置和跟随状态。新内容到达时，正在尾部的用户继续跟随，向上阅读的用户保留位置并可用「回到最新」。产物栏按会话记住选中的产物，同一会话、产物和版本共用正在进行的正文请求。切换实例清空页面里的阅读位置与产物选择。

theme.js 在首屏样式加载前应用 WorkWeb 的主题偏好，支持深色、跟随系统、浅色及预览 URL。顶栏中的工具进入现有工具与文件页，设置打开现有连接弹层，连接胶囊显示当前演示或实例连接状态。

左侧工作区进入进展、Worker 协作、任务、审批和工具与文件。work-pages.js 把任务、审批和能力呈现在主区。连接状态下读取现有 runs、delegations、OmniWeave 票据、会话待办、审批及能力端点，审批决定使用已有策略修订号。未连接时使用标明的本地样例。右栏始终按会话读取产物。

本批的连接、历史、发送、普通回复和工作区查询走真实 V2 HTTP。离线回归注入模型。真实多 Worker 交付与发布验收按各自阶段继续。
