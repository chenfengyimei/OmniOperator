# DESIGN.md —— OmniOperator 视觉方向与设计原则

> 本文件约束「往哪个方向改」。token 的具体值以 `web/ui/tokens.css` 为唯一源（见 `MASTER.md`），
> 工程硬约束以 `docs/v/reference/UI_DESIGN_SYSTEM.md` 为准；冲突时以后者与 `tokens.css` 为准。

## 1. 视觉定位

**暗色优先的玻璃工作台（dark-first glass workbench）**：极光感页面底 + 分层半透明表面 + 青紫渐变唯一强调色。
气质目标：专业的开发工具（类似 IDE/Agent 控制台），不是消费级 App，也不是后台管理系统模板。

关键词：`暗色优先` `分层玻璃` `青紫强调` `高密度` `小圆角` `克制动效` `状态驱动`。

## 2. 十条设计原则

1. **状态优先于装饰**：任何视觉处理不能削弱「运行中/待审批/已完成/未知/失败」的辨识度。
2. **一个强调色**：全站唯一青 `#3ddbd9` + 紫 `#7c8cf8` 渐变；不得出现第二种品牌强调色或自造渐变。
3. **层级靠表面与留白**：用 `--surface-0..3` + 玻璃三档 + 间距建立层级；不靠堆叠边框、阴影、渐变光斑。
4. **密度服务可读**：正文 13px、次级 12px、辅助 11px、注释下限 10.5px；**全站字号下限 10px**，信息密度靠层级不靠缩小。
5. **玻璃只用于壳层**：`backdrop-filter` 仅限 rail/顶栏/浮层/弹窗；卡片与列表靠半透明底 + 内高光 + 细边线表达。
6. **凹陷区实色**：代码、终端、输出、输入内衬用 `--surface-inset`，不用玻璃。
7. **深浅双态同源**：只换种子变量，不写两套样式；浅色下强调色压深保证对比，玻璃自动跟随。
8. **动效克制**：hover 120ms、面板切换 180ms、弹窗 240ms，统一 `--ease-out`；`prefers-reduced-motion` 全量关闭。
9. **可恢复性可见**：加载/空/错误/成功四态齐全；迟到响应不得覆盖新选择；未知状态必须显式标注「未知」。
10. **功能不降级**：任何视觉重构不得删除既有能力或改变操作语义（审批、停止、恢复、重试、队列、检查器）。

## 3. 色彩与表面

| 角色 | token | 用法 |
| --- | --- | --- |
| 页面底 | `--surface-0`（暗 `#070809`） | body + 极光渐变 + 网格纹理 |
| 面板/卡片 | `--surface-1/2/3` | 卡片、面板、浮起层依次提亮 |
| 凹陷 | `--surface-inset` | 代码块、终端、输入内衬 |
| 强调 | `--seed-accent` / `--seed-accent2` / `--grad` | 主按钮、选中态、进度、关键数字 |
| 语义 | `--ok` / `--warn` / `--danger` | 只用三支；「提示」用强调色 |
| 文本 | `--text-1..4` | 主/次/辅助/占位；`--text-4` 仅用于非正文 |

禁忌：第二个强调色；纯白薄纱 `rgba(255,255,255,x)`（浅色主题会隐形）；组件层写死色值；深色下大面积高饱和色块。

## 4. 字体与排版

- 正文/UI：系统 sans（Segoe UI Variable Text / PingFang SC / Microsoft YaHei）。
- 数字、ID、时间、指纹、代码：`--font-mono`（JetBrains Mono / Cascadia Code / Consolas）。
- 层级：页标题 18/700（子站）或 16（工作台 `--fs-title`）；区块标题 15/700；卡片标题 13/680；正文 13/1.7；辅助 11；注释 10.5。
- 中文优先；英文 eyebrow 用 10px/650/字距 0.12em；不使用 10px 以下字号。
- 不用远程字体（离线自洽），图标字体用随包的 Material Icons（`icons.css`）。

## 5. 动效

- 只做「状态变化提示」的动效：面板进出、toast、消息入场、加载脉冲、审批倒计时。
- 时长/缓动：120 / 180 / 240ms，统一 `--ease-out`；不写裸 `cubic-bezier`。
- 禁止：大面积视差、持续呼吸光效、滚动时的视差层、会遮挡内容的弹跳。
- `prefers-reduced-motion` 下全部关闭（`frame.css` 全局兜底，新增动效必须复用该兜底）。

## 6. 图标与品牌

- 图标：Material Icons 字体（离线 woff2），语义固定（rail 分组图标不要随意换）。
- 品牌：`web/ui/brand-mark.svg` 只在 rail 顶部出现一次；顶栏不重复品牌图标、不加副标题。
- 不使用 emoji 当功能图标；不使用第二套图标库。

## 7. 状态语言（文案即设计）

| 状态 | 表达要求 |
| --- | --- |
| 加载 | 有占位（`正在读取…` 或骨架），禁止白屏等待 |
| 空 | 说明「为什么空 + 怎么让它不空」，禁止只写「暂无数据」 |
| 错误 | 原位错误态 + 服务端 detail；422 只显示字段与错误，不回显敏感输入 |
| 成功 | 说清「保存了什么 + 何时生效」（如需重启才生效要写明） |
| 未知 | 明确 `未知`/`待核查`，并给出核对入口；不得推定成功 |
| 恢复 | 说明断线/重试/迟到响应的当前状态与下一步动作 |

## 8. 与三个设计技能的分工

- 视觉方向与设计系统生成 → `ui-ux-pro-max`（检索风格/配色/字体/UX 规则，产出候选而非最终裁决）。
- 交互架构与状态机 → `agent-product-ui-ux`（主会话/Worker、工具时间线、审批、恢复、滚动与焦点契约）。
- 评审与精修 → `impeccable`（critique/audit/polish/typeset/layout/colorize/animate/distill）。
- 真实观感验收 → `playwright`（截图与交互，不参与设计决策）。

冲突时按 `AGENTS.md` 的优先级：用户要求 > 产品架构约束 > Agent 交互规范 > 本仓库设计系统 > 通用视觉建议。
