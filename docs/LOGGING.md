# V2 日志、指标与诊断合同

本规范适用于 `domain / application / adapters / composition` 新内核；默认产品入口仍为 V1。完整业务保留清理与三平台实机验证尚未完成，不能据本规范宣称整个 V2 已交付。

## 记录归属

桌面发现只审计操作、数量、截断和匹配结论，不记录应用路径、原生句柄、会话身份、窗口标题或正文。`desktop.probe/targets/verify/observe/capture` 通过固定 desktop 类别关联 request_id、operation_id 和 trace_id；辅助进程 stderr 仅有界计数后丢弃。截图发布/释放引用记录尺寸、对象及会话身份，不写图片或UI文本；诊断包只导出待处理/缓存/回收及暂存残留汇总，不包含短时窗口快照或图片。详见[桌面合同](V2_DESKTOP.md)。

所有者终端的输入、输出和原生stderr不得进入诊断日志；操作审计只保存身份、意图指纹、字节数和状态。在线诊断只输出实例汇总，不输出终端目录、命令或屏幕。PTY接收输入的回执与命令执行结果分开；`unknown`不作成功统计，也不自动重放。原生回收、持久结算失败和输出缺口必须可见，不能仅因为辅助进程退出而声称清理完成。

所有者的未知动作核查依据属于可擦除业务正文，不能写入诊断日志；核查审计只记录核查ID、结论与固定指纹。来源删除清空依据正文，日志、诊断包和工作台旧响应均不能恢复它。`doctor`保留原始`unknown_actions`统计，并另列使用共同核查判定的`action_review_attention`，避免把人工核查误称为成功执行或费用核清。

消息原文、动作参数、工具结果和费用结算属于业务库；审批、权限变化、外部动作依据和维护记录属于持久审计。诊断日志只用于状态、关联、耗时、异常位置和降级。模型请求、聊天正文、工具完整载荷、凭据、Cookie 与浏览器状态不得写入诊断日志。

`composition/instance.py` 组装唯一日志写线程、指标注册表和诊断服务。业务模块获取 `omni.v2.*` logger，不初始化 handler，不重定向全局 stdout。CLI 的正常结果仍使用 stdout。

普通日志采用 JSONL，包含 UTC 时间、等级、event、component、build_id、boot_id 及可用的 request/trace/span/agent/session/run/operation 标识。上下文通过 contextvars 传播至受管执行器，任务结束后恢复；子进程接入仍须显式协议传播。异常只记录类型和帧位置，不记录异常值、源码行、局部变量。OpenTelemetry 自动异常事件关闭，外部导出默认关闭。

日志入队前递归脱敏并限制载荷，字典键同样脱敏。已知凭据注册表最多 256 条、合计 16 MiB；重复注册幂等，容量用完拒绝新增，不淘汰可能出现在迟到错误中的旧凭据。超大文本整段替换，避免截断后留下半个凭据。凭据写入必须先完成注册保护。

## 有界执行与故障行为

普通日志和临时调试共用 10,000 条队列与单一写线程。队列满、编码失败或写盘失败增加可查询丢失计数；限频 stderr 只输出固定错误码和计数。日志故障不冒充业务成功，也不无限阻塞用例。

普通文件最多 16 段、每段 16 MiB，保留 14 天。活动写入检查轮转；受管维护器每分钟检查过期段，因此空闲时也可清理。只处理固定 runtime.jsonl 段名，拒绝链接及异常文件，不清理其他用户文件。

应用诊断最多接受四个公共操作；文件执行器两个线程、五个配额，包含一个维护任务。请求断开或取消后，配额继续计入实际工作；关闭预算到期仍有工作时保留存储与实例锁，报告未完成，不能宣称清理成功。普通日志查询也使用这套生命周期。

## 指标与结果

指标使用十一个固定 operation：request、database_read、database_write、turn、model、summary、tool、delivery、object、maintenance、desktop。结果复用领域 Outcome：ok、error、denied、cancelled、unknown；最多 55 个直方图序列。指标和临时调试共用同一操作注册表。会话、运行、账号、目标、模型名称和用户文本不进入标签。

模型费用未知、写操作异常、迟到投递回执仍按未知记录；不能因为协程正常返回而计为成功。持久汇总读取同一业务状态谓词，费用预留与已知支出分别展示，未知费用不等于零。尚未接入的对象耗时序列、原生 RSS 与受管子进程采样不伪造为零，后两项明确返回 null。

## 临时调试

所有者通过当前 Agent 的日志面板显式开启。捕获绑定 Agent、完整操作 UUID 和本次 boot，最长 3,600 秒；重启不恢复。全体受管调试文件合计最多 128 MiB，入队预留与写前校验共同限制总量。自动到期、额度耗尽、主动停止、写盘故障和关闭均停止接受；旧队列按丢失计数处理，已开始写入的一条可以完成。

DEBUG 使用固定事件和组件，只保存合法关联标识、固定 operation/outcome 及有限耗时；不读取日志 message、异常值或任意 payload。启用调试不允许采集聊天内容。调试文件不进入普通 runtime.jsonl 或默认诊断包。

启用意图及成功、失败、停止写入当前 Agent 的持久审计。首笔审计失败不启用；成功审计失败立即停止。停止审计失败时保持关闭并重试审计。过期状态由单调时钟决定，维护器补写停止审计。停止请求绑定 capture UUID，旧页面不能停止新捕获。stderr-only 部署明确拒绝本地调试。

后台每分钟清理修改时间超过 24 小时的 `debug-UUID.jsonl`，活动文件保护；目录扫描最多 1,000 项，越界或链接异常明确报错。无关文件不因位于日志目录就被删除。

## HTTP 与工作台

所有入口要求所有者认证，沿用 `/api/v1` 的来源检查：

| 接口 | 行为 |
|---|---|
| `GET /system/metrics` | 固定维度指标、业务聚合与脱敏健康 |
| `GET /system/logs` | 时间、等级、组件、运行筛选；稳定游标 |
| `GET /system/diagnostics` | 有界 ZIP 附件，不是业务备份 |
| `GET /agents/{agent_id}/audit` | Agent 审计；cursor/limit 分页 |
| `GET /agents/{agent_id}/runs/{run_id}/events` | 指定运行的持久事件；cursor/limit 分页 |
| `GET /system/audit` | 实例维护审计；cursor/limit 分页 |
| `GET/POST /agents/{agent_id}/debug` | 查看或显式开启当前 Agent 调试 |
| `DELETE /agents/{agent_id}/debug/{operation_id}` | 停止指定捕获 |
| `GET /agents/{agent_id}/debug/{operation_id}/logs` | 当前 boot 最近捕获的有界游标读取 |

日志每页最多 500 条，扫描约 1 MiB；实时界面缓存最多 500 条，按页面生命周期释放请求和轮询。游标过期明确返回 410；切换捕获、空间或实例后拒绝陈旧响应。当前捕获之外的历史调试文件保留用于本地排查，不通过当前捕获接口跨 Agent 或跨启动读取。

### 持久业务历史分页（R3.retention_audit.cursors）

三类业务历史使用统一响应 `items/next_cursor/has_more/stream/history_trimmed`，每页默认 100 条、最多 200 条。`stream` 包含 `high_water/trim_revision/deleted_count/last_trim_at`。初次不传 cursor；后续原样传回 next_cursor，不解析或改写它。这里的序号与诊断文件游标相互独立；`after` 即使为 0 也返回 422，不静默按旧分页读取。

游标绑定历史 epoch、流、Agent 或实例、清理修订及运行筛选。流/作用域/筛选混用返回 422 `history_scope_mismatch`，非法或未来位置返回 422；清理修订或恢复 epoch 变化返回 410 `history_cursor_expired`。DELETE 触发器在原事务记录三类作用域变化，删除中间行同样使原游标失效，不能仅以最小剩余序号判断。事件作用域为整个 Agent，运行筛选不缩小该失效边界。普通重启保留 epoch，恢复与业务隔离同事务更换。

工作台 Agent 审计和实例审计均有加载更多及状态提示，最多显示最近读取的 200 条；410 时清空旧视图与游标，提示用户显式重新加载。新查询的 `history_trimmed` 仍说明历史曾被清理，不把空结果误称为完整历史。迟到响应不得覆盖新 Agent/实例视图，未知审计类型使用通用标签。持久事件 HTTP 已采用同一合同，当前工作台不消费该事件流，也没有 V2 持久 WS/SSE 通道。

## 诊断导出

默认包严格包含 summary.json、correlations.jsonl、README.txt。汇总包括版本、平台、数据库声明结构与计数、配置分类数量、资源及能力健康；日志只提取固定格式关联、事件与错误码，排除自由文本和磁盘路径。最多扫描 1 MiB / 10,000 行并保留 500 条，截断、损坏和不可读明确报告。

压缩包及解压总量均不超过 2 MiB，写出前检查精确成员集合、CRC 与加密标志。目标必须在实例目录之外；先将私有临时文件写完并 fsync，再同盘原子发布，不覆盖既有文件。POSIX 使用 no-replace 硬链接发布，Windows 使用不覆盖 rename；发布失败不留下貌似完整的目标文件。进程被强制终止时可能留下私有 `.partial`，不会当作正式导出。

在线导出使用运行中的本地所有者服务，拒绝重定向与 HTTP 内容编码，限制原始流读取。离线导出取得实例独占锁，只读数据库；结构不匹配则拒绝，不自动迁移，不启动业务或调用模型/设备。

```powershell
uv run --no-sync python -m omni.composition.cli --home <独立V2目录> diagnostics <实例目录之外的新ZIP路径>
uv run --no-sync python -m omni.composition.cli --home <独立V2目录> diagnostics <实例目录之外的新ZIP路径> --offline
```

诊断包不包含聊天、数据库文件、凭据或浏览器登录态；不能用于业务恢复。密钥与凭据备份必须单独显式处理。

## 业务保留与待实施范围

30 天执行正文与180天 Agent 审计/事件明细分别采用独立的 plan/apply/cancel、验证备份与断点续跑合同。正文清理裁剪旧终态运行的动作参数/结果与事件载荷；审计和事件只按精确白名单、来源及业务保护清理。事件删除保留运行身份、原运行内序号和last_seq，不重建费用或去重状态。聊天不按此策略删除。

必须保护活跃/未终态运行、unknown 副作用、reserved/unknown 模型费用、待执行工作、未完成及 unknown 投递、持有的资源、来源锚点、文档上下文引用及人工固定。对象与运行已有固定入口；正文裁剪与持久标记已接线，备份核验失败或审计写入失败不能宣称裁剪成功。v2_0014 已建立游标分配及清理水位基础；180 天预览另外核验审计作者外键、完整正文批次及正在进行的引用释放。人工允许后续调度的 unknown 投递仍受保护。工作台“诊断日志”提供只读入口；固定时间与记录上界的分页不授权删行。完整合同见[审计保留设计](V2_AUDIT_RETENTION_DESIGN.md)。

R3.retention_references 为已裁剪动作增加独立的引用 plan/apply/cancel。准备、精确关系释放与取消写入 reference_release.* 业务审计；每条引用的删除、进度与释放审计共同提交，失败共同回滚。计划保存对象版本、SHA-256、大小及原正文批次，来源/费用/资源等保护须再次查询，不能只信正文指纹。历史目标不建立对象外键；已释放目标在对象被后续 GC 删除后仍可凭历史续跑，不能重复写释放审计。

工作台与默认诊断只展示引用批次状态计数，doctor 对 prepared 批次报告需要关注；不导出备份路径、取消理由、执行正文或完整计划。取消只撤销未提交目标，不把已释放关系、文件或正文记作恢复。释放不写“对象已删除”结果；文件回收必须另审现有 GC 新计划，物理失败继续报告残留。释放前备份可恢复引用及对象，裁剪前备份才可恢复原正文。完整合同见[执行正文保留合同](V2_EXECUTION_RETENTION.md)。

现有用户“遗忘”会使摘要与派生记忆失效，不可用于时间保留清理。诊断日志轮转、调试清理和对象 GC 通过，也不代表完整业务保留已完成。当前证据与未完成项见 [运行诊断记录](evidence/v2-operations.json) 与 [V2 台账](tasks/v2.json)。

审计删除的准备、逐目标删除、完成、取消及恢复撤销记录为 audit_retention.*，默认不属于可清理种类。每次删行与目标状态、触发器水位及维护审计同事务，日志故障不能代替审计持久证据。运维计数 audit_retention 只包含状态数量，doctor 的 audit_retention_attention 统计 prepared 批次；全部目标已提交但未完成收尾也报告。恢复转入新 epoch 并取消 pending，不自动续删。详见[审计保留合同](V2_AUDIT_RETENTION_DESIGN.md)。

事件维护记录为 event_retention.*，同样写入audit并默认保留；事件删除只推进events清理修订，不推进audit删除修订。事件裁剪后追加的未裁剪行、恢复interrupted与未知种类、unknown动作结果和未结费用保护。事件/审计共用执行核心，来源及维护保护共用查询；运维 event_retention/doctor event_retention_attention 只报批次状态计数，工作台不显示事件原载荷。恢复同时撤销旧事件计划，正常重启允许原备份续跑。

## R4 I/O安全补充与开放项

显式凭据引用和工作台修改共用一个有界执行器；原生调用按FIFO执行，取消不释放实际配额。模型在准备完成后重新核验权限再发送；已证实未发送费用才释放预留。原生系统后端直接选择WinVault、Keychain或Secret Service，不选择配置的明文链式后端。加密库使用持久替换，并先持久移除查询名再清理删除残留。

实例级修改意图/结果进入全局所有者审计，普通日志以request_id/operation_id关联。工作台审计最多显示200条，默认诊断只导出未知数量，排除审计正文与凭据。当前审计已记录未知，后续还需凭据注册/业务操作/核查授权状态和恢复代次；供应商多凭据、SDK环境发现及完整客户端生命周期仍按R6逐类接入和验收。不能把本批50项新增回归视为这些开放项已经完成。

## 凭据授权记录补充（v2_0010）

凭据引用、操作、核查是业务真值，instance_audit 是同事务的解释记录。未结束意图需查询业务状态，活跃操作与未知结果分别显示；核查只解除或撤销未来权限，不改历史观察。普通日志只通过 operation_id/request_id 关联，不写密钥、引用名和人工证据。默认诊断包不包含凭据核查正文。核查与恢复业务合同见[V2 凭据记录](V2_CREDENTIAL_AUTHORITY.md)，平台系统存储仍需实机验证。

## 运行保留预览（R3.retention_preview）

工作台可固定/取消固定本次运行；retention_revision 独立 CAS，编辑及审计同事务。CLI 的 retention-preview 要求独占实例，只读检查当前结构，不自动启动或升级。每页最多50个旧终态运行，输出指纹、大小与保护原因，不含执行正文。预览明确 can_apply=false，不能直接用于删除；R3.retention_apply 增加备份后复核、断点执行、正文裁剪标记与显式取消；R3.retention_references 独立释放已裁剪动作的精确对象引用，180天摘要/审计仍待推进。详见[执行正文保留合同](V2_EXECUTION_RETENTION.md)。用户遗忘不参与此流程。

## 在线维护的记录与归属（R4.maintenance）

维护请求、尝试与业务结果属于持久业务记录；`maintenance.*` 审计与相应入队、领取、取消或结算同事务。索引发布及擦除传播必须与任务成功共同提交，审计失败共同回滚；普通重启中断与备份恢复取消分别记录，不能用一条“已恢复”日志代替真实状态。任务状态、attempt_no、业务build/原擦除请求关系是排查真值。

诊断日志以维护job UUID作为 `operation_id`，结合 `agent_id`、固定事件/错误码、耗时与结果关联；不输出文档正文、标题、请求体、幂等key、token或凭据。token和请求key仅在受保护的业务存储中用于所有权与去重，公开状态及诊断导出不包含它们。指标使用维护类型、结果等固定维度，任务ID不作为指标标签。

取消请求不代表实际工作已停止；结算失败保留实际Task、容量及关闭残留，报告固定错误状态并由原所有者继续处理，不能静默丢弃或重放。监控区分待排队、活跃、取消中与待结算；phase 0排空失败时保留文档、数据库和实例锁。在线维护仅含全文重建与已有擦除确认续跑，TTL/GC及备份恢复继续记录于独占离线维护合同，不作为自动在线任务。

## 本地事实整理的审计与诊断（R4.maintenance.memory）

`memory.organization.*`记录入队、提案发布、应用、拒绝、撤销、取消、失效或失败，与对应批次/候选状态在同一短事务提交。业务真值是v2_0018的批次、固定来源与候选关系；普通诊断日志不代替所有者核查证据。应用不表示事实已删除，取消不表示已撤销先前应用，恢复隔离不表示重新授权。

后台处理使用固定`memory.organization` span，以Agent与批次UUID作为关联；所有者决定以候选UUID作为operation_id。事件、结果与错误码使用固定值，指标仅使用有限组件/结果维度，不以批次、人物、记忆或会话身份作标签。不输出事实正文、quote、请求体、幂等key、所有权token或凭据；审计仅包含策略、计数、指纹和决定等必要元数据。

维护状态分别计数queued、ready待核查及失败/失效，零模型调用与零模型预算是当前本地算法合同。调用方取消后，服务仍跟踪实际Task；phase 0未排空必须显示残留并保留数据库、实例锁，不能用取消等待日志宣称事务已停止。确定性输入错误结算failed；基础设施异常保留queued并报告worker不健康。恢复隔离与普通启动续处理分别记录，不将离线TTL/GC或验证备份伪装为本批在线整理操作。

## 可信插件的审计与运行诊断（R4.extensions）

`extension.*`审计登记安装、明确授权、禁用、漂移与恢复撤权；动作继续使用原action/approval业务链及其同事务审计。版本、授权代次、grant和run binding解释实际执行身份，诊断日志不能代替它们。grants.review_audit_id纳入统一真实外键保护，不能因审计达到保留时间丢失所有者信任依据。

诊断按agent_id、run_id与动作operation_id关联，使用固定事件、结果、错误码和耗时；不输出插件源码、请求/结果正文、参数、幂等key、源目录、凭据或完整stderr。指标只使用有限组件与结果标签，工具及插件UUID不作为高基数标签。宿主健康明确展示常驻/在途数量、poisoned清理残留及关闭状态；进程上限4、在途上限64是本批宿主合同，不混同文档维护队列。

静态捕获和握手成功只说明目录、包与catalog身份匹配，不表示插件代码已经执行或已产生效果。入口加载只发生在已登记和审批的实际派发之后；写入已派发后连接丢失、取消或无法确认结果时保留unknown，不能记录成普通可重试失败。实际spawn、调用或进程回收未结束时保留Task与句柄；phase 0关闭残留必须可查询，并阻止数据库与实例锁提前释放。恢复撤权与正常启动分别记录，不把旧授权恢复、备份完成或元数据安装写成“插件已安全运行”。

## 原生凭据进程诊断

系统钥匙串只在固定helper中调用，原生stdout丢弃、stderr有界排空丢弃，协议中的密钥不进入诊断或argv。主进程沿既有request/operation上下文记录`credential.native.unconfirmed`及固定error_code，健康仅显示在途、常驻、回收残留和失败计数。未知写入仍查询原凭据操作/审计，不靠日志重写结论；回收未完成禁止核查解除权限。原生样例证据不包含值，只保留回读/清理/进程回收的明确状态，写入未知时确认字段为null。

## 终端核查记录

terminal.review.recorded/evidence_erased审计和对应元数据/说明操作同事务。诊断使用terminal.review.recorded、terminal.review.replayed及terminal.review.evidence_erased，按请求、Agent和review UUID关联，不写人工说明、终端输入/输出或proof正文。健康只计pending/closing；核查不会修改原unknown观察，不能从一条日志推断命令成功、历史进程消失或允许重发。
