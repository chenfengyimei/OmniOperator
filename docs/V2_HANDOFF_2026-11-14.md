## 4. 必须保持的架构与类型合同

- **四层单向**：入口适配器 → 应用服务 → 领域与端口；基础设施实现端口；composition 统一构造与关闭。
  领域无 I/O；仓储不建表不自连。由 `agent/tests/test_arch.py` 的 AST 守卫强制。
- V2 是**单实例、单所有者、多 Agent、单一 `omni.db`**；不迁 V1 数据、不双写、不加兼容层。
- 关键类型：`Record = dict[str, JSON]`（`application/ports.py`）；
  `JSON = None|bool|int|float|str|list[JSON]|dict[str,JSON]`（`domain/contracts.py`）；`Payload = dict[str, object]`（更宽）。
- **unknown ≠ 失败**，不自动重放写操作；审批 fail-closed；数据库只用含 WAL 的一致快照接口。
- **禁止 `# type: ignore` / `# pyright: ignore`**。唯一既有例外：`event_loop.py` 的 proactor import（已记入 `TYPE_CHECKING.md` §4）。

## 7. 类型化实战要点（P3 全程沉淀，直接复用）

| 坑 | 正确做法 |
| --- | --- |
| **协议参数逆变** | 实现必须与端口**完全同宽**：既不能更窄（`Record` vs `Payload`），也不能更宽（`dict[str,object]` 替 `Record` 同样破门禁）。dict 本身**不变**。动手前先读端口签名。已知宽口径：bilibili `forms=dict[str,object]` / `mentions=list[dict[str,object]]`；maintenance `claim=Claim\|Record`；schedule `save value=dict[str,object]`、materialize/enqueue `Mapping[str,object]`；mcp `tools=Sequence[Record]`；image `model_image_policy_add value=Record` |
| **`Select` 泛型变长** | 定长列元组不能标注成变长元组 → 在 return 处 `cast(Select[tuple[object,...]], stmt)` |
| **`.alias()`** | 返回 `NamedFromClause`（泛型有 bound，**不要填 `[object]`**），不是 `Alias` |
| **计算列** | `func.length` / `literal_column` 需 `cast(Column[int], ...)` 才能进 where/order_by |
| **`cast` 命名冲突** | 模块已 `from sqlalchemy import cast` 时，typing 用别名（先例：`action_review_repository` 用 `tcast`） |
| **HTTP 边界防御** | 静态已窄时 isinstance 报冗余，用 `isinstance(cast(object, x), str)` **保留运行时防御**，不要删检查 |
| **领域函数更宽** | 如 `validate_retention_plan(plan: dict[str,object])`，`Record` 不自动兼容 → 调用处 cast；`domain/context` 的 batch/tail/turns 返回 `list[Mapping]` 比 Record 宽 → 逐行收窄 |
| **拆分 isinstance 复合条件** | 必须沿用**原错误码与原消息** |
| **冻结迁移 / 纯 SQL** | 加注解后 AST 遍历顺序会变 → 字面量按**多重集**比对（按序列比会虚警）+ 常量 `ast.literal_eval` 相等；纯 SQL 模块另用 sqlite 方言编译逐字节比对 SHA256 |
| **未纳入的父类/混入** | 用局部 `x: Any = self` 视图桥接，爆炸半径限本文件；**父类纳入后回头清理桥接**（第 184 批已清理语义仓储三处，类型链贯通） |
| **跨模块漂移** | 只改其他模块的**签名**，绝不改其函数体——改体会把它的潜在错误拖进本批范围。误改用 `git checkout HEAD -- <file>` 还原 |
| **聚合根** | `repository.py`（24 混入）可在不纳入未类型化混入的前提下完成，靠局部 Any 视图 |
| **删除/变更顺序** | GC/裁剪类模块用定向 grep + 专门故障测试证明**破坏性顺序逐字未变**，不靠推理 |
| **批量改文档** | 用一个 Python 脚本做多处 `str.replace` + `json.load` 校验，胜过多次 Edit；脚本改写过文件后若要 Edit 必须重新 Read |
| **锚点唯一性** | 脚本替换前 `assert t.count(a)==1`，命中重复就扩大上下文 |

## 8. 验收口径（重要，禁止四种写法）

`-n 2` 下 Playwright 重度用例会因资源争用偶发失败。**必须**：

1. 先并行跑全量，报告留档；
2. 从 XML 提取失败 nodeid 写 argfile，`pytest -q -n 0 @argfile` **串行复跑**，报告留档；
3. 仍失败的 UI 项再做**隔离复跑**；
4. 需要定归属时做**干净 HEAD 对照**：
   `git worktree add temp/build/wtNNN HEAD --detach` + `PYTHONPATH` 指向副本 + 主解释器，
   每个症状家族取 1 个代表用例；用完 `git worktree remove --force`。
   **单次对照不能作为结论**（第 25 节点首跑通过曾误判，第二次失败即推翻，最终三次才定性）。

**禁止**：① 把"串行/隔离通过"写成"并行全绿"；② 把抖动写成功能缺陷；
③ 把他方未提交工作区导致的**确定性**守卫失败写成抖动；④ 把其他会话引入的违规写成本批回归。

**他方改动可能在验收期间变化**（第 35 节点 UI 会话中途修掉 CSS 违规，导致 3 项串行转绿——那不是抖动）。
按并行时点快照记录，并注明串行/对照的时点差异。

**收割脚本已就绪并校验**：`temp/build/_harvest_full.py <report.xml> <argfile.txt>`
