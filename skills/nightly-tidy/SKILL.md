# 夜间整理（批量 review）

## When to Use

心跳/定时任务在夜间触发时（建议用 cron 建一个 daily_at 任务，prompt 写
"按 nightly-tidy 技能做夜间整理"）；或用户明确要求"整理一下今天的记忆"。

## Procedure

1. `daily_digest`（hours=24）建立全局：哪些会话活跃、新增了哪些长期记忆、
   最近 review 都做了什么、档案占了多少额度——先看清今天发生了什么再动手；
2. 档案整理：`profile_manage(operation=view)` 对照 digest 与今天的话题，
   把重复、过时、可合并的行 edit 合并或 delete 删除。档案只放核心稳定特征
   （身份、长期偏好、重要约定），宁少勿多；
3. 记忆沉淀：digest 列出的新记忆里，把表述含糊的（"他说好"、"那个东西"）
   用 search_history 找到上下文，重新 remember 一条自包含的修正版。
   注意长期记忆没有删除工具，修正是新增更准确的表述，不是覆盖；
4. 技能沉淀：如果今天踩坑后找到了可复现的多步路径，用 skill_create 蒸馏；
   单次性操作不建技能，宁缺毋滥；
5. 汇报：三五行以内——整理/合并了什么、有什么值得明天跟进。这份汇报会
   存进任务会话，若任务配了 deliver_to_qq 还会推送给用户。

## Pitfalls

- 这是无人值守场景：CONFIRM 级工具（发QQ、浏览器写、安卓动作）会被
  DenyApprover 拒绝，不要尝试走写路径；
- 不要为了"看起来做了事"而改写正确的记忆——整理的目标是准确，不是数量；
- digest 显示零活动时直接汇报"今天无事可整理"，不要虚构内容；
- 档案未到额度且没有冗余行时跳过合并步骤，"无需变更"也是合格的整理结果。

## Verification

- 汇报里的数字能对上 digest（处理了几条记忆、档案动了几行）；
- 修正后的记忆是自包含的（半年后单看这一句也能懂）；
- 全程只用了 SAFE 级工具。
